# T-03: Forged, stolen or duplicated documents at Tier 2

- Area: Eligibility and Sybil resistance (G-1, G-2)
- Adversary: A-1, A-9
- Status: **Partial by design.** Possession of a document isn't personhood: a person with two valid documents, or a stolen document with its access data, gets two identities. A state that issues documents (A-1) can mint identities for its own citizens. Stated in the P3-1 ADR.

## Threat

One person registers with several documents (a passport and an mDL, or two passports), or with someone else's document.

## Mitigation

Tier 2 proves validity of an issuer-signed document and derives a per-document uniqueness nullifier (P3-1 ADR, P3-4).

## History

- 2026-10-11 (P1-17): membership is proven against a complete depth-32 tier tree, so one registration (one document's uniqueness nullifier) carries at most one voting identity; over Semaphore's LeanIMT it could have carried a private tree of them ([[membership]], Tier tree).
- 2026-10-11 (P3-1): [[0010-tier2-identity-provider]] chooses zkPassport's scoped per-document nullifier. zkPassport checks passive authentication only, so cloned chip data proves; its documentation states "one ID, one account", not one person. The verifier ties the proof's date to the addition's L2 time and requires an unexpired document, so a backdated proof can't register an expired document; a renewed or replaced document whose old chip still reads still gives a second identity. The nullifier type is fixed per deployment and a removal never frees a nullifier. So anyone holding a document's chip data (including the issuing state and a malicious proof-app build) can pre-register it and permanently burn its holder's nullifier; the holder's only recourse is a new document until P3-2 and P3-4 design a dispute path.
- 2026-10-12 (P1-17b): the tier tree is implemented and checked against an independent implementation, including forbidden commitments (leaf 0) and stray removals.
- 2026-10-12 (P3-4 part 1, [[0022-tier2-keyed-nullifier]]): the Tier 2 nullifier becomes `H2(x, sk · H1(x))` under the panel's threshold OPRF key, with `x` zkPassport's per-document private nullifier, so one document still yields one nullifier; each attester recombines the evaluation from the seats' proven answers and checks the output proof against it, and an addition counts only with `max(k, n − 1)` attesters signing its group position after every earlier nullifier reached them, so a duplicate needs 5 corrupt seats of 7. Open for part 2: if an accepted document signer uses ECDSA and zkPassport's circuit doesn't fix the SOD signature's encoding and low `s`, a holder gets a second per-document input and so a second nullifier. Losing the key ends the scope and means re-registration.
- 2026-10-12 (P3-4 part 2a, [[0022-tier2-keyed-nullifier]], Amendment): the document signature's encoding is canonical. zkPassport takes ECDSA signatures as fixed-width `r ‖ s` with low `s` and range-checked `r` and `s`, and RSA signatures below the modulus, so a holder can't re-encode one signature into a second per-document input `x`. Our query circuit must also reject `x = 0`, which zkPassport's hash-only commitment form admits. Uniqueness still rests on the soundness of zkPassport's identity sub-circuits, on which a question is held for the owner (details withheld until the owner decides on disclosure). Until it is settled, real documents don't register through them.
- 2026-10-12 (P3-4 part 2b-2a, [[nullifier-key]]): an honest seat approves at most one Tier 2 key per scope, and a key counts only with `max(k, n − 1)` seats' approvals, so a second key for one scope, and with it a second nullifier for every document, needs a seat that broke that rule.
- 2026-10-13 (P3-4 part 2b-2b, [[nullifier-reshare]]): a reshare keeps the Tier 2 key's `sk`, since each dealer's constant commitment must be its share commitment `C_i` (`constant`), so every nullifier stays the same across a panel change; a new seat approves at most one successor of any key, and a successor counts only with `max(k', n' − 1)` new seats' approvals, so a key has at most one counted successor and a scope's keys form one chain.
- 2026-10-13 (P3-4 part 2b-2b review, [[nullifier-reshare]]): an old seat deals to at most one successor panel per predecessor while a run to it is live, and a successor counts only with `max(k, n − 1)` dealers, a rule of counting itself, not only of honest approvers (a panel of an insider's own keys has none), so two successor panels need an old seat that dealt to both; for 4-of-7 the two dealer quorums share 5 seats, at least one honest. Smaller panels rely on the release pinning one successor.
- 2026-10-13 (P3-4 part 2b-3a, [[keyed-nullifier-hashes]]): `H1` and `H2` are deterministic in the scope and `x`, so one document has one `N` provided the circuits enforce four things the page states: the map's root sign rule (canonical `sgn0`, whose soundness in Noir 1.0.0-beta.22 was checked), one blinding scalar `r` with `0 < r < l` binding both `B = r · H1(σ, x)` and `Z = r · U` in the output circuit (otherwise any `U` and so any `N` fits `Z`), the unblinded `U` in Baby Jubjub's prime-order subgroup (TACEO's audit finding A; otherwise an even `r` admits `U + T` and a second `N`), and `x ≠ 0` in the query circuit.
- 2026-10-17 (P3-4 part 2b-3b-1): `h2` in `packages/circuits/lib/keyed_nullifier` asserts `U` on the curve and then in the prime-order subgroup before hashing, so no circuit can compute `N` from `U + T`; Noir tests refuse a point off the curve, the point of order 2 and a vector's `U` plus it (checked by mutation: without the subgroup assertion they fail). The other three conditions (the sign rule through TACEO's map, which every vector now pins before cofactor clearing; one `r` binding `B` and `Z`; `x ≠ 0`) belong to the query and output circuits of part 2b-3b-2.
- 2026-10-17 (P3-4 part 2b-3b-2a, [[nullifier-query]]): the query circuit opens `comm_in`'s private-nullifier slot only in zkPassport's clear-value form with `x ≠ 0` and a non-zero salt, so the hash-only form can't give a document a second `x`; it requires `0 < r < l`. The output circuit binds one `r` to both `B = r · H1(σ, x)` and `Z = r · U`, requires `U` in `𝔾` and not the identity, and restates `x ≠ 0`, so one document has one `N` per scope. An output counts only with exactly the key's `k` answers in ascending seat order, never a count the client chooses. Residual: that `comm_in` holds this document's one private nullifier rests on the identity chain's checks (part 2b-4) and on the question the ADR's Amendment leaves open, and the statements aren't yet circuits (part 2b-3b-2b).
- 2026-10-17 (P3-4 part 2b-3b-2b-1): the query and output circuits exist in `packages/circuits`, each constraint with a Noir test where only it breaks: the clear-value slot with `x ≠ 0` and `s_x ≠ 0`, `0 < r < l` (`r + l` opens the same `B` and `Z` and is refused), one decomposition of `r` multiplying both `H1(σ, x)` and `U`, `U` on the curve, in `𝔾` (`U` plus the point of order 2 fits the honest `Z` for an even `r` and is refused) and not the identity. Residual: no verification key or proof yet (part 2b-3b-2b-2), and the identity chain's checks (part 2b-4).
- 2026-10-18 (P3-4 part 2b-4a, [[nullifier-key]], Approval): an honest seat now approves at most one _live_ initial key per scope, not one ever: once a key's deadline passes without it counting, its seats may approve another run's, so a stalled run no longer blocks the scope's key for good (T-54). The guarantee against a second counted initial key, and so a second nullifier per document, now rests on each seat reading from its own L2 node, once the deadline's block is final on L1, whether a key counted, and on the registry accepting at most one counted initial key per scope (part 2b-4), which is load-bearing and must exist before any registry is deployed.
- 2026-10-18 (P3-4 part 2b-4b-1, [[contracts]], Group registry, Nullifier keys): the group registry records the Tier 2 scope's keys and decides on chain whether one counts: at most one initial key per scope, ever, and a successor only of the current key, with `max(k, n − 1)` old seats' consent and `max(k', n' − 1)` new seats' approval, so a second counted key, and with it a second nullifier for every document, no longer rests on each seat's view of the chain. The approval statements now carry the run's deadline, which the registry enforces, since it can't read it from `key_id`. Residual: a corrupt quorum can record a key whose transcript fails, which a verifier refuses; that stops the chain (a new scope) but adds no second key. The contract is part 2b-4b-3's.

- 2026-10-18 (P3-4 part 2b-4b-2, `packages/crypto`): the group registry's records of the scope's keys and its checks are code, replayed by `replayNullifierKeyRecords` against `nullifier-key-registry.json` from an independent implementation, so a verifier finds the one chain of keys the registry recorded and stops at the first record a rewritten history put there. Seats now sign only the statements with the run's deadline (`-approval-3`, `-reshare-approval-2`) and the old panel's consent, each only with `RECORD_MARGIN` left; nothing signs the retired statements any more. The transcript checks and the release's successor pins join the replay with the verifier's Tier 2 counting.
- 2026-10-18 (P3-4 part 2b-4b-3, `packages/contracts`): the group registry records the scope's keys on chain: `recordNullifierKey` takes the initial key once ever, and `recordNullifierReshare` a successor only of the current key with a `key_id` never recorded, each with `max(k, n − 1)` distinct seats' P-256 signatures on statements it builds itself; over every replay of `nullifier-key-registry.json` it records exactly the chain `replayNullifierKeyRecords` finds, so no record makes a second key, or a second nullifier for any document, count on an honest L2.
- 2026-10-18 (P3-4 part 2b-4d-1, [[identity-chain]]; [[0010-tier2-identity-provider]], Amendment (part 2b-4d)): before answering a query a seat checks five zkPassport sub-proofs ending in its `comm_in`, under keys pinned per role, from an anchor set of the deployment's issuer valid on a proof date within a day of the seat's clock, so the `x` the query blinds is the private nullifier of a document that issuer signed, unexpired, with a holder aged 18 or more of its nationality. Not mitigated: no sub-circuit checks the document signer's validity or revocation, so a revoked signer's documents still prove; real documents wait for a signer proof of our own (option B of the amendment) as well as our app. US non-citizen nationals pass the nationality predicate.
