## Scope

The fix the owner chose on 2026-10-12 for the residual accepted on P1-12 part 3b (#101; [[0002-everlasting-privacy]], Decision): a trustee node's obligation to send receipts through the contract path ([[delivery]], Direct submit) has no bound, since intake checks no membership, so a flood of ineligible ballots plus an operator that withholds board data until the node's cutoff can force more contract-path receipts than any budget allows and silently drop receipted ballots whose clients have gone away (T-25, T-52, T-54).

- [[share-encryption]] (Intake and receipts) and [[delivery]]: at cast, the client gives each trustee the full ballot record, its membership proof included, with the ciphertext; spoiled ballots never reach intake, so the Benaloh challenge is unchanged.
- A trustee receipts only a ballot whose membership proof verifies against the registered tier root.
- A trustee node owes contract-path receipts only for the ballot [[revoting]] would count for each tier and nullifier, so its obligation is bounded by the electorate; state that bound and the capacity the windows support, and check it as `deliveryWindowFits` checks the windows.
- P1-18: the contract takes share receipts in batches (many signatures, one call, one forced deposit).
- Remove the residual from [[delivery]], T-25 and T-52 once closed.

MUST be done before any election registry is deployed. Board data availability (a content address per anchored segment and a publication deadline) complements it and stays with P4-3.
