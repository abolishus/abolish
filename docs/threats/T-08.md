# T-08: Electorate definition manipulation

- Area: Eligibility and Sybil resistance (G-1, G-2)
- Adversary: A-2
- Status: **Planned.** Who may define an organisation's electorate is the organisation's problem, not ours; we make the definition public and fixed.

## Threat

A closed electorate (organisational vote) is defined with extra or missing members.

## Mitigation

The electorate (group root at a fixed block) is bound into the election definition, whose hash is on L2 before voting opens (P1-18). Each tier's root is at an L2 block strictly before the one that registers the definition, so the additions behind it are public before anyone votes ([[election-definition]], The electorate is in the past).

## History

- 2026-10-11 (P1-10b): each tier's `root_l2_block` must be strictly before the block that registers the definition, so the additions behind a root are public before voting; a definition naming a later block fails [[verifier]] 2.4 and P1-18's registry rejects it ([[election-definition]], The electorate is in the past). Without it, an insider operating a group's signer could commit to a root whose additions it posts only after close, shutting honest voters out invisibly.
- 2026-10-11 (P1-18, part 2): the election registry refuses a definition with any tier root at or after the registering L2 block ([[contracts]], Election registry), as [[election-definition]] requires; verifier 2.4 still checks it.
- 2026-10-27 ([[P2-17]] part 4d-2a, [[verifier]], Ballot admission, step 2): the verifier's ballot admission judges a rolling poll's version-5 ballots against the root of the step each names, of its cell's tier, which `packages/crypto` computes from the group registry's events and the definition's registration time it is given, never a root the ballot, an event or the bundle states; without those events no ballot is judged. The verifier doesn't yet read them from the run, so a rolling poll still stops at 2.3 (part 4d-2b).
- 2026-10-30 ([[P2-17]] part 4d-2b-1, [[verifier]], Electorate, The rolling chain): those events and that time come only from the registries' records the verifier's own checks pass: the events from 2.4's rolling replay, given only where the recount passes (a stray or out-of-order addition to a listed group gives no chain at all), and the time from the one `DefinitionRegistered` that registered the definition. The operator's one-ballot admission takes that chain from its own finalized read of the registries; the run still stops a rolling poll at 2.3 until it builds the chain from the archive.
- 2026-10-30 ([[P2-17]] part 4d-2b-2a, [[verifier]], Electorate, The rolling chain, From the archive): the run builds that chain from the archive's replay of the group and election registries under the registries the release pins (none yet, so every run still stops a rolling poll at 2.3), only where each registry's replay reproduces an evidence record past both the close and every `root_l2_block`, so no step root is taken from events that may stop short. Since the archive's output roots aren't checked on L1 yet (T-71), a ballot a step root or the registration time rejects leaves 5.1 to 5.3 unverifiable, never failed, and is never counted.
