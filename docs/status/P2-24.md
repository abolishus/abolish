## Scope

Every way a poll travels, as [[sharing]] designs them: the share sheet, link previews (done in [[P2-18]]), QR codes, the printable flyer, the embed, native share on phones, a result card once results exist, and the voter's own "I answered" card. From `share-*.tsx` in `apps/web/src/mockups/`.

- The voter's own card is made on their device and shared only by them; the server never learns that it was made or what it says.
- Every surface carries the poll's short code and seal, and nothing that identifies a voter.

Rules for every part, as [[P2-19]]'s: everyday register by default ([[language]]); no hard-coded strings (`messages.ts`); CSP-safe (no inline `style`); server-rendered where the page is the website's; a fixed analytics template per route, never a path or poll ID (T-67); each component a story with a play function passing axe at desktop width and 360px; SSR and serve tests per route; the mockup's story deleted in the PR whose page matches it. Privacy holds everywhere: nothing an account does on the website (following, reacting, sharing, notifications) is ever stored, logged or keyed with a ballot, nullifier, receipt or the fact of having answered, and the T-10 no-join tests cover every new table, queue and log line ([[PROJECT_BRIEF]], Identity).

## Part 1a: the share sheet on the poll page

"Share this poll" in the poll page's Answering section opens a dialog ([[sharing]], Share sheet): the poll's short link (`<origin>/p/<code>`, the same for everyone) with **Copy link** and a status line, **Share…** where the browser has the Web Share API (given `{ title, url }` and nothing else), and otherwise one line saying so with **Email the link** (`mailto:` with the title as subject). The dialog's description says sharing sends the link, never the sharer's answer. The copy and the share happen in the browser: nothing reaches our servers or analytics (T-10, T-67), and the route's analytics template is unchanged.

- Offered only for a poll with a short link that isn't hidden: a hidden poll's text was withheld by moderation, so we don't offer to spread it; a delisted one is still reachable by link and keeps the sheet.
- The title is the link preview's (`Poll <code>` until the API serves question text, [[P4-3]]).
- Tested: `poll-share.stories.tsx` (copy, failed copy, the share menu's exact data, the email fallback, dark; axe at desktop and 360px), `poll-summary.stories.tsx` and `tests/ssr.test.ts` (the trigger is server-rendered for a coded poll, absent without a code and for a hidden poll).
- Known-weak: the trigger needs the page's script; without it the short link is still in the page's evidence. The fallback line ("open abolish.ch or abolishus.eth and enter the code") is left out until the ballot client takes a code. The ballot client's "Ask others" on the Done screen waits on [[P2-20]]'s Done screen. The mockup's story (`share-sheet.stories.tsx`) stays until the QR, flyer and embed rows land.

## Part 1b: the QR code in the share sheet

The encoder [[sharing]] recommends already sits in `packages/ui` (`src/lib/qr.ts`, any version, levels L to H, tested by `tests/qr.test.ts` against the standard's published tables and an independent reader), with its `QrCode` component, so this part adds no dependency. Below the share rows, **Show a QR code** expands inline (`aria-expanded`) to the poll's short link as a QR code at level M, drawn in the browser: the link upper-cased (`HTTPS://ABOLISH.US/P/<CODE>`), which alphanumeric mode keeps at version 2, the coarsest grid; the router already matches `/P/` and codes are case-insensitive ([[sharing]], Short links). Dark modules on a white ground in both themes. It holds the same link as everything else in the sheet, so it says nothing about who showed it (T-10); nothing reaches our servers or analytics (T-67).

- Tested: `poll-share.stories.tsx` (`QR code`: collapsed by default with no image, the image's name, version 2's 33-module view box proving the upper-case alphanumeric form, collapsing again; `QR code, dark`: the light ground; axe at desktop and 360px).
- Known-weak: the code is drawn only once the sheet opens in the browser, so it needs the page's script, like the sheet. The note doesn't yet send people to a flyer for print; that row comes with part 2. The mockup's story stays until the flyer and embed rows land.
