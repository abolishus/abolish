# P2-18: Short links

- State: in progress (part 1, the code functions in `packages/core`, merged in #199; part 2, the lookup in Postgres and the API route, next)
- Branch: `claude/p2-18`
- Phase: Phase 2: Open polls end to end at Tier 0

## Scope

Short links for polls, as [[sharing]] (Short links and entry points) designs them: `abolish.us/p/<code>`, where the code is the first 35 bits of the poll's definition hash (its seal) as 7 characters of lower-case Crockford base32 (`0-9a-z` without `i l o u`). The link-preview renderer already computes the 7-character form (`shortCode` in `apps/web/src/og/model.ts`, P2-9); nothing resolves a code yet, so the link printed on previews doesn't open anything.

The rules every part keeps:

- **Ownership is a pure function of public data.** Among registered polls in registration order, the earliest whose definition hash has a 7-character prefix owns that code; a later poll whose prefix is taken gets 8 characters, then 9, and so on. An earlier poll's code never changes when later polls arrive, so a poll ground to collide can't take an existing code, and mirrors, `apps/node` and the verifier can resolve codes without us.
- **Forgiving input.** Codes are case-insensitive; on input `o` reads as `0` and `i`/`l` as `1`; `u` and anything else outside the alphabet is refused. QR codes carry the upper-case form (`HTTPS://ABOLISH.US/P/3J55DW1`), so `/P/<CODE>` must resolve too.
- **No code is kept.** Page analytics record the template `/p/:code`, never the code (T-67). A refusal never echoes the input.

## Plan

Each part is one PR on this branch's name. None is protocol code, so none is inside the `crypto-review` gate.

1. **The code functions** in `packages/core` (shared by `apps/api` and `apps/web`; `packages/crypto` stays protocol-only): `shortCode(hash, length)`, input normalisation, and the ownership rule over definition hashes in registration order. `apps/web`'s `shortCode` moves here. Fast-check properties (honouring `FC_NUM_RUNS`, printing the seed): codes round-trip; normalisation accepts every forgiving variant and refuses the rest; every poll gets a unique code; an earlier poll's code never changes as later polls arrive, adversarially colliding prefixes included; a code grows past 7 characters only on a collision.
2. **Lookup in Postgres and the API route.** A Drizzle migration (the migrations skill's workflow) adding what an indexed lookup by definition-hash prefix needs, and a contract route in `packages/api-contract` (`zod/mini`, strict) that resolves a code to its election id and canonical code, for example `GET /elections/by-code/{code}`. It applies the ownership rule at the code's length, resolves a delisted or hidden poll exactly as the election routes resolve it by id today, and is rate-limited like comparable routes. The OpenAPI spec is regenerated. Tests: resolution, collisions resolved by the rule, unknown and malformed codes answering 404 without echoing input.
3. **The website's `/p/<code>`.** It resolves the code through the API and redirects to `/polls/<electionId>`, with long caching only for a code that resolved. An unknown code gets the site's NotFound page with a 404. The router also matches `/P/<CODE>`. The poll page and the link preview show each poll's canonical code, so a collided poll shows its 8-character one. The analytics template `/p/:code` is added to `src/analytics.ts`. Tests in the style of `ssr.test.ts` and `serve.test.ts`: redirect, upper-case and forgiving forms, not found, the analytics template, and security headers on the redirect.

Later, with the sharing surfaces: `/p/<code>/flyer`, `/p/<code>/embed`, `/embed/p/<code>` (the script-free embed, which needs `frame-ancestors` relaxed on `/embed/*` only), and code entry in the ballot client's other entry points ([[0020-entry-points]]).

## Part 1 (#199)

`packages/core/src/short-codes.ts` (also `@abolishus/core/short-codes`): `shortCode`, `parseShortCode`, `assignShortCodes` and `resolveShortCode`; `apps/web`'s link previews call it.

- The rule as built: in registration order, a poll's code is the shortest prefix of at least 7 characters that no earlier poll's **hash** shares (not merely no earlier poll's code). So a code's owner is always the earliest poll with that prefix, and part 2's lookup is: the earliest registered poll whose hash starts with the code, which owns it if the code is 7 characters or some earlier poll shares its prefix one character shorter. Any other prefix answers 404.
- Codes run to 52 characters: the 52nd holds the hash's last bit and four zero padding bits, which `parseShortCode` requires, so distinct hashes always get distinct codes.
- Case is folded in ASCII only (the Kelvin sign is refused, not read as `k`).
- Tested: fast-check properties against an independent bit oracle and a naive statement of the rule over adversarially colliding prefixes (uniqueness, stability as polls arrive, growth only on collision, resolution), plus fixed examples.
- Known-weak: a 7-character collision costs seconds to grind, and it only ever lengthens the grinder's own code; someone who learns a definition hash before it's registered can register a colliding poll first and push the victim to 8 characters. `assignShortCodes` holds every hash in memory: it is the reference, and part 2 resolves in Postgres.
