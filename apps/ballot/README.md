# @abolishus/ballot

The ballot client: a static single-page app, the only place a vote is cast. Built reproducibly into `dist/`, which is hash-addressed and served unchanged from `abolishus.eth`, subdomain IPFS gateways, our domains and the Capacitor shell. Internal (AGPL-3.0-only).

## What it holds to

- **No third-party runtime code beyond React, the shadcn/ui runtime and `@abolishus/crypto`'s `@noble/*` libraries** (owner decisions 2026-10-12; T-43). `tests/bundle.test.ts` builds the app, Web Worker included, and fails if any module in the bundle comes from an npm package outside its allowlist (React, Base UI and its dependencies, `class-variance-authority`, `cn`, `lucide-react`, `@noble/*`), or from workspace code other than this app, `@abolishus/ui` and `@abolishus/crypto`'s build. The fonts (Oxanium, JetBrains Mono) are bundled, never fetched from a CDN.
- **No analytics** (T-67). The same test fails on any analytics, tracking or error-reporting SDK's markers (PostHog, Google Analytics, Segment, Sentry and others) and on any URL other than a short list of inert strings (XML namespace names, React's error-decoder link, Tailwind's licence comment).
- **A strict CSP** (T-43), in a `<meta>` tag ahead of everything that loads, so it travels with the bytes whoever serves them: scripts, styles, fonts and images from the client's own origin only; no inline code or `eval`; `connect-src 'none'` until the screens that fetch an election add the API's origin; workers from its own origin only; Trusted Types, so no string becomes markup or script, with one named policy (`ballot-worker`) reserved for the worker's own script URL; no `<base>` and no form posts. `tests/csp.ts` pins the policy directive by directive. A `<meta>` policy can't set `frame-ancestors`, so framing protection needs a header from the host.
- **Protocol work in a Web Worker** (`src/worker/`). The worker checks an election before the client shows it, with `@abolishus/crypto`'s `checkElectionToShow`: it refuses a definition that doesn't decode, names another election or is ill-formed, and text that doesn't decode, doesn't match the definition's commitment or is ill-formed (T-34, T-41); `src/election.ts` only turns a passed election into what the screens show. Encryption and proving join it later. The page spawns it through the one Trusted Types policy the CSP allows, `ballot-worker`, which `src/worker-policy.ts` creates when it is evaluated; `main.tsx` imports it first, so it exists before any other module's code runs, and it mints a URL for the worker's own script only. A worker takes no CSP from the page, so on a host that sends no CSP header it would run unrestricted: it has no network, storage or code-loading API, and the page does all I/O (T-43).
- **Relative URLs only** (`base: "./"`), so one build works at any path (T-41, T-49).
- **An origin of its own.** A path gateway (`/ipfs/<cid>/`, `/ipns/<name>/`) puts every CID on one origin, where `'self'` and the same-origin policy admit any other content on the gateway: a page under another CID could open or frame the client, read its document and replace `crypto.getRandomValues`. So the client shows a refusal instead of running on such a path (`src/origin.ts`; T-43, T-41). It is served from origins dedicated to it: our domains, `abolishus.eth`, or a subdomain gateway (`<cid>.ipfs.<gateway>`).
- **Third-party licences** ship as `third-party-licenses.md` beside the bundle, since minification strips React's notice.
- **Reproducible**: `dist/` is declared as the build output, and `repro-build` builds it twice and compares every byte.

## Test

- `vp run --filter @abolishus/ballot test`: builds the app and checks the bundle (the worker's script included: its own file, with no network, worker or code-loading API), the CSP and `index.html`, and the path-gateway rule; checks that the entry script creates `ballot-worker` before React's code; checks what the client shows of a checked election (the checks themselves are tested against every vector in `packages/crypto`); and checks the page–worker messages and the worker-URL rule.
- `vp run --filter @abolishus/ballot test:e2e`: serves the production build and loads it in headless Chromium: it renders with its styles and fonts, with no CSP violation, console error or request to another origin, and the browser refuses an injected script, markup written into an HTML sink, an event-handler attribute, a request to any origin and an image from another origin; served under `/ipfs/<cid>/`, it refuses to run; the page already holds `ballot-worker`, so no later code can create it. `tests/worker.e2e.ts` builds a test-only page (`tests/harness/`) under the same CSP that drives the real worker: it checks an election and refuses relabelled text, nothing but the client's own files is requested while it runs (the worker's script is served with no CSP header, as a gateway would), and no worker can be spawned from a plain string URL. Needs Playwright's Chromium (`vp exec playwright install chromium`).
- `vp run --filter @abolishus/ballot test:storybook`: every screen's story in headless Chromium, its play function, then axe (WCAG 2.2 AA), in both themes.
- `vp run --filter @abolishus/ballot preview`: builds and serves the production client. There is no dev-server script: Vite's development client injects inline styles and a WebSocket that the CSP refuses, and a relaxed development policy would be a second policy to keep from leaking into a release. Use Storybook for working on screens.
