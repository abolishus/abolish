# @abolishus/web

The public website: a TanStack Start app rendered on the server, for finding polls, reading what our server says about them and, later, their results. It never casts a vote: ballots are cast only in [`apps/ballot`](../ballot/README.md). Internal (AGPL-3.0-only).

## What it holds to

- **Our server calls the API; the browser doesn't** (T-10). Pages get data from server functions (`src/data.ts`), which call the public API (`src/server/api.ts`) with requests built from the contract and the poll ID alone, so a visitor's cookies, account session, address or user agent never reach the API. Every answer is checked against `@abolishus/api-contract` before use.
- **Claims, shown as claims** (T-24, T-34). A poll page decodes the definition with `@abolishus/crypto`, the verifier's own code, and refuses one that doesn't decode or names another election. It shows the definition's hash, to compare with the election registry, and the board's size, chain head and root, saying plainly that they are only this server's word until an L1 checkpoint covers them.
- **One spelling per poll** (T-31). A poll page's address is its ID in lowercase hex; anything else is not found. The lookup form forgives `0x`, capitals and spaces and redirects to that one address.
- **Short links that check their claim** (T-31, T-34, T-67). `/p/<code>` (and `/P/<CODE>`, as a QR code carries it) takes any forgiving form of a poll's short code, asks the API which poll owns it (`GET /elections/by-code`), fetches and checks that poll's definition as its page does, and redirects (301) to `/polls/<id>` only if the code is a prefix of that definition's hash. Only that redirect may be cached, for a day; anything else is the site's 404, which never quotes the input, and analytics count `/p/:code`, never the code. The poll page and its link preview print the poll's canonical code (`GET /elections/code`), which is longer than 7 characters for a poll whose prefix an earlier poll took, and only if it is a prefix of the definition hash the page checked; with no registration recorded they print none, rather than a 7-character prefix that could be another poll's.
- **A CSP with a nonce per response** (T-43). Scripts only from our own origin plus the inline scripts the server rendered that response with, each carrying its nonce; styles, fonts and images from our origin; `connect-src 'self'`; no framing, `<base>` or plugins. With `no-store` (a cached page would share its nonce), HSTS, `no-referrer`, `nosniff`, same-origin opener and resource policies and a restrictive `Permissions-Policy` on every response (`src/security.ts`, `src/start.ts`).
- **Server functions refuse other sites** (`createCsrfMiddleware`, by `Sec-Fetch-Site` and `Origin`), before any handler runs.
- **Errors quote nothing.** A failed API call reaches the page as one fixed error, because a server function's error is serialised into the page; the log gets its kind only.
- **Accounts live here, never votes** (T-10, ADR 0017). `/auth` is the account handler from `@abolishus/core` (passkeys only), mounted by the Node front, so its host-only session cookie never reaches the API or the ballot client's host. `/account` signs up, signs in and out, lists the account's polls from `/drafts` (each failure in plain words, with retry, discard and delete), manages passkeys and deletes the account; its WebAuthn JSON conversions are our own (`src/account/webauthn.ts`), so the page adds no third-party browser code (T-55). The pages never receive the session cookie: the front passes `Cookie` only to `/auth`.
- **A front that logs no paths** (T-10, T-11, T-67, T-52). `src/node/serve.ts` serves the built Start handler, `/auth` and the hashed assets on `node:http`. It builds every request's URL on `WEB_ORIGIN`, never on `Host`; it bounds bodies at 64 KiB and requests in flight at 64, and times out idle or slow connections; its log line is the method, a route class, the status and the duration, never a path, query, header or address.
- **Analytics that can't follow anyone** (T-67, T-55). PostHog gets product analytics and error tracking only from our server: page views are counted by the front as a template from a fixed list (`/polls/:id`, never the ID) and a status, and a page reports its own uncaught errors to `/ingest/error` on our origin as an error name, the page's template and positions in our hashed bundles, never a message or path (`src/analytics.ts`, `src/error-reports.ts`). The front passes on only a report of exactly that shape, from our origin, naming bundles it serves. Every event gets a fresh random ID and no person profile, GeoIP is off, and events go in shuffled batches every 10 seconds without their own timestamps (`src/node/analytics.ts`). No page loads PostHog's code or talks to its host, and PostHog sees our server's address, never a visitor's.
- **Moderation is public** (T-68). `/moderation` lists every decision with its reason code, never who made or reported it; a delisted or hidden poll says so on its page and tells search engines not to index it. `/polls` lists only what the API's listing names (`GET /elections`), which leaves out delisted and hidden polls; each listed definition is decoded and checked as on its own page, and the page says the registry on chain names every poll.

## Build and run

`vp run --filter @abolishus/web... build` packs the Node entry into `dist/node/main.mjs`, then builds the Start app into `dist/server` and `dist/client`, with every dependency inlined into the server. `node dist/node/main.mjs` runs from `dist/` alone, with no `node_modules`; `Dockerfile` packs `dist/` into the image `deploy.yml` ships to staging ([Railway runbook](../../docs/runbooks/railway.md)).

## Configuration

- `API_URL`: the public API's base URL (`http(s)`, no credentials, query or fragment).
- `WEB_ORIGIN`: this site's public `https` origin. Every request's URL is built on it, and it is the passkeys' origin.
- `ACCOUNT_RP_ID`: the passkeys' RP ID; `WEB_ORIGIN`'s host by default. Never the ballot client's RP ID or same-site with it (ADR 0017).
- `ACCOUNT_SECRET`: signs account cookies; at least 32 bytes of randomness.
- `TURNSTILE_SECRET_KEY`: the Turnstile widget's secret key. Every passkey ceremony start (sign-up, sign-in, adding a passkey) needs a token solved on `WEB_ORIGIN`'s host, checked with Cloudflare before anything is written (packages/core, Turnstile).
- `TURNSTILE_SITE_KEY`: the same widget's site key, which the poll editor (`/account/polls/<id>`) renders it with when an author submits a poll. Without it the editor says polls can't be submitted here; a malformed one is refused at start. Only the editor's pages allow Turnstile's script and frame in their CSP (`src/security.ts`).
- `BALLOT_URL`: the ballot client's address (`https`, no credentials, query or fragment; ADR 0020's second domain). The stream's cards (`/discover`) link to it with the poll in the fragment, `#election=<id>`, which no server sees. Without it the cards link only to each poll's page; a malformed one is refused at start.
- `DATABASE_URL`: a login granted `abolish_app` only (packages/core, Database).
- `POSTHOG_HOST`, `POSTHOG_KEY`: PostHog's ingestion origin (`https://eu.i.posthog.com`, say) and the project API key, both or neither. Without them nothing is reported.
- `WEB_HOST`, `WEB_PORT`: where to listen; `127.0.0.1:3000` by default, behind the proxy that terminates TLS.

## Test

- `vp run --filter @abolishus/web test`: unit and property tests of the ID and `u64` rules, the definition view against `docs/spec/vectors/election-definition.json`, and the security headers; then `tests/ssr.test.ts` builds the app and renders every page with the built server against a stub API: headers and nonces on every page, what a poll page shows and refuses, that nothing of the visitor's reaches the API, lookups and redirects, the moderation log, server functions refusing other sites, and an API outage that leaks nothing.
- The same task, against Postgres (`TEST_DATABASE_URL`): `tests/serve.test.ts` runs the front with the real account handler as `abolish_app` and a software authenticator fed through the page's own WebAuthn conversions (sign-up, a second passkey, sign-out, sign-in, deletion, a cross-origin sign-out refused), and checks assets, path traversal, the origin the URL is built on, `Set-Cookie`, body bounds, the in-flight limit and the log; `tests/deployable.test.ts` copies `dist/` out of the repository, runs `main.mjs` with plain Node and checks a page, its assets and `/auth`, a refusal to start on bad configuration that quotes none of it, and that no client asset carries account server code.
- `tests/analytics.test.ts`: page templates and stack frames by property (no path's text, only frames in our bundles), the report shape and every refusal, the browser reporter (its cap per page load, what it ignores) and PostHog batches (anonymous, bounded, failures logged by kind). `tests/serve.test.ts` checks what the front reports for each route and every refusal at `/ingest/error`; `tests/deployable.test.ts` checks the client bundle carries no analytics SDK and that half a PostHog configuration stops the server.
- `vp run --filter @abolishus/web test:storybook`: every component's stories in headless Chromium, their play functions, then axe (WCAG 2.2 AA), in both themes.
