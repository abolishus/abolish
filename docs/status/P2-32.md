# P2-32: Testnet contract deployment

- State: in progress (part 1, the deploy script and its local run, in parts: part 1a, the preconditions audit and [[0044-testnet-deployments]], merged in #840; part 1b, the deploy script and its local run, next)
- Phase: Phase 2: Open polls end to end at Tier 0

## Scope

The owner's top priority (2026-10-29): nothing on staging can create, open or count a real poll until the contracts exist on Base Sepolia (L2, 84532) and Sepolia (L1, 11155111) and the services pin them. No deploy script, deploy workflow or deployment record exists yet ([[P2-22]], Blocked, item 1; [[staging-testnet]], Not yet possible). This item builds all three, so the owner's deploy day is running one workflow and pasting its record's addresses into Railway.

## Parts

1. **The deploy script and its local run** (`packages/contracts/script/`, no `.github/` change). One Foundry script that deploys every contract the staging path needs in dependency order: the L2's group registry, election registry, trustee registry (pinning the launch panel), board, registration account and paymaster, with the Safe + TimelockController admin the `contracts` skill requires; the L1's board anchor (trusting the anchoring Safe), and the receipt-key registry [[0023-receipt-evidence]] calls for if it isn't built yet (then it is this part's first PR). Every pin a contract takes at construction (the panel's keys and threshold, the Tier 0 registrars and threshold, the Safe, the anchoring clock) comes from the script's environment, never a literal. It writes `packages/contracts/deployments/<chain-id>.json` (addresses, transaction hashes, runtime bytecode hashes, the deploying commit) and refuses to run if any spec precondition below fails. A test deploys it to two local Anvil chains and checks every recorded address's code hash and every pin read back through the generated bindings.
2. **The deployment record** ([[deployment]], record `0x0020`): a command in `packages/contracts` (or `packages/core`) that builds the canonical record from the two chains' JSON files plus the owner's off-chain inputs (origins, RP IDs, published groups, prover hashes), checks it against [[deployment]]'s well-formedness rules, and prints the Railway variables each service needs (`CREATE_*`, `REGISTRY_SYNC_*`, `TIER0_*`, `POLL_STUB_*`, `POLL_ROOT_GROUPS`, the seats' `TRUSTEE_CONFIG` fields) so no address is copied by hand. Workers' startup checks ([[P2-22]] part 4b) read it unchanged.
3. **`ci: testnet contract deploy`** (rule B: its own small `ci:` PR, no auto-merge, the owner reviews): a `workflow_dispatch` workflow in the `staging` environment that installs the pinned toolchain, runs part 1's script with `TESTNET_DEPLOYER_KEY` on both chains, verifies every contract on the explorers with `ETHERSCAN_API_KEY`, runs part 2's check over the result and opens a PR committing `deployments/` and the record. Dry-run mode (simulate only, no broadcast) is the default input.
4. **Runbook**: [[staging-testnet]]'s "Not yet possible" and "Deploy day" rewritten around the workflow, listing each input variable, which key it is and what to do with the printed Railway variables; [[P2-22]]'s Blocked item 1 marked done once the workflow has deployed.

## Preconditions the script enforces

The spec forbids deploying a registry or board until these hold ([[contracts]], Election registry, Known-weak; the event tables' retirement notes): every superseded definition version and event-table version the spec says MUST be retired is retired in the deployed bytecode; the close rule's contracts ([[close]]) and membership-checked intake ([[P1-12c]]) are in. If one isn't met on `main`, the first part of this item is closing it, before the script. Part 1a found nine open on `main`. [[0044-testnet-deployments]] waives them for the staging deployment alone ([[contracts]], Testnet deployments), so the script enforces the rest, and deploys only the staging target while any of the nine is open.

## Needs from the owner

- `TESTNET_DEPLOYER_KEY` and `ETHERSCAN_API_KEY` in the GitHub `staging` environment, the deployer funded on both chains.
- The pins: the anchoring Safe's address, the Tier 0 registrar addresses and threshold, the registration account owner, the seven seats' public identity keys and the panel threshold ([[staging-testnet]], Keys). Until they exist, parts 1 and 2 are built and tested against Anvil with generated test keys.

## Out of scope

Mainnet (owner sign-off), the independent panel ([[P1-7]]), and Tier 1/2 contract wiring beyond what the registries already deploy.

## Part 1a: the preconditions

Checked on `main` (2026-10-30). Each condition the spec gives as "before any registry is deployed", "before any deployment", or as before deploying a contract with a given call:

- **Met:**
  - the close rule's contracts ([[close]], [[P1-18]] part 4c);
  - membership-checked intake and the bounded receipt obligation ([[P1-12c]]), which closes [[0002-everlasting-privacy]]'s residual;
  - the contract paths for share receipts, batches, roots, postings and complaints ([[delivery]], Direct submit). The Board has every one of those calls, so STATUS's Known-weak entry saying they have none is stale;
  - contract-event versions 1 to 11 retired: rule 9 pins version 12 for every definition the registry serves;
  - definition version 2's window question ([[election-definition]], Deadlines), which is moot since every window is a constant;
  - the superseded tags: no contract uses `board-checkpoint`, `event-accumulator`, `sig/ceremony-registration`, the version-1 and version-2 nullifier-key approvals or the deadline-less reshare approval;
  - the self-paid path ([[0024-tier0-registration]], D);
  - [[P2-16]] part 5's contract side: ballot version 4, the version-2 delivery records and the author panel's registration;
  - the nullifier-key margins ([[nullifier-key]], Recording), which hold while the L2's sequencing window is at most `MAX_SEQUENCING_WINDOW` (3,600 L1 blocks, Base's). The runbook has the operator check Base Sepolia's on deploy day.
- **Open, waived for a testnet only** ([[0044-testnet-deployments]]; [[contracts]], Testnet deployments):
  - definition versions 1 and 3 still admitted;
  - the registry's decoder not budgeted to the record's limits under an L2 gas cap;
  - Tier 2's addition path ([[P3-4]]);
  - the nullifier-key events in a contract-event version ([[P3-4]]);
  - a contract path for tally openings ([[P1-18]]);
  - verifier 1.2's creation-code binding, which isn't specified yet ([[P4-1]]);
  - each group's region fixed at creation, logged and signed ([[0019-regional-cells]]). `GroupRegistry` takes no region yet, so registration serves region 0 only;
  - the verifier reading obligation roots' leaves ([[P1-12f]] part 3), which STATUS gives as a gate on any deploy of the board with the root call, testnets included, and which [[0044-testnet-deployments]] now waives for a testnet;
  - `tally-late` built in the verifier ([[P1-19]]), which STATUS gives as "no election registry is deployed before it". The window it needs is in bytecode ([[P1-18b]]).
- **Already scoped beyond a testnet in [[contracts]], which now binds every deployment but the staging one:** the operator's boarding throughput against self-paid floods ([[P4-3]]) and the `SELF_PAID_FEE` review. The script's chain check covers them too.
- **The owner's to accept for a testnet:** [[delivery]]'s three residuals: a newest ballot that never reached the board, approved stubs holding capacity, and withheld board data and the complaint scope. The deploy waits on it ([[STATUS]], Waiting on the owner). Parts 1b and 2 don't.
- **Not a deployment condition:** the verifier's own outstanding checks ([[P1-19]]: 2.3 requiring board-entry version 5, 4.5 and 6.3). They ship in its releases, not in any bytecode.

Part 1b's script takes an explicit target and, while any of these is open, deploys only the staging target and only on 84532, 11155111 or 31337, recording the target in its deployment files.
