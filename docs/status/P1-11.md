# P1-11: Group and hash layer

- State: in progress
- PR: #23 merged (ADR [[0007-group-and-hash]]); the group and hash layer is on this branch, restarted from `main`
- Branch: `claude/p1-11`
- Phase: Phase 1: Threat model, spec, crypto core, circuits, verifier, reference election (CLI only)

## Scope

Group and hash layer: point/scalar codecs with canonical decoding (ristretto255 has no subgroups to check), hash-to-scalar and hash-to-group and domain separation, plus published vectors.

## Decision

[[0007-group-and-hash]], accepted by the owner on 2026-10-10 (option A): ristretto255 (RFC 9496), SHA-256 as `H`, RFC 9380 `hash_to_ristretto255` for `h`, and RFC 9497's `HashToScalar` construction for Fiat–Shamir challenges. Threats: T-39, T-31, T-30 (T-30 and T-39 updated).

## Built (this branch, after #23)

- `@noble/curves` 2.4.0 in the catalog and as `packages/crypto`'s runtime dependency with `@noble/hashes` (`gated` passes).
- [[group]]: the group, `scalar` and `element` codecs, `H`, `HashToScalar`, `hash_to_ristretto255` and `h`; [[notation]], [[domain-separation]] (Fiat–Shamir via `HashToScalar`, `DST` length, `generator-h` specified, one primitive per tag) and the vectors README updated. The in-circuit tag rule and circuit packing move to P1-17 (group elements never enter a circuit).
- `packages/crypto`: `scalar`, `element`, `elementOrIdentity`, `H`, `challenge`, `hashToGroup`, `G`, `GENERATOR_H`, `IDENTITY`; `TAG_REGISTRY` gains each tag's primitive, and `ds` takes only plain-hash and KDF tags.
- Tests: RFC 9496 A.1–A.3, RFC 9380 K.3 and RFC 9497 A.1 (all three modes, proofs included) from the vendored RFC texts; `group.json` and `hash.json` from an independent Python implementation (`scripts/group-vectors.py`); fast-check properties for both codecs; a source check that every `@noble/curves` hash-to-curve call passes a `DST`; the static-DH factor script and a test of its trial-division table.

## Known-weak

- The 6.4-bit static-DH bound above 2¹⁷ queries rests on a probabilistic factor search (Pollard's rho, 2²³ iterations, `packages/crypto/scripts/static-dh-factors.ts`); CI checks only the trial-division part.
- No published vector covers `hash_to_ristretto255` in one step; ours are built from the two published halves.
- RFC 9496 A.4 (`SQRT_RATIO_M1`) is checked only through `Decode` and element derivation: `@noble/curves` doesn't export it.
- `challenge` accepts no tag yet: every Fiat–Shamir tag stays reserved until P1-12 specifies its statement layout.
- The vectors' independent implementation is ours too (Python, written from the RFCs); it shares no code with `@noble/curves`, and it checks itself against the RFC appendices before printing.
- The catalog change touches `pnpm-workspace.yaml`, a CODEOWNERS file, so the PR waits for the owner's review.
