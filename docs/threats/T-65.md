# T-65: Deployer or service credential leak

- Area: Development, supply chain and operations (G-14)
- Adversary: A-6, A-2
- Status: **Partial.** Environment protection rules are the owner's to configure; agents can't verify them. CI also holds a repository-level, read-only Docker Hub token (`DOCKERHUB_TOKEN`, #19) for pulling service images; any workflow run from an in-repo branch can read it, so it must stay read-only.

## Threat

Deployer or service credential leak.

## Mitigation

Testnet deploys only from GitHub Actions with environment secrets; no session ever holds a private key (AGENTS.md). Mainnet waits for the owner.

Index: [[THREAT_MODEL]].

## History

- 2026-10-11 (P2-11 part 1): [[railway]] gives each Railway service its own database login: `api-migrate` one granted `abolish_migrator`, `api` one granted only `abolish_app`, so the API's credential can't alter a table, trigger or grant. `RAILWAY_TOKEN` lives only in the `staging` and `production` GitHub environments, one project token per Railway environment.
- 2026-10-11 (P2-11 part 2, #69): migrations run from the deploy workflow, not a Railway service, so the migrator login is the `staging` environment secret `MIGRATE_DATABASE_URL` beside `RAILWAY_TOKEN` (which can read every Railway variable anyway), and Postgres is reachable over Railway's TCP proxy behind its passwords. `sslmode=require` encrypts that connection without verifying the proxy's certificate, so an active attacker between the runner and Railway could capture the migrator login, which can drop the board's triggers (T-23); results stay recoverable from chain and IPFS (T-66). Build and publish jobs hold no environment secret.
- 2026-10-17 (P2-22 part 1, [[0032-poll-creation-operations]], [[poll-creation]]): the creation key, an externally owned account for creating and registering website polls only, lives only in the `worker-create` deployment's Railway variables, with a float of a few days' gas; its rotation, sweep and compromise response are in the runbook. A thief can spend the float and create elections, and register only definitions our seats approved for elections it created ([[T-72]]).
- 2026-10-22 (P2-31 part 1, [[0038-verified-accounts]]): `apps/web` gains the SMS and email providers' credentials and three keyrings (phone hash, email hash, email encryption), kept in its environment only. A leak of the phone-hash keys together with the account table reveals every verified number (T-73); rotation, with its runbook in part 3, retires a leaked key.
- 2026-10-30 ([[P2-32]] part 3b): `TESTNET_DEPLOYER_KEY` is read by one job of `testnet-deploy.yml`, in the `staging` environment, which runs no npm code: only the hash-verified forge and cast, bash and jq. It reaches forge as a command-line argument (forge reads a raw key from no variable), so any process in that job could read it; none but those runs there. The rehearsal on forks sends as the deployer without its key, and the jobs that run npm code (confirming, the record) hold only the RPC URLs.
