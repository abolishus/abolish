# T-55: Malicious or hijacked npm dependency

- Area: Development, supply chain and operations (G-14)
- Adversary: A-6
- Status: **Partial.** In place for the lockfile, and for the gated packages' declared dependencies and imports. Residuals: a malicious release of any dependency older than 7 days, or a long-con maintainer, passes every check. The build toolchain (vite-plus and its rolldown, oxc and tsdown closure) is trusted: every bundle check, `repro-build` and the release double build run the same bundler, so a malicious toolchain release can inject code into every published package and the ballot client while writing honest-looking source maps. Dev dependencies run unconstrained in tests and builds. The import lint is a tripwire for a fixed list of loader names (`require`, `createRequire`, `getBuiltinModule`, `eval`, `Function`, workers, `process.dlopen`, `process.binding`); evaluator gadgets such as a function's `.constructor`, string timers, script elements and WebAssembly are caught only by review. Runtime guards still to add: a ballot-client CSP without `unsafe-eval` (P2-8) and running the verifier CLI with `--disallow-code-generation-from-strings` (P1-19).

## Threat

Malicious or hijacked npm dependency.

## Mitigation

Exact pins in the pnpm catalog; 7-day minimum release age; registry-only resolution with integrity matching the registry; no install scripts outside `allowBuilds`; provenance-downgrade refusal; `packages/crypto` resolves to `@noble/*` only, with an `@noble`-only lockfile closure, `src` imports limited to declared dependencies and a packed bundle that inlines no `node_modules` code, and the verifier only to gated packages and `@noble/*` (CI `gated` check, P1-9); `claude-review` justifies every added package (AGENTS.md, Dependencies).

## History

- 2026-10-11 (P2-5 part 1): `better-auth` and `@better-auth/passkey` 1.7.7 enter `packages/core`, with 45 lockfile packages, among them `@simplewebauthn/server` and the `@peculiar/*` ASN.1 and X.509 parsers. None reaches a gated package's closure (the `gated` check passes) and none has an install script. better-auth's telemetry is off in its options, and `createAccounts` refuses to start if `BETTER_AUTH_TELEMETRY` would switch it back on.
- 2026-10-12 (P2-7, part 1): `packages/ui` adds Tailwind 4.3.3 and `@tailwindcss/vite` as dev dependencies (build-time only: the CSS compiler, its `@tailwindcss/oxide` native scanner and `lightningcss`, each with per-platform optional binaries and no install scripts), and IBM Plex from three `@fontsource` packages as runtime dependencies (CSS and font files, no code). None reaches a gated package's closure. `apps/ballot` will bundle the fonts but no third-party code from `packages/ui` (T-43).
- 2026-10-11 (P0-2): Storybook and its Vitest browser-mode runner join the dev dependencies of `packages/ui` (about 200 packages, none in a gated package's closure). One setting was needed: the owner's decision excludes `semver@6.3.1` from the provenance-downgrade check (it is a 2023 security backport published without provenance). esbuild's install script stays unapproved and doesn't run. Its platform binary comes from an optional package, so the script isn't needed. These dev dependencies run unconstrained in tests and Storybook builds, like every other dev dependency.
- 2026-10-12 (P1-18 part 5): `@wagmi/cli` 2.10.0 joins `packages/contracts`' dev dependencies for the contract bindings the brief names (54 lockfile packages, among them viem and esbuild 0.25.12). Build-time only: the generated bindings are plain data with no imports, and `packages/contracts/test/bindings.test.ts` compares them with forge's artifacts. esbuild's install script stays unapproved and doesn't run. None reaches a gated package's runtime closure.
- 2026-10-12 (P1-18 part 5 follow-up): that closure runs in the contracts package build after `forge build`, with write access to `out/`, so it can rewrite bytecode without changing an ABI. Verifier 1.2 and deployments therefore take a forge-only release build, never the package build's `out/` (T-64).
- 2026-10-17 (P2-21 part 1, [[0009-membership-proof]], Amendment): snarkjs 0.7.5 and ffjavascript 0.3.1 are proposed as the ballot client's first third-party runtime code beyond React and the shadcn/ui runtime, in the worker's chunk only, as upstream's prebuilt browser bundles (with six inlined packages). They run beside the identity secret, so a hijacked release could leak it; exact pins, the 7-day release age, the lockfile's integrity, review of the bundled files and the hash-addressed release are the defences. Admitting them is the owner's (`ci:`, the bundle allow-list).
