# P1-12d: Share receipts carried many to a signature

- State: todo
- Phase: Phase 1: Threat model, spec, crypto core, circuits, verifier, reference election (CLI only)

## Scope

Raise the cap that [[P1-12c]] part 2's capacity check puts on an election's electorate ([[delivery]], Capacity; STATUS, Known-weak). On the forced path a contract-path receipt costs about 63,000 gas, because each carries its own P-256 signature, storage key and event. With the deployed windows and `R` of one hour, that limits an election to about 1,280 members with 3 seats, or about 28,000 with `R` of 21 hours. Honest trustee nodes refuse anything larger (stub check 4), so larger elections can't be registered (T-25, T-52, T-54).

- [[delivery]]: a share-receipt batch record. One seat's signature covers many (`ballot_hash`, `share_hash`) pairs of one election, under its own signature tag ([[domain-separation]]). The delivery check reads each pair as a receipt that passes `share-receipt` when the batch's signature verifies.
- `packages/contracts`: a board call and event that take a batch with one signature verification, one storage key and one event per batch. Adding the event needs a contract-event version that names it, which the election registry's profile rule then pins. It must be decided before any registry is deployed.
- `packages/crypto` with an independent Python model and vectors; `packages/verifier` reads the record (coordinate with [[P1-19]]).
- Re-measure the forced path's figures and update `FORCED_PATH` and the caps.

A national electorate needs more than any record per receipt on L1. The obligation could instead be committed as a root, with its leaves made available by [[P4-3]]'s data availability. That choice is an ADR.
