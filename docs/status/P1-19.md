# P1-19: `packages/verifier` CLI

- State: in progress, waiting on #40 (first part: verifier library, input bundle, report and board checks 4.1–4.2)

## Scope

`packages/verifier` CLI: download the board (from local files first), recompute and check everything, and check a served ballot client against a signed release. Spec in `docs/spec/verifier.md`. Per [[0005-permanent-archive]]: check the archived event sequence against each contract's event accumulator using archived storage proofs at output roots (reporting whether each root settled by TEE-only or ZK proof), walk the manifest chain and every anchor's `archiveLocator`, and pass with Arweave or IPFS unreachable.

## Waiting on #40

The verifier imports `@abolishus/crypto`, the first import between workspace packages. Crypto's `exports` point only at `dist/` (gated.ts), so root `vp check`, the verifier's checks and tests, and the gated pack all fail on a fresh CI runner until crypto is built first. #40 (`ci:`, owner review) builds it in the setup action and before the gated check. This part's PR opens once #40 merges.

## Plan

The item is built in parts, each its own PR on this branch's name:

1. **Library, bundle, report and board checks** (this part): local inputs only, checks 4.1 and 4.2, every other check reported unverifiable.
2. **CLI.** A `bin` entry, which needs a `ci:` change first: `gated.ts` doesn't allow `bin` in a packed manifest. Exit codes per verdict.
3. **Inputs from L1 and the definition**, replacing bundle members: anchors and `now` (P4-1), the clock, election identifier and pinned versions (P1-10b, #35).
4. **Event-accumulator replay (4.4)**, once P1-18 part 4 defines the contract-event record and its evidence. Then archive walking (4.3) with P4-3, and the ballot, ceremony and tally checks as P1-12 to P1-15 land.

## Tested

- Every board of `docs/spec/vectors/board.json` (the independent Python implementation), written as a bundle. Each gives the rows the spec's table predicts for its code: pass/pass, fail/not-reached, not-reached/fail, pass/fail, or unverifiable/unverifiable for a bad copy. The verdict is `unverifiable`, and `verdictAgainstInputs` is `failed` exactly for election failures.
  - Two vectors can't be written as `board.bin` as they are. `entry-trailing-bytes` is self-delimiting, so its extra bytes become the next entry's start, and the copy no longer matches. `forged-trailing-ignored` ends with a 2-byte fragment, reported as unreadable and changing nothing.
- The report:
  - lists every check of `docs/spec/verifier.md` exactly once, in order (parsed from the spec);
  - gives each check its kind;
  - reports every unimplemented check unverifiable;
  - keeps its members in the spec's order.
- Splitting (fast-check, at `FC_NUM_RUNS=1000`):
  - concatenated entries split back exactly;
  - a short tail or a truncated payload is counted, never split;
  - a length over `MAX_BOARD_PAYLOAD` stops before anything is read;
  - unreadable bytes past the extent change nothing, and inside it they give `checkpoint-missing`.
- The bundle:
  - every in-range value round-trips (fast-check);
  - 24 malformed shapes are each rejected, including uppercase or short hex, leading zeros, out-of-range integers, unknown or missing members and `__proto__`;
  - invalid UTF-8 is rejected, not replaced.

## Known-weak

- **No verdict yet.** Every input is a local file and most checks aren't implemented, so every run reports `unverifiable`. That is by design, not a gap in what's built.
- **No CLI yet** (part 2: `bin` needs a `ci:` change to `gated.ts`).
- **Duplicate JSON members aren't detected.** `JSON.parse` keeps the last one. A bundle is unauthenticated input, so two readers disagreeing on one changes no verdict, but a later part that reads members from L1 must not inherit this.
- **`board.bin` is split by the version-1 layout.** An anchored entry in another layout (no other version exists) would leave the copy unsplittable or mis-split: unverifiable from that copy, never a failure. If a version 2 changes the layout, splitting must follow the pinned version.
