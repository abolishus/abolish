## Scope

Split from [[P1-10]], which built the primitive codecs, record framing and `DS` framing. This item specifies and implements version 1 of the election definition (`0x0001`) and the display-text record (`0x0009`) in `docs/spec/` and `packages/crypto`, with vectors (`docs/spec/vectors/election-definition.json`, `display-text.json`) and the `profile-mismatch` vectors. It also specifies the `abolish/v1/election-definition` tag's input layout.

Waits on: the group and hash layer (P1-11) for `H` and for group elements in the definition; the trustee panel encoding ([[0006-trustees]], which the owner decides) for the panel field, which until then can be a test panel.

## Carried over from P1-10's reviews

Non-blocking findings from the #21 reviews. #35 closes all four (see Built).

- **The definition's own version pin.** The election definition carries the profile, so it can't be decoded against a pin known in advance. Add a dedicated definition decoder: decode `UNPINNED`, then reject with `profile-mismatch` unless the decoded version equals the profile's pin for `0x0001`. Add a vector for it. Otherwise, once a second definition version exists, a creator could encode a new election under a retired layout (T-34, T-31; [[verifier]] check 2.3). Also correct the `packages/crypto` README, which says only vector files and tests pass `UNPINNED`.
- **Error code precedence.** When a record's version is both unknown to the decoder and not the pinned one, `RecordSchema.decode` reports `unknown-version`, while [[verifier]] 2.3 says `profile-mismatch`. Settle which code wins in [[notation]] and the vectors, then make the code match.
- **Unregistered record numbers.** A production `RecordSchema` (without `allowTestRange`) accepts any number from 1 to `0xfeff`, including numbers the registry never assigned. Reject numbers outside `RECORD_TYPES` unless the test range is allowed, so [[versioning]] stays the only place numbers are assigned.
- **`struct()` keeps the caller's fields array.** Copy and freeze the fields when the codec is made, so the layout can't change after a record type registers it.

## Known-weak

- **Version 1 will likely be superseded.** P1-14 (panel, ceremony), P1-17 (electorate, verification-key hash), P1-18 (contracts, timing and close rule) and the owner's trustee decision ([[0006-trustees]], including whether civic elections need a marker) may each need a field changed; each change is a new version, and every verifier keeps version 1 until its retirement cutoff ([[0008-draft-record-layouts]]).
- **No well-formedness bound on `l1_inclusion_bound`, `sequencing_window` or `max_sequencer_drift`** (zero is accepted). P1-18 owns the close rule and adds the bounds.
- **A creator can archive somewhat over 100 chosen bytes per definition:** `election_id` (until P1-18's registry assigns it), `display_text_commitment` (only the report-only check 2.7 compares it with text), and the free bits of the bounded integers (times, `l1_inclusion_bound`, `sequencing_window`, `max_sequencer_drift`, `root_l2_block`). T-17's residual now says so.
- **Labels can differ only invisibly** (`Yes` and `Yes` plus U+200B): exact repeats are rejected, look-alikes aren't (T-41).
- **Translations aren't checked against each other.** Two translations can give an option different meanings. The commitment makes that public evidence but doesn't prevent it (T-41).
- **`threshold ≥ 2` is the only floor on `k`.** [[0006-trustees]] may raise it.
- **Decode-error labels in the vectors are written by hand** from the strict-decoding rules; only the encodings and the rule labels are checked by the independent script. `unexpected-record-type` for a definition is tested in TypeScript only, because a vector file's known types are only those in that file.
- **One identity in two tier groups votes once in each.** Since P1-17 the nullifier scope binds the tier ([[membership]], Scope), so each tier counts at most one of its ballots; a voter in several tiers may vote in each, which G-2 allows (T-16).

- **`encodeElectionDefinition` and the hash functions accept a definition whose profile doesn't pin `0x0001` at exactly version 1.** Such bytes hash, but `decodeElectionDefinition` rejects them with `profile-mismatch`, so a creator tool must check the self-pin before registering. Making the encoder refuse them would also stop the property tests from building `profile-mismatch` inputs, so it waits for P1-18's creation path, which must check that `decodeElectionDefinition(encodeElectionDefinition(d))` succeeds before registering: registration is write-once, so a mistake costs the creator the election.
- **The anchoring authority is still pinned by the verifier release** ([[board]], Anchoring; this PR doesn't change it). An insider could anchor a conflicting seal checkpoint on time from an address no release pins, then ship a release that pins it, so two releases disagree on one closed election (T-24, T-53). P4-1 should make the authority set an immutable property of the anchor contract, which rejects anchors from anyone else.

## Handed to other items (from `crypto-review` on #35)

- **P1-18:**
  - The election registry admits a definition only if `trustee_registry` recorded its stub hash for its `ceremony_transcript_hash`. It assigns `election_id` from the chain ID, its address and its counter ([[board]]) and admits one definition for it, write-once, only from that election's creator; it does not reject a repeated `ceremony_transcript_hash`, since a first-come rule would let anyone who learns it before registration block or retroactively fail a legitimate election ([[election-definition]], Stub hash; T-25).
  - `trustee_registry` records a (stub hash, transcript hash) pair only with signatures over both by the identity keys of a panel the deployment pins, never on `msg.sender` alone (T-37, T-71).
  - It admits only well-formed definitions whose chain IDs and addresses are the deployment's own (T-17).
  - The group registry fixes each group's tier when it creates the group ([[verifier]] 2.1, 2.4).
  - The election registry rejects a definition with any tier's `root_l2_block ≥ block.number` ([[election-definition]], The electorate is in the past; T-08). That relies on `block.number` being the L2's own block number, as on Base ([[0004-l2-choice]]).
  - The contract-event record (`0x0008`) carries each event's authenticated L2 block number, so a verifier can compare a root's block with the registering block and attribute additions to blocks ([[verifier]] 2.4).
- **P1-14:** the ceremony context binds the definition's stub hash, and `trustee_registry` records it with the transcript hash ([[election-definition]]).
- **P1-12 and P1-14:** before making any share, the ballot client checks the panel against a pinned panel and checks that every share key comes from the bound transcript, signed by the trustee's pinned identity key. Trustee nodes run the same checks before receipting a share ([[verifier]] 2.5).
- **P2-8 (ballot client):** before casting, check that each `root_l2_block` the ballot uses and the definition's registration are in finalized L2 history and that the root rebuilt from the additions up to it equals the definition's; otherwise refuse to cast and alarm ([[election-definition]], The electorate is in the past).
- **P3-2:** every addition to a tier-t group carries tier-t evidence, so the verifier can check a definition's tier labels (T-01, T-06).
- **P1-13 and P1-15:** the share-delivery deadline, the complaint window and any re-vote freshness bound become constants of the pinned ballot and tally versions, or definition fields.
- **P1-13, P1-15, P1-18 and P4-1 (the seal):** `lastSegment` follows from the definition alone ([[election-definition]], The seal). P1-13 and P1-15 fix the openings and tally windows as constants of the record versions the profile pins; P1-18 fixes the post-finality window for contract events as a constant of the immutable contracts; P4-1 fixes `epoch`, `period` and `deadline` as immutable values of the anchor contract and computes the seal by that formula, never from a per-election or per-release value; P1-18's registry rejects a definition with `opens_at < epoch`, and P1-18 justifies the post-finality window against the L2's worst-case settlement delay. A version-1 election uses the anchoring authority its verifier release pins for `l1_anchor`. If any window must vary per election, version 2 of the definition comes before any election registry is deployed (T-54, T-53, T-23, T-24, T-36).
- **P1-12:** the plurality sum proof is over {0, 1}. The definition now requires `min_selections = 0` for plurality, as [[0003-tally-scheme]] says. For approval, the sum proof's range is [`min_selections`, `max_selections`], which extends [[0003-tally-scheme]]'s [0, L]. A non-zero minimum means a voter can't cast a blank ballot, or re-vote one (T-28, T-45).
