# P1-12c: Membership-checked intake and bounded trustee receipts

- State: done (part 1, membership-checked intake and the bounded receipt obligation, merged in #171; part 1b, the review follow-ups on #171, merged in #191; part 2, the complaint scope, the close rule in a node's view and the forced path's capacity check run by the trustee node as stub check 4, merged in #276; raising the cap that check puts on electorates is [[P1-12d]])
- Branch: `claude/p1-12c`
- Phase: Phase 1: Threat model, spec, crypto core, circuits, verifier, reference election (CLI only)

## Scope

The fix the owner chose on 2026-10-12 for the residual accepted on P1-12 part 3b (#101; [[0002-everlasting-privacy]], Decision): a trustee node's obligation to send receipts through the contract path ([[delivery]], Direct submit) has no bound, since intake checks no membership, so a flood of ineligible ballots plus an operator that withholds board data until the node's cutoff can force more contract-path receipts than any budget allows and silently drop receipted ballots whose clients have gone away (T-25, T-52, T-54).

- [[share-encryption]] (Intake and receipts) and [[delivery]]: at cast, the client gives each trustee the full ballot record, its membership proof included, with the ciphertext; spoiled ballots never reach intake, so the Benaloh challenge is unchanged.
- A trustee receipts only a ballot whose membership proof verifies against the registered tier root.
- A trustee node owes contract-path receipts only for the ballot [[revoting]] would count for each tier and nullifier, so its obligation is bounded by the electorate; state that bound and the capacity the windows support, and check it as `deliveryWindowFits` checks the windows.
- P1-18: the contract takes share receipts in batches (many signatures, one call, one forced deposit).
- Remove the residual from [[delivery]], T-25 and T-52 once closed.

MUST be done before any election registry is deployed. Board data availability (a content address per anchored segment and a publication deadline) complements it and stays with P4-3.

The residual in [[delivery]], T-25 and T-52 is replaced by a cap on electorates (Known-weak), which [[P1-12d]] raises.

## What was built (part 1)

- [[share-encryption]], Intake and receipts: intake takes the ballot record under the pinned version, and checks `delivery-malformed`, then `ballot-stray`, `ballot-tier` (`ballot-cell`), `validity-shape`, `share-hash-unqualified`, `share-hash`, `membership-proof`, `option-proof`, `sum-proof` and decryption. Before any intake the node checks the definition as a verifier does before admitting ballots, 2.4 and 2.8 included, since the recomputed member counts are what bound its obligation. The L1 reference isn't checked at intake. Notes: what a receipt now says (a registered member's ballot), the order, intake open to members rather than to anyone, and the timing residual narrowed to members.
- [[delivery]], Direct submit: **What a node owes**. At the intake cutoff `c_I`, for each (tier, ν) of a ballot it receipted, the node runs [[revoting]]'s selection over the ballots of its view (its receipted ballots less those shown absent, with every ballot it holds from the anchored board or the contract's records, each admitted) whose L1 reference is admitted, and owes the selected ballot's receipt only if it receipted its ballot hash, under any L1 reference (a ballot cast again with the same core after a reorganisation keeps its receipts); nothing on a tie. It decides once, at the intake cutoff `c_I = t_D − F − R` every node shares, over the view it then holds; intake stays open until `c_I` and is refused after it. `deliveryWindowFits` now checks `max(2 · period + deadline, W_C) + R + F ≤ DELIVERY_WINDOW`, so everything is confirmable by `c_I` (the deployed constants still need 28 hours), and `intakeCutoff` computes `c_I`. It also owes the newest receipted ballot whose L1 reference fails (a reorganised block whose core the client cast again, when the board's copy is withheld). So at most `2 · Σ group_size_t` receipts per seat. The old "MAY skip a superseded ballot" rule is replaced. Residuals: the unbounded obligation becomes "bounded, not yet shown payable" (part 2), and a new, narrower one: a newest ballot that reached the trustees but not the board, with withheld board data, leaves the older selected ballot only its board-path receipts.
- [[ballot-validity]], Casting: step 5, the finished record goes to each qualified seat's intake.
- `packages/crypto`: `intakeBallot(election, keys, record, ciphertext)` (decodes under the election's pinned version, then `admitForIntake`, the admission checks with `share-hash` inserted, then `openShares` and the receipt), returning the ranking fields too; `intake` is renamed `intakeShares` and documented as the share half with no membership check, used only by simulations; `owedReceipts(view, receipts, l1, window)`, with `receipts` every ballot hash the node receipted, never reduced when a copy is shown absent; it throws while any L1 reference is pending. `packages/sdk`'s simulation calls `intakeShares` (its ballots carry no membership proofs, `SIMULATION_STUBS`).
- `docs/spec/vectors/intake.json` from `packages/crypto/scripts/intake-vectors.py`, an independent Python implementation reusing the ballot, ballot-v2, share-encryption and share-receipt generators, with membership proofs and pairing verdicts from snarkjs 0.7.5 over Semaphore 4.14.3's depth-32 artifacts (sha256-checked by `ballot-proofs.mjs`).
- T-25 and T-52 history.

## Tested (part 1)

- Properties: any single-byte change to an accepted record is refused; `owedReceipts` owes at most two receipted ballots per tier and nullifier, independent of the view's order, and agrees with a direct reading of the rule over views whose casts often share a ballot hash (`FC_NUM_RUNS`).
- `owedReceipts` units: the newest receipted ballot only; the newest receipted ballot whose block was reorganised away when the board's copy is withheld (from `claude-review` on #171); a receipt for a ballot hash covering its core cast again under another block after the first block failed the L1 check; one per tier and nullifier; nothing on a tie; nothing when a ballot it didn't receipt supersedes; a board copy of a receipted ballot is the same ballot; ballots with an unadmitted L1 reference neither count nor supersede; it throws while L1 hasn't passed close, and when one message names two ballot hashes; an accepted vector intake feeds it.
- The share half: `share-receipt.json` unchanged, through `intakeShares`. Crypto and sdk suites pass; `vp check` and `vp run -r check` clean.

## Known-weak (part 1)

- The node's view keeps a receipted ballot it can't show absent, so with withheld board data a newest ballot that never reached the board leaves the older selected ballot only its board-path receipts (and the client's copies); It MUST be closed (P4-3's data availability) or accepted by the owner before any election registry is deployed, and is in STATUS (Known-weak). The view ignores the close rule (5.5) until P1-18 specifies it.

## Independent review (part 1)

In-session subagent with `.github/review/crypto-review.md`, on the complete diff:

The node now owes the selected ballot's receipt if it receipted its ballot hash under any L1 reference, counted before the L1 filter; spec, a unit test and a model property cover it.
- **Non-blocking, applied:** the new residual (a newest ballot that never reached the board) is a trade against main's unbounded obligation; it now MUST be closed (P4-3) or accepted by the owner before any registry is deployed, and is in STATUS Known-weak.
- **Non-blocking, superseded:** the subagent suggested the node decide again whenever its view changes; `claude-review` on #171 showed that the union of decisions is unbounded (below), so the node decides once instead.
- **Non-blocking, carried to part 2:** the bound is the electorate, which Tier 0 identities can inflate; part 2's capacity check runs against each definition's actual counts.
- **Nit, left:** `intakeShares` is exported; its name and documentation say it checks no membership and that a node never receipts with it, and the sdk simulation needs it until P1-21 part 2 brings membership proofs.
- **From `claude-review` on #171, blocking, fixed:** with board data withheld the node may hold only its own copy of a ballot whose block was reorganised away, which fails the L1 check, so it owed nothing for the copy cast again that the delivery check selects. A node now also owes, per tier and nullifier, the receipt of its newest receipted ballot whose L1 reference isn't admitted, so the bound is two per member of each tier.
- **From `claude-review` on #171, blocking, fixed:** owing the union of every decision as the view changed broke the bound (an operator releasing data, or a member getting their own ballots recorded one at a time, flips the selection). The node now decides once, over the view it then holds, and refuses intake after it.
- **From `claude-review` on #171, blocking, fixed:** a decision point of each node's choosing let an honest node close intake minutes after the close, so a client retrying after a trustee outage at the close was left to post or leave the ballot undelivered, against the delivery window's stated purpose. - **From `claude-review` on #171, blocking, fixed:** "receipted" was read from the view's copies, so once the node showed a receipted copy absent (its block reorganised away, the full board published), the copy cast again under the same ballot hash lost its receipt and nothing was owed. `owedReceipts` now takes the node's receipts as ballot hashes, never reduced by absence; the spec says so, with a test.

## Part 2: the complaint scope and the forced path's capacity (#276)

Once P1-18 had merged, the board already took receipts in batches (`submitReceipts`) and had the posting and complaint calls, so no contract change was needed. What was missing was a bound on complaints and any check that a node can pay its bounded obligation.

- [[delivery]], What a node owes: **the complaint scope**. At `c_I`, over the same view, the node fixes for each (`tier`, `ν`) of any view ballot the hash the selection picks and the newest one whose L1 reference isn't admitted. It owes one complaint per hash in the scope that has a passing posting in time whose shares fail, by `c_K`: at most two per (`tier`, `ν`). It SHOULD also complain, budget allowing, about failing postings outside the scope whose ballots it can't show absent.
- [[delivery]]: **the view applies the close rule** (5.5) to each copy the node holds from the board or the contract, by its entry (`ballotWindow`). A late ballot can't displace the counted one, and the newest-ballot residual's close-rule clause is gone.
- [[delivery]], **Capacity** (new):
  - The portal's metering is read from Base's and Base Sepolia's `SystemConfig` on L1.
  - The check uses the sustainable target of 2,000,000 deposit gas per L1 block and one L1 block per 13 seconds.
  - The pinned call figures are 17,000,000 gas for 256 receipts and 150,000 for a complaint, with intrinsic gas and `P256VERIFY`.
  - Each election's receipts and complaints are spread evenly over their intervals. A set fits if the summed rate stays within the target.
  - Caps with the deployed windows: 1,280 members with 3 seats at `R` of one hour, 28,307 at 21 hours.
  - An approved election stops counting once finalized L2 shows it can't be registered.
- [[ceremony]], Stub checks: **step 4**, which `apps/trustee-node` runs.
  - `served/` records are written before signing.
  - Approvals run one at a time.
  - `neverRegistered` releases an election only on proof.
  - `SeatStore.list` is new.
  - `RELEASE_WINDOWS` pins `W_C` and `F` at 13 hours and `R` at one hour.
- `packages/crypto`: `complaintScope`, `FORCED_PATH`, `forcedPathDemand`, `forcedPathFits`, `forcedPathMembersLimit`, `definitionMembers` (refuses rolling and empty electorates), `ViewWindow`; `ViewBallot.entry` is required.
- `docs/spec/vectors/delivery-obligation.json` from `packages/crypto/scripts/delivery-obligation-vectors.py`, an independent Python model. It includes the cross-language `owedReceipts` vectors part 1b deferred.
- `packages/contracts`: `test_ForcedPathCallGas` binds the call figures; the board's precompile run sets `EXPECT_P256VERIFY`.
- [[contracts]], Board; T-25, T-52 and T-54 history; STATUS Known-weak (the cap, unregistered stubs holding capacity, the complaint-scope residual); new queue item [[P1-12d]].

- **Contracts:** under `osaka`, a 256-receipt call and a complaint call cost at most their figures and within 10% and 20% of them. A mutation of the receipt bound fails the test. Both EVMs pass.
- **Suites:** crypto (`FC_NUM_RUNS=1000`), trustee-node, verifier and sdk pass. `vp check` and `vp run -r check` are clean.

## Known-weak (part 2)

- **The cap is low.** At about 63,000 gas a receipt, an election can have at most 1,280 members with 3 seats at `R` of one hour, or about 28,000 at 21 hours, at the price of an intake cutoff 20 hours earlier. [[P1-12d]] raises the cap by over an order of magnitude. A national electorate needs more than any record per receipt on L1.
- **Approved stubs nobody registers hold capacity until their `opens_at`.** Whoever can get ceremonies run can make honest seats refuse real elections closing at chosen times. An admission rule for stubs is [[P2-13]]'s. No deployment supplies `neverRegistered` yet, so nothing is released.
- **The target is shared.** Other depositors (voters' forced ballots and postings included), other panels' elections, close statements and complaints beyond the scope aren't reserved for. Base's multisig can change the metering. A full receipt call takes 85% of a block's deposit limit.
- **Withheld board data can keep a counted ballot's failing posting out of the complaint scope.** P4-3's data availability closes this.
- **The node runs check 4 only for definition version 1.** It's the only version the node reads. A release reading later versions MUST count author seats and members the same way. A node must run one process per store.
- **The call figures assume `P256VERIFY`.** The measurement uses EIP-7951's 6,900-gas price.
