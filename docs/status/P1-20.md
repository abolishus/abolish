## Scope

Reference election fixture (`vp run reference-election`), CLI only: ceremony → tiers (stubbed until Phase 3, with the stubs clearly marked) → cast/challenge/re-vote → direct submit → close → threshold decrypt → tally → anchor (Anvil) → wipe + rebuild → independent verification offline. Makes the `reference-election` check real. The same PR sets `EXPECT_FIXTURE: "true"` in `.github/workflows/reference-election.yml` (a `ci:` change), so removing the script later fails the check. The workflow must call a fixed, owner-reviewed entry point rather than whatever the root script says, independently run `packages/verifier` over `reference-election-output/`, and require the transcript to cover every stage the brief lists.

## Plan

The fixture grows with the items it proves, so it is built in parts:

1. **The runner** (done, #129): `apps/reference-election` and the root `reference-election` script, with stage 1 (the key ceremony), stage 7 in part (anchoring on Anvil) and stage 9 in part (the verifier in a process of its own over the output bundle). `stages.json` lists every stage with its coverage, so a run never reads as the whole proof.
2. **Each later stage** with the item that builds it (stages.ts names them): the ballot record and casting (P1-12, P1-13), the tally (P1-15, once there are ballots), direct submit (P1-18 part 4, P4-2), registration and groups (P2-5, P2-6, P3-2 to P3-4), the wipe and rebuild (P2-1, P4-3) and verification from chain and IPFS alone (P4-6). Every feature PR extends the fixture (AGENTS.md).
3. **`ci:` arming** (owner review): `EXPECT_FIXTURE: "true"` (done, #134), so removing the root script fails the check. Still to come: a fixed entry point in the workflow rather than the root script, the verifier run independently over `reference-election-output/`, and `stages.json` required to show every stage `covered`. These wait until every stage is covered, since the check would fail before.

- Stage 1: a 4-of-7 panel with fresh identity keys runs the four ceremony rounds through `@abolishus/crypto`, every seat taking part ([[0006-trustees]] rule 7); the definition (plurality, three options, the profile with board-entry version 4) binds the transcript, which binds its stub hash (T-37, T-34). The display text is real and committed to, though nothing shows it yet.
- Stage 7, in part: `BoardAnchor` from forge's build on Anvil with a 1-hour period and the 12-hour deadline; the ceremony's segment and the seal anchored inside their windows from a stub authority; a finalized header rebuilt to RLP and checked against its block hash, and `eth_getProof` nodes for the lowest-segment word and every segment's word.
- Stage 9, in part: `packages/verifier` from its built package, in its own process with an empty environment, over the bundle directory alone (T-36). 3.2, 4.1 and 4.2 must pass, no check may fail, and the verdict must be `unverifiable` (every input is a local file), with the matching exit code.

- Every stub is named in `STUBS` and written to `stages.json`: placeholder L2 addresses, a placeholder Tier 0 group and membership key hash, the panel as a local file, the authority, and a seal one segment after the ceremony's.

## Known-weak (part 1)

- Stages 2 to 6 and 8 aren't covered, and 1, 7 and 9 only in part: the check proves a ceremony, its board and its anchors, not an election. `stages.json` says so on every run.
- The check runs whatever the root script says and doesn't require every stage covered: the remaining `ci:` steps (above) wait for full coverage. `EXPECT_FIXTURE` is set since #134, so removing the script fails it.
- The verifier's verdict is `unverifiable` by design: the definition, panel, header, clock and first segment are local files, and 3.1 (the trustee registry on L2) isn't implemented. The run checks that the rows that can pass do.
- The seal is chosen by the fixture (the segment after the ceremony's), not computed from the definition, since no post-close window is fixed yet.
- The clock starts one period before Anvil's genesis time, and the fixture moves Anvil's time forward to anchor; nothing runs in real time.
