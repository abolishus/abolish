## Scope

Reference election fixture (`vp run reference-election`), CLI only: ceremony → tiers (stubbed until Phase 3, with the stubs clearly marked) → cast/challenge/re-vote → direct submit → close → threshold decrypt → tally → anchor (Anvil) → wipe + rebuild → independent verification offline. Makes the `reference-election` check real. The same PR sets `EXPECT_FIXTURE: "true"` in `.github/workflows/reference-election.yml` (a `ci:` change), so removing the script later fails the check. The workflow must call a fixed, owner-reviewed entry point rather than whatever the root script says, independently run `packages/verifier` over `reference-election-output/`, and require the transcript to cover every stage the brief lists.

## Plan

The fixture grows with the items it proves, so it is built in parts:

1. **The runner** (done, #129): `apps/reference-election` and the root `reference-election` script, with stage 1 (the key ceremony), stage 7 in part (anchoring on Anvil) and stage 9 in part (the verifier in a process of its own over the output bundle). `stages.json` lists every stage with its coverage, so a run never reads as the whole proof.
2. **Each later stage** with the item that builds it. Part 2a (#260) is the L2 side of stage 1. Part 2b, casting (stage 4), needs real membership proofs first: the API's admission (P2-3 part 2d) and the verifier's (5.1 to 5.3) reject every ballot without one, and nothing in the workspace proves membership yet (P2-8, P5-4 own the client prover). Otherwise (stages.ts names them): the ballot record and casting (P1-12, P1-13), the tally (P1-15, once there are ballots), direct submit (P1-18 part 4, P4-2), registration and groups (P2-5, P2-6, P3-2 to P3-4), the wipe and rebuild (P2-1, P4-3) and verification from chain and IPFS alone (P4-6). Every feature PR extends the fixture (AGENTS.md).
3. **`ci:` arming** (owner review): `EXPECT_FIXTURE: "true"` (done, #134), so removing the root script fails the check. Still to come: a fixed entry point in the workflow rather than the root script, the verifier run independently over `reference-election-output/`, and `stages.json` required to show every stage `covered`. These wait until every stage is covered, since the check would fail before.

## What was built (part 2b-1)

- `apps/reference-election/src/casting.ts`: four Tier 0 voters with fresh identity secrets (`newIdentitySecret`); the definition's one group is their identity commitments, its root their tier tree (`tierTreeRoot`) and its size 4, so every definition the run writes names a real root rather than the placeholder 1. ## What was built (part 2c)

- `apps/reference-election/src/tally.ts`: the fixture runs every trustee node through `@abolishus/crypto`'s production entry points. `intake` is each seat's `intakeBallot` of a cast ballot with its own ciphertext (the admission checks, decryption, the signed receipt), refusing to go on if a seat refuses an honest ballot; its share receipts (`0x000b`) are the ballot's delivery records. `tallyOpening` is the cell's tally over its counted ballots: each seat sums its shares (`sumShares`), seals its sums to seat 1 in a summed-share message under seat 1's registered KEM key (`sealSummedShares`), seat 1 opens each against its own aggregate (`openSummedShares`), combines (`openCell`) and signs the opening (`signTallyOpening`, tally-opening version 1). `destructionStatements` is each seat's signed statement (`0x000f`). The ceremony now keeps each seat's per-election secrets (`Ceremony.secrets`) for this.
- The run: in the honest election and the poll of questions, every seat takes every cast ballot in, and the share receipts are boarded on the board path after the window's ballots, in the same segment, so the ballots keep their indices (the poll's operator receipts name them). The board gets two more segments: the segment after the window's (`period(closes_at) + 1`, the floor of the counted extent's last segment) stays empty and is anchored; each election's one cell is tallied over every voter's last ballot and its opening boarded in the next segment; once that is anchored, every seat's destruction statement is boarded in the seal's, the one after (tally.md, Destruction, When). The client's receipt check at cast takes the window's segment and the one after.
- The verifier must now judge every tallied election's format-5 bundle (`checkTallied`): 5.8, 5.9, 6.1, 7.1 to 7.3 and 8.5 pass, the one cell reports the counted ballots and the counts the votes cast add up to (the honest election's `1, 0, 1`, the poll's 11 options), every seat is `destroyed`, 4 ballots are admitted and entries 1, 3 and 4 selected. The honest election's format-5 bundle was judged by nothing before; the poll's pinned 7.2 and 8.5 as failing. The community node must still report the same checks as the verifier on each (stage 9).
- `stages.json`: stage 6 is `partial`, stage 4's note says the seats take the ballots in, stage 7's lists the new segments. `STUBS` says the seats' duties are the fixture's, not `apps/trustee-node`'s, and that the seal is four segments after the ceremony's rather than derived from tally.md's windows.

## What was built (part 2b-2a)

- `apps/reference-election/src/seats.ts`: one `apps/trustee-node` node per seat, each a `CeremonySeat` and an `IntakeSeat` over a `FileStore` of its own in a temporary directory outside the run's output (mode 0700, removed however the run ends). The deployment's side: `electorateCheck` (the stub's one Tier 0 tier against the fixture's voters' tree), `registrationCheck` in `l2.ts` (the election registry's `definitionHashOf` and the trustee registry's `keySetOf` at Anvil's latest L2 block, for the definitions the fixture registered) and the nodes' clock, the L1 time the run sets.

Then a control: with the clock at the delivery deadline `t_D`, past the intake cutoff, every node must refuse the last ballot again (`intake-closed`, T-54).
- `election.ts`: `singleStub` and `boundDefinition` split out of `runCeremony`, and `SeatKeys` (index, KEM secret, signing secret), the per-election keys the tally and destruction statements read, from either path. `STUBS.seats` says what the nodes don't do yet; `STUBS.casting` no longer claims the seats are the fixture's.

The operator's receipts are still signed over the fixture's copy, which the answers have just matched.
- The poll is cast before the honest election, since the honest election's cutoff control moves the L1 clock past the close and the API would refuse the poll's ballots after it. The never-boarded ballot behind the `dropped` receipt is never submitted.
- `STUBS.casting` and stage 4's note no longer say the poll bypasses the API.
