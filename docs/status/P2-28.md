## Scope

Making the everyday app feel like an app, and fast, everywhere.

- An installable web app (manifest, icons, offline shell) for `apps/web`; the ballot client's own install stays under its CSP and entry-point rules ([[0020-entry-points]]).
- Targets, measured on staging and recorded here: the first answer in three taps ([[first-answer]]); a poll open within a minute of submitting; proving on a mid-range phone ([[P2-21]]); page loads on a slow phone connection.
- An accessibility audit of every everyday screen against WCAG 2.2 AA, and translations for at least one language beside English, end to end.

Rules for every part, as [[P2-19]]'s: everyday register by default ([[language]]); no hard-coded strings (`messages.ts`); CSP-safe (no inline `style`); server-rendered where the page is the website's; a fixed analytics template per route, never a path or poll ID (T-67); each component a story with a play function passing axe at desktop width and 360px; SSR and serve tests per route; the mockup's story deleted in the PR whose page matches it. Privacy holds everywhere: nothing an account does on the website (following, reacting, sharing, notifications) is ever stored, logged or keyed with a ballot, nullifier, receipt or the fact of having answered, and the T-10 no-join tests cover every new table, queue and log line ([[PROJECT_BRIEF]], Identity).

The worker gets `workerHeaders` (`default-src 'none'; connect-src 'self'`, `no-cache`), the pages' policy gains `worker-src 'self'`, and the front classes both paths as `offline`: no cookie, never a page view (T-67). Frames, posts, other origins and every other file are left to the browser. The build no longer inlines a font under 4 KiB as a `data:` URL, which `font-src 'self'` refused on every page. Tested in `tests/offline.test.ts` (the served text run in a context of its own against a stand-in scope: what install keeps and refuses, activation's clean-up, pass-through, the offline page on failure, what it leaves alone, and a fast-check property that no request, online or not, stores anything), `tests/security.test.ts`, `tests/serve.test.ts` (class, cookie, not page views), `tests/ssr.test.ts` (the built page and worker: headers, no script, the empty "Try again" link, the worker's configuration matching the page's hash, the built worker run in a bare context, `worker-src` on pages), `tests/offline.e2e.ts` (Chromium against the built site behind the real front: it installs and keeps only those files; with the server gone a page shows the offline page with the site's font and no policy violation; "Try again" opens the page once the server is back) and the stories `OfflinePage` and `OfflineDark` in `src/components/site-layout.stories.tsx`.
