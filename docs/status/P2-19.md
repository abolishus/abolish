## Scope

Turn the page mockups in `apps/web/src/mockups/` (Storybook `Mockups/Web/…`) into the real `apps/web` routes, on the data that exists today. The mockups are the reference for layout, copy and motion; [[language]] is binding (two registers, everyday by default; square corners; motion only reveals real data; no motion that loops or counts). Nothing here waits on protocol work: every part uses routes the API already serves, and leaves out what it can't show yet instead of faking it.

Rules for every part:

- **No hard-coded strings.** The mockups hard-code English; the real components take translated text from `apps/web/src/messages.ts` (`useTranslate`), as the existing components do.
- **CSP-safe.** The page's CSP has `style-src 'self'`, which blocks inline `style` attributes. Kit components that set one (`TallyBars`' bar width; check `BoardMap`, `InclusionPath`, `QrCode`, share parts and the mockup helpers too) must draw the same thing another way before a real page uses them: SVG geometry attributes, `<meter>`/`<progress>`, or classes. Widening `style-src` is a `security.ts` change for the owner, not a fix.
- **Server-rendered.** Nothing reads `window` or `document` during render; scroll hooks and the motion utilities already render the final state on the server.
- **Analytics stay fixed.** Every new route gets a template in `src/analytics.ts` (`PAGES`) and its test; no path or poll ID is ever kept (T-67).
- **Tested like the kit.** Each new component has a story with a play function that passes axe at desktop width and 360px (`test:storybook` runs both); SSR and serve tests cover each route. A mockup stays in Storybook as the reference until its real page matches it; then its story is deleted in the same PR.

9. **The board page's consistency checks** (done in #775). `/polls/:id/board` asks `GET /board/proofs/consistency` for the proofs between each pair of neighbouring checkpoints its anchors show, and between the head and the latest checkpoint (the smaller tree first, since either may be read first), all at once, at most 6 a page; equal sizes need no proof (the roots must be equal), and a head read empty beside a checkpoint fails without one, since a board that held entries never reads empty again. `oneHistory` (`src/board.ts`) checks each with `@abolishus/crypto`'s `verifyConsistency` over `BOARD_TREE`, and a proof the server refuses as out of range counts as failed: it claimed a tree its board doesn't hold. Each verdict is a line beside what it checked: under the head ("one history" or not) and under each checkpoint ("Extends the checkpoint after period N" or "Doesn't extend"), each saying it was checked by the server's proof or by the same root at the same size; a failure says our server couldn't prove it and to keep both, as evidence of tampering, and the page still shows everything else (T-24). The proofs name only checkpoint and head sizes every visitor is shown, so they tell our server nothing a visit didn't (T-10). The anchors' claim now says the page checks these proofs, and still leaves anchoring and the entries to the verifier. An entry's own page ("your place on the board") stays out of the website: asking our server for one entry's proof tells it which entry is the visitor's (T-10), so it belongs to the ballot client and the verifier, which hold the receipt.
