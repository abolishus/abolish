# T-24: Equivocation (split view)

- Area: Integrity and verifiability (G-7, G-8, G-9)
- Adversary: A-2, A-1
- Status: **Planned.** Residual: before the next anchor, a voter checking via our API alone can be shown a fork. Receipts must be re-checked after anchoring.

## Threat

The server shows different boards to different viewers, for example omitting one voter's ballot only from the copy that voter sees.

## Mitigation

Receipts are checked against L1-anchored checkpoints, which everyone sees identically: an inclusion proof shows the entry is in the anchored tree, and a consistency proof shows the anchored tree extends the one the voter was shown when casting (RFC 9162; [[board]]; P1-13, P1-16, P4-1); community nodes (P4-5) and the verifier read from chain + IPFS, not our API.

Index: [[THREAT_MODEL]].
