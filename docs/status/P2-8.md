# P2-8: `apps/ballot`

- State: in progress (part 1 merged in #81 and #83; its bundle and CSP policy check merged in #82; part 2, the Web Worker and the election screens, is next)

## Scope

`apps/ballot`: a static, reproducible build; encryption and proving in a Web Worker; strict CSP; a no-analytics bundle test.

## Part 1: the shell, its CSP and the bundle tests

- `apps/ballot`: a Vite build of React and `@abolishus/ui` into `dist/` (declared for `repro-build`), with relative URLs so one build serves at any path, no module-preload polyfill, no inlined assets and no source maps, and React's licence beside it in `third-party-licenses.md` and IBM Plex's OFL-1.1 in `font-licenses.txt`. One screen so far: what the client is, with its strings in an i18n catalog.
- The CSP is a `<meta>` tag ahead of everything that loads, so it travels with the hash-addressed bytes: `default-src 'none'`; scripts, styles, fonts and images from `'self'`; `connect-src 'none'` until part 2 fetches an election; Trusted Types with no policy; `base-uri` and `form-action 'none'` (T-43).
- An origin of its own: on a path gateway (`/ipfs/<cid>/`, `/ipns/<name>/`) every CID shares one origin, so another CID's page could open or frame the client, read its document and replace `crypto.getRandomValues`, learning the vote and its randomness. The client shows a refusal there instead of running (`src/origin.ts`). It runs from our domains, `abolishus.eth` or a subdomain gateway (T-43, T-41).
- No dev-server script: Vite's development client needs inline styles and a WebSocket the CSP refuses, and a second, relaxed policy could leak into a release. Screens are worked on in Storybook.
- No ADR: nothing here is a one-way door. The CSP can only be tightened or widened by later releases, each pinned by the tests.

Tested:

- `test` (`tests/bundle.test.ts`) builds the app and checks the output: every bundled module is from `react`, `react-dom`, `scheduler`, this app or `@abolishus/ui`; only the page, scripts, styles and IBM Plex fonts are emitted; no analytics, tracking or error-reporting SDK marker (T-67, the brief's bundle test); no URL but a short list of inert strings; no `eval`, `new Function` or string timers; `index.html` has exactly the pinned CSP before the first load, no inline script, style or event handler, and only relative `./assets/` references. Checked by mutation: a `posthog` string, `'unsafe-inline'` in `script-src`, an inline `<script>` and a `fetch` to another origin each fail a test.
- `test:e2e` (`tests/page.e2e.ts`) serves the production build and loads it in headless Chromium: it renders with its stylesheet and self-hosted serif, with no CSP violation, console error or request to another origin; the browser refuses script text, a script URL, `innerHTML`, `insertAdjacentHTML` and an event-handler attribute (Trusted Types), a `fetch` to another origin and to its own, and an image from another origin; served under `/ipfs/<cid>/` it shows the refusal. `test` also checks the path-gateway rule.
- `test:storybook`: the screen's story in both themes, its play function and axe (WCAG 2.2 AA).
- By hand: two builds, one under another timezone, gave byte-identical `dist/` trees.

Known-weak:

- **The build can steer what the CI check sees.** #82 judges the output of a build that runs PR-controlled code, including any `apps/ballot/vite.config.*` (a `.js` or `.mjs` file takes precedence over `.ts`), any `postcss.config.*` from `apps/ballot` up to the root, and Tailwind `@plugin`/`@config` code in any CSS the build loads. Any of it could tell when the check runs and emit clean output only then. Review of those files is the remaining gate (T-59); CODEOWNERS for them is the owner's call.
- **Framing isn't prevented.** A `<meta>` policy can't set `frame-ancestors`; whoever serves the client must send it as a header (P2-11, P4-3). An IPFS gateway may not, so a hostile page could frame the client from a gateway (T-43).
- **The path-gateway refusal only recognises the `/ipfs/` and `/ipns/` convention.** A host that serves many CIDs on one origin under other paths isn't detected, and the refusal doesn't stop a same-origin page from attacking the voter some other way; it only keeps the voter from voting there. Listing only dedicated origins (P4-4) is the real fix.
- **Navigation isn't covered by the CSP.** `connect-src 'none'` stops subresource requests, not a top-level navigation, `window.open`, a link or a WebRTC connection to an attacker's STUN or TURN server, so injected code could still leak data that way. Trusted Types and `script-src 'self'` are what keep injected code from running at all.
- **The e2e runs in Chromium only.** CI installs Firefox and WebKit too, but their Trusted Types support differs; a voter on a browser without Trusted Types keeps the rest of the policy.
- **No release record yet.** The build is reproducible, but nothing signs `dist/` or publishes its hash and IPFS CID; that comes with the client's release pipeline (T-41), and the verifier's 1.1 check needs it.
- **The analytics markers are a deny-list.** The real guards are the package and URL allow-lists and `connect-src 'none'`. Tracking code copied into workspace source under another name would pass the bundle tests; review, and the CSP once the client talks to the API, are what stop it.

## Part 1 follow-ups

From #81's `claude-review` (non-blocking):

- The path-gateway check decodes the path as a gateway would before comparing its first segment, so `/%69pfs/`, double encodings, `//ipfs/`, `/./ipfs/` and backslashes are refused; so is any path with a `..` segment after decoding (`/x/%2F..%2Fipfs/`, which nginx would resolve to `/ipfs/`), an undecodable path, and one still changing after four rounds. Tested with listed cases and a fast-check property over every percent-encoding of `ipfs` and `ipns`.
- The e2e closes each test's page, so a late event can't reach the next test.
- Part 2 was marked as waiting on #82 (merged), and the build-config residual is recorded here and in T-59, T-43 and T-67.
- The test of the four-round decoding cap now uses a truly nested encoding, so it exercises the cap rather than the undecodable branch (#83's review).
- `pnpm-lock.yaml` is regenerated: on `main` it still listed `shadcn` as a runtime dependency of `@abolishus/ui` after its manifest moved it to dev dependencies, so a frozen install failed.
