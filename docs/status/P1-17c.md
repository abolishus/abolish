## Scope

What P1-17 originally carried that [[0009-membership-proof]] no longer needs for membership, ready for the first custom Noir circuit (Tier 2 predicates, if [[P3-1]] needs one):

- the `packages/circuits` workspace (Noir 1.0.0-beta.22, bb 5.0.0-nightly.20260522) with `build`, `test` and `check` scripts, committed artifacts, and the test that every key and verifier is bb's zero-knowledge flavour (`circuits` skill);
- the in-circuit tag-to-field rule ([[domain-separation]], In-circuit hashes);
- the record packing rules ([[notation]], Noir circuits);
- Noir tests that consume the cross-language vectors in `docs/spec/vectors/`.

## Built

- [[domain-separation]], In-circuit hashes: `tag_field(tag) = int(H(DS("abolish/v1/circuit-tag", tag))) >> 8`, the tag as the first input of every in-circuit hash, a fixed number of inputs per tag, and the hash named in the tag's registry row. `abolish/v1/circuit-tag` is registered (T-30, T-31).
- [[notation]], Circuit-facing values: the packing of every type a circuit can take (field elements, integers, booleans and enums, `bytes[N]`, `bytes<M>` and `utf8<M>`, lists, records), with what the circuit constrains, so packing is injective on canonical values (T-31).
- `docs/spec/vectors/circuit.json`: every registered tag's field element and both byte packings at their boundaries, printed by `packages/crypto/scripts/circuit-vectors.py`, an independent Python implementation that reads the tags from the registry.
- `packages/crypto`: `circuitTagField` (only for a tag registered In-circuit, so no plain-hash tag gets a second layout; T-30), `packBytes`, `packBoundedBytes`, `PACK_CHUNK`, with vector tests and fast-check properties (round trip, injectivity of bounded packing, element counts and ranges).
- `packages/circuits`: the Nargo workspace and the `abolish` library (`pack_bytes`, `pack_bounded_bytes`), with Noir completeness and soundness tests; a vite-plus test that turns every packing vector into a Noir test (plus a non-zero-padding test per short bounded value) and runs `nargo test`; and source rules: nothing asks bb for a proof without zero knowledge, and every Noir dependency is a path inside the package.

## Known-weak

- **No circuit, so no artifacts yet.** Membership uses Semaphore's circuit ([[0009-membership-proof]]), and no custom circuit is specified, so a circuit here would be dead code. The first circuit brings the committed ACIR and verification keys (rebuilt and compared in CI), the test that each key and Solidity verifier is the zero-knowledge flavour, the noir_js/bb.js round trip (adding those two packages to the lockfile), gate-count snapshots, and the list and record packings in code. Until then the zero-knowledge rule is enforced only as a source scan.
- **The source scan is a tripwire.** It matches the spellings bb uses today for disabling zero knowledge; a renamed flag would pass it.
- **`tag_field` has 124-bit collision resistance,** as Semaphore's `F`: 248 bits of SHA-256. Enough for a fixed, public set of tags, which an attacker can't choose.
- **`std::static_assert` in `pack_bytes` is untested as a failure**: Noir can't test a compile error, so a wrong output length is caught only when a circuit using it is compiled.

## Notes

- Several files still name P1-17 as the Noir consumer of the vectors or the item the toolchain check must precede: [[0001-canonical-encoding]] (Consequences), [[P1-10]] (Known-weak) and [[P1-16b]]. They now mean this item; each is updated when its owner next touches it.
- The `circuits` skill's nullifier rule (`H(tag, identity_secret, poll_scope)`, with every in-circuit hash tagged) predates [[0009-membership-proof]]. Membership nullifiers follow [[membership]] instead: the tag is on the scope, outside Semaphore's circuit, and adding one inside would give a voter a second nullifier derivation. The skill is owner-reviewed (`.claude/`), so the owner updates it; until then [[membership]] governs membership nullifiers, and the skill's rule applies to this item's own circuits.
- Any circuit here must meet [[0002-everlasting-privacy]]'s zero-knowledge requirement, which [[0009-membership-proof]] found bb's UltraHonk can't yet be shown to meet statistically.
- The circuits skill says `build` runs `nargo compile` and `bb write_vk`; with no circuit there is nothing to compile, so `build` is `nargo check --workspace` (declared outputs: none).
