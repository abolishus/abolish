# T-42: Compromised voter device changes the vote

- Area: Client integrity and cast as intended (G-6, G-13)
- Adversary: A-3
- Status: **Partial.** Malware that controls the device can also fake the challenge check. Checking must be possible on a second device or by an independent verifier the voter chooses; that flow is designed in P1-13. Under P1-3 (option B), malware can also post an invalid share on an honest voter's last ballot; the complaint can arrive after close, so the voter can't re-vote, and the vote is nullified.

## Threat

Malware alters the plaintext before encryption.

## Mitigation

Benaloh challenge/spoil: the voter can challenge any ballot and check the opening (P1-13).

## History

- 2026-10-11 (P1-13): a ballot's L1 block publishes when it was made, so P1-13's challenge part must keep challenged entries from being matched to the cast ballot by time ([[revoting]], Residuals); the receipt check must show admission and selection, since the ranking fields escape Benaloh's audit.
- 2026-10-12 (P1-13 part 3a, [[0021-challenged-ballots]]): a challenged ballot is never boarded on its own. The casting device commits to the core by its tracking code (the full core hash, as a QR code) before the cast-or-challenge choice; a second device records it, checks a challenge's opening against it, and later finds the cast ballot by it. So challenging leaves no board entry near the cast ballot to match by time. The check resists malware only on a second device or checker the voter chooses.
