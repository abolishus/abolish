## Scope

Every way a poll travels, as [[sharing]] designs them: the share sheet, link previews (done in [[P2-18]]), QR codes, the printable flyer, the embed, native share on phones, a result card once results exist, and the voter's own "I answered" card. From `share-*.tsx` in `apps/web/src/mockups/`.

- The voter's own card is made on their device and shared only by them; the server never learns that it was made or what it says.
- Every surface carries the poll's short code and seal, and nothing that identifies a voter.

Rules for every part, as [[P2-19]]'s: everyday register by default ([[language]]); no hard-coded strings (`messages.ts`); CSP-safe (no inline `style`); server-rendered where the page is the website's; a fixed analytics template per route, never a path or poll ID (T-67); each component a story with a play function passing axe at desktop width and 360px; SSR and serve tests per route; the mockup's story deleted in the PR whose page matches it. Privacy holds everywhere: nothing an account does on the website (following, reacting, sharing, notifications) is ever stored, logged or keyed with a ballot, nullifier, receipt or the fact of having answered, and the T-10 no-join tests cover every new table, queue and log line ([[PROJECT_BRIEF]], Identity).

## Part 1a: the share sheet on the poll page

"Share this poll" in the poll page's Answering section opens a dialog ([[sharing]], Share sheet): the poll's short link (`<origin>/p/<code>`, the same for everyone) with **Copy link** and a status line, **Share…** where the browser has the Web Share API (given `{ title, url }` and nothing else), and otherwise one line saying so with **Email the link** (`mailto:` with the title as subject). The dialog's description says sharing sends the link, never the sharer's answer. The copy and the share happen in the browser: nothing reaches our servers or analytics (T-10, T-67), and the route's analytics template is unchanged.

- Offered only for a poll with a short link that isn't hidden: a hidden poll's text was withheld by moderation, so we don't offer to spread it; a delisted one is still reachable by link and keeps the sheet.
- The title is the link preview's (`Poll <code>` until the API serves question text, [[P4-3]]).
- Tested: `poll-share.stories.tsx` (copy, failed copy, the share menu's exact data, the email fallback, dark; axe at desktop and 360px), `poll-summary.stories.tsx` and `tests/ssr.test.ts` (the trigger is server-rendered for a coded poll, absent without a code and for a hidden poll).
- Known-weak: the trigger needs the page's script; without it the short link is still in the page's evidence. The fallback line ("open abolish.ch or abolishus.eth and enter the code") is left out until the ballot client takes a code. The ballot client's "Ask others" on the Done screen waits on [[P2-20]]'s Done screen. The mockup's story (`share-sheet.stories.tsx`) stays until the QR, flyer and embed rows land.

## Part 1b: the QR code in the share sheet

The encoder [[sharing]] recommends already sits in `packages/ui` (`src/lib/qr.ts`, any version, levels L to H, tested by `tests/qr.test.ts` against the standard's published tables and an independent reader), with its `QrCode` component, so this part adds no dependency. Below the share rows, **Show a QR code** expands inline (`aria-expanded`) to the poll's short link as a QR code at level M, drawn in the browser: the link upper-cased (`HTTPS://ABOLISH.US/P/<CODE>`), which alphanumeric mode keeps at version 2, the coarsest grid; the router already matches `/P/` and codes are case-insensitive ([[sharing]], Short links). Dark modules on a white ground in both themes. It holds the same link as everything else in the sheet, so it says nothing about who showed it (T-10); nothing reaches our servers or analytics (T-67).

- Tested: `poll-share.stories.tsx` (`QR code`: collapsed by default with no image, the image's name, version 2's 33-module view box proving the upper-case alphanumeric form, collapsing again; `QR code, dark`: the light ground; axe at desktop and 360px).
- Known-weak: the code is drawn only once the sheet opens in the browser, so it needs the page's script, like the sheet. The note doesn't yet send people to a flyer for print; that row comes with part 2. The mockup's story stays until the flyer and embed rows land.

## Part 2: the flyer

`/p/<code>/flyer` ([[sharing]], Printable flyer), a page of its own beside `/p/<code>` (which only redirects), reached from **Print a flyer** in the share sheet. It resolves the code as `/p/<code>` does, then loads the poll page's data and prints only the code that page would print (T-34): a code that isn't the poll's is the site's 404, quoting nothing. A hidden poll gets a notice instead of a sheet, as it gets no share sheet; a delisted one keeps its flyer.

The sheet: an emerald band, "A poll on abolish.us" and the poll's seal, the link preview's headline (`Poll <code>` until the API serves question text, [[P4-3]]) and "N short questions, answered together." for several, the short link as a QR code at level Q (the upper-case form, so version 2 for `HTTPS://ABOLISH.US/P/<CODE>`), "Scan to answer", the link to type, when it opens and closes (UTC, as on the board), "How to answer", "Anyone can check the count" with the launch line (During launch, Abolish alone holds the key for this poll), "Non-binding, run by citizens." and seven tear-off tabs with the link. A closed poll's sheet says "Scan to see the poll" and that it no longer takes answers. Nothing about answers: no count, no lead.

- **Paper and ink** are links (`?paper=letter|a4&ink=color|mono`), so they work without script; anything else falls back to the defaults. US Letter by default, since abolish.us starts in the US ([[sharing]] open question 7, decided here); A4 is one link away. Black and white drops the band and the emerald frame.
- **Print:** the sheet is drawn in container units, so it is one drawing at any width, from a phone to the paper. It names an `@page` (`flyer-a4`, `flyer-letter` in `src/styles.css`, since the CSP allows no inline style) with no margin, and printing a page that holds a sheet hides everything else and the sheet's ancestors' frames, so it prints edge to edge on one page. **Print this flyer** calls the browser's print; without script, the browser's own Print does the same.
- The page and its QR code are server-rendered; the page sets `noindex`. Page views count `/p/:code/flyer`, never the code, paper or ink (T-67); the API is asked nothing of the visitor's (T-10).
- Tested: `poll-flyer.stories.tsx` (US Letter, A4, black and white, a dark page with a light sheet, not open yet, closed, several questions: the headline, the QR code's version-2 view box at level Q, the link, the closing time, the launch line, seven tabs with the link, no count or percentage, the choice links; axe at desktop and 360px), `poll-share.stories.tsx` (the row's link), `tests/ssr.test.ts` (security headers, the default sheet, A4 and black and white by link, a bad choice falling back, an upper-case code printing the canonical one, a hidden poll's notice, four kinds of code not found, nothing of the visitor's forwarded), `tests/analytics.test.ts` and `tests/serve.test.ts` (the template). Printed to PDF in Chromium on both papers while building: one page each, edge to edge.
- The mockup's flyer (`share-flyer.tsx` and its story) is deleted, as this page matches it. `share-sheet.stories.tsx` stays until the embed row lands.
- Known-weak: no question text, place or asker yet (the API doesn't serve them, [[P4-3]]), so the flyer names the poll by its code. The fallback line ("open abolish.ch or abolishus.eth and enter the code") is left out until the ballot client takes a code, as in the share sheet. Browsers' own print headers and footers can't be turned off from the page; the page says to turn them off. No translations of the flyer yet (one locale).

## Part 3: the embed

`/embed/p/<code>?theme=light|dark` ([[sharing]], Embed and The embed decision): a card other sites frame. It resolves the code as `/p/<code>` does and loads the poll as its page does, which must print the same code (T-34), then checks the poll's display text as the stream checks a card's. It is rendered by a server handler as static HTML (`renderToStaticMarkup`), never through the router's document, so it carries no script of ours, not even the router's.

- **The card:** the seal and "A poll on abolish.us" (with the question count for several), the poll's own words in their language and direction (the link preview's headline while none can be shown), then, for an open poll on a deployment with a ballot client, each answer of the first question as a link into the ballot client with the poll and the pick in the fragment ([[first-answer]]; T-10, T-11), the closing time, **Answer on Abolish** ("Answer N questions on Abolish"), "Answers are taken only on Abolish, never in this card." and the short link. A poll not yet open, closed, without text or without a ballot client gets **See the poll on abolish.us** instead of answers. Every link opens a new tab. No form, input or button, and nothing about answers (results come with [[P2-25]]). A hidden poll's embed shows a notice and a link to its page, none of its text; a code that isn't the poll's is a 404 notice that quotes nothing.
- **Headers** (`src/security.ts`, `embedHeaders`): the only frameable page (`frame-ancestors *`), with no `script-src` at all, `form-action 'none'`, and the CSP's own `sandbox allow-same-origin allow-popups allow-popups-to-escape-sandbox`, which holds even where a host drops the iframe's attribute. `allow-same-origin` is a change from [[sharing]]'s first snippet, now updated: a sandboxed opaque origin is refused our `same-origin` stylesheet, and with no script the origin gives the frame nothing else. No cookie (the session cookie is `SameSite=Strict` anyway), no referrer, `cross-origin-resource-policy: cross-origin` so an isolated host can still frame it, and `public, max-age=60` since it carries no nonce; anything but a 200 is `no-store`. Every other page keeps `frame-ancestors 'none'`.
- **The share sheet** gains **Embed on your site**, which switches the dialog to the embed panel ([[sharing]], Share sheet): the card or a plain link that loads nothing from us, the card's colours (the reader's setting, light, dark), the code to paste with **Copy code**, a link to open the card in a new tab, and **Back to sharing**. The snippet sets a height for the poll's shape (one question 420 + 56 per answer, several 640, measured at 320 pixels wide; the page scrolls inside past that), `loading="lazy"`, `referrerpolicy="no-referrer"` and the sandbox. Copying happens in the browser; nothing reaches our servers or analytics.
- Page views count `/embed/p/:code` (any case), never the code or theme (T-67).
- Tested: `tests/ssr.test.ts` (an open poll's words and answer links with nothing but the ballot client and the short link off the card, several questions, a closed poll, the theme by link and a bad one ignored, a forgiving code drawn canonical, a hidden poll's notice, four kinds of code not found and never cached, the embed's headers on every answer, no script, form or inline style anywhere, every link a new tab, nothing of the reader's forwarded (cookie, address, referrer), and every other page still unframeable), `tests/security.test.ts` (the policy and which paths are embeds), `tests/analytics.test.ts` and `tests/serve.test.ts` (the template), `poll-embed.stories.tsx` (open, dark, several, closed, not open yet, no text, no ballot client, hidden, not found, at 320 and 640 pixels; axe at desktop and 360px), `poll-share.stories.tsx` (the panel: the exact snippet, the theme in its address, copying, the plain link, back). Framed cross-site in Chromium while building, at 320 and 640 pixels, light and dark: the stylesheet loads under the sandbox and the heights fit.
- The mockups' share sheet and embed (`share-sheet.tsx`, `share-embed.tsx` and their stories) are deleted, as the poll page's sheet now has every row, with the mockup helpers only they used.
- Known-weak: no results, asker or place on the card yet ([[P2-25]], [[P4-3]]). The panel has no inline preview (the site's CSP frames nothing), only a link to the card. The fallback line ("open abolish.ch or abolishus.eth and enter the code") is left out, as in the sheet and the flyer. A host that drops `allow-same-origin` from its own iframe gets the card unstyled, still working. The card's fonts are the stylesheet's; the small subsets Vite inlines as `data:` URIs are refused by `font-src 'self'` here as on every page, so those glyphs fall back to the system font. A reader's browser reaches us whenever a host page loads (T-11); the plain link is the alternative.
