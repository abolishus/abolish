- State: in progress (part 1: read side and request log, in review; part 2, ballot admission, to follow)

- Phase: Phase 2: Open polls end to end at Tier 0

## Scope

`apps/api` (Hono + oRPC): board read, ballot submit, election definitions.

Must include the T-10 no-join test for this app: no request log line, metric label or cache key carries both an account or session identifier and a ballot, nullifier or poll-participation value.

## Plan

1. **Read side and request log** (this part): every procedure of the contract, with `ballots.submit` failing closed; election definitions stored in core; the T-10 request-log test.
2. **Ballot admission**: `ballots.submit` decodes the record strictly and runs the admission checks (verifier 5.1 to 5.5, 5.7, 5.8) before `appendEntry`, with the segment taken from the anchoring clock. Needs P1-17b (membership proof verification) and the ballot record's decoder; until then the server boards nothing, and nothing is lost: a voter can submit directly once P1-18's direct submit exists (T-25).

## Built (part 1)

- `packages/core`:
  - migration `0001_election_definitions.sql`: one write-once row per election (`SELECT`, `INSERT` for `abolish_app`; triggers reject every change for every role);
  - `storeDefinition` (strict decoding and well-formedness through `@abolishus/crypto`, idempotent, `conflict` on different bytes) and `readDefinition`;
  - `readHead`, `readEntries` (count and byte bounded, lengths read before payloads), `readInclusionProof` and `readConsistencyProof`, all over `@abolishus/crypto`'s `BOARD_TREE`;
  - `@abolishus/core/test-db`, the per-file test schema helper, for other packages.
- `apps/api` (new, private, AGPL-3.0-only): the contract's router and a `node:http` server with oRPC's OpenAPI handler. JSON bodies only, bounded and cut off at `MAX_REQUEST_BODY`; a GET with a body is refused; board procedures answer only for elections with a stored definition; `ballots.submit` answers `ELECTION_NOT_OPEN`.
- Request log (T-10, T-11): method, matched contract route, status and duration only; errors by kind only. The handler context is the database alone.
- Decision: no Hono yet (see the app's README). Adding it changes the owner-reviewed catalog, and nothing needs it until accounts (P2-5).
- Threats: T-10, T-11 (no addresses logged), T-23, T-24, T-31, T-34, T-52, T-53.

## Tested

- Core (against Postgres, `FC_NUM_RUNS=1000`): the definitions table's schema, grants and write-once triggers (app and owner); every decoding and well-formedness vector of `election-definition.json` refused, with nothing stored; the published hash; conflicts; byte flips either refused or stored exactly as given. Board reads: heads equal what `checkBoard` and `merkleRoot` recompute; pages concatenate to `readBoard`; the byte budget (examples and a property that each page is within budget and maximal); every inclusion and consistency proof of an 11-entry board verifies with `verifyInclusion` and `verifyConsistency`; `invalid-range` and `beyond-board`, including sizes above Postgres's `bigint`.
- API, over HTTP: every procedure checked with `@abolishus/crypto`; error statuses; a 9 MB board page cut at 8 entries; non-JSON, multipart, oversize and chunked oversize bodies refused; `ballots.submit` boards nothing.
- T-10: requests carrying cookies, bearer tokens, forwarding headers, query values and ballots leave none of them in the log, and every line has exactly the four allowed fields; an internal error's message never reaches the log or the response.
- Mutation checks, by hand: logging the raw URL, removing the streaming body bound, and boarding on submit each fail a test.

## Known-weak

- **No ballots are taken yet** (part 2).
- **Heads and proofs read every entry hash** of the tree they cover, O(n) per request, with no cache. Fine for the reference election; a cache of the tree's frontier comes before real load (T-52).
- **No rate limiting** (`RATE_LIMITED` is never returned) and no CORS, which the ballot client will need from its own origin (P2-8).
- **The proxy's own access log** is outside this test; P2-11 must configure it (T-11).
- Stored entry hashes are served as stored; a client that checks what it is served catches a column that disagrees with the bytes.
