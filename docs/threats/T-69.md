# T-69: Legal compulsion

- Area: Development, supply chain and operations (G-14)
- Adversary: A-1, A-7
- Status: **Partial by design.** A gag order compelling a malicious client release is T-41; we can't prove a negative.

## Threat

We are ordered to hand over data, insert a backdoor or stop operating.

## Mitigation

Data minimisation: we never hold an account-ballot linkage or plaintext votes to hand over (T-09, T-10); censorship resistance (T-49).

Index: [[THREAT_MODEL]].

## History

- 2026-10-11 (P1-16): the board's anchoring key is a compulsion target. Its holder can fail a running election by equivocating (public and attributable), but not a closed one: late anchors don't count ([[board]], Timing).
- 2026-10-11 (P1-16 follow-up, #37): a compelled anchoring key's holder who anchors checkpoints no board can match fails the running election attributably (`checkpoint-inconsistent`), rather than leaving it silently unverifiable ([[board]], Board checks).
- 2026-10-12 (P4-1 part 1): the L1 board anchor takes checkpoints only from its fixed authority (a Safe), only inside each period's 12-hour window, so a compelled or seized key can't fail a closed election. Residuals: unattended hourly anchoring keeps the Safe's quorum online on the runners, so seizing their hosting is seizing the quorum; the Safe's owners and threshold can change after deployment. A quorum held at some moment could also anchor for elections not yet created; verifiers ignore anchors before an election's first segment, and the creator checks the few slots from that segment on before its ceremony, per slot, so a briefly held quorum can't block future identifiers wholesale ([[contracts]], Board anchor).
- 2026-10-12 (P3-2 part 1): the Tier 0 signing service holds a threshold of the group registry's registrar keys online, so seizing or compelling it yields the power to add or remove any Tier 0 member, attributably (every record carries its signatures). The keys are dedicated, never the Safe's owners, so the blast radius stops at Tier 0; rotating them needs a new registry and new groups ([[contracts]], Group registry).
- 2026-10-12 (P1-7 follow-up, [[contracts]], Trustee registry): under [[0006-trustees]] rule 7 an election opens only with `max(k, n − 1)` qualified seats and as many registration signatures, so any two seats of a 4-of-7 panel can stop every election from opening by refusing to take part or to sign. That is below the decryption threshold, and rule 1 lets one state hold up to `k − 1` seats, so a single state compelling two trustees can do it, as censorship rather than decryption (T-25). Re-runs don't help against a deliberate refusal, and a refusal shows only as absence, never attributed. The refusal can also be selective (a node sees the stub and can fetch its committed display text, so it can block chosen polls while looking like an outage), and rule 2 lets one hosting provider run up to `k − 1` nodes, so a compelled or seized provider can block too. Before rule 7, blocking needed `n − k + 1` seats, which is more than rule 1 lets one state hold when `n ≥ 2k − 1` (4 seats for 4-of-7). This follows from rule 7; the owner's decision doesn't state it, so it is listed in [[0006-trustees]] (Known-weak) and STATUS (Known-weak) for the owner to see.
