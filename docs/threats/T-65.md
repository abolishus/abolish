# T-65: Deployer or service credential leak

- Area: Development, supply chain and operations (G-14)
- Adversary: A-6, A-2
- Status: **Partial.** Environment protection rules are the owner's to configure; agents can't verify them. CI also holds a repository-level, read-only Docker Hub token (`DOCKERHUB_TOKEN`, #19) for pulling service images; any workflow run from an in-repo branch can read it, so it must stay read-only.

## Threat

Deployer or service credential leak.

## Mitigation

Testnet deploys only from GitHub Actions with environment secrets; no session ever holds a private key (AGENTS.md). Mainnet waits for the owner.

Index: [[THREAT_MODEL]].

## History

- 2026-10-11 (P2-11 part 1): [[railway]] gives each Railway service its own database login: `api-migrate` one granted `abolish_migrator`, `api` one granted only `abolish_app`, so the API's credential can't alter a table, trigger or grant. `RAILWAY_TOKEN` lives only in the `staging` and `production` GitHub environments, one project token per Railway environment.
