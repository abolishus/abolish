# P1-10: Canonical encoders and decoders

- State: in review
- PR: #21
- Branch: `claude/p1-10`
- Phase: Phase 1: Threat model, spec, crypto core, circuits, verifier, reference election (CLI only)

## Scope

Strict encoders and decoders in `packages/crypto` for the primitive types and record framing of [[notation]] (option A of [[0001-canonical-encoding]]), the `DS(tag, m)` framing of [[domain-separation]], and the tag and record-type tables checked against the spec's registries. Threats: T-31, T-30, T-36, T-52, T-04, T-34.

The record layouts that were P1-10's (election definition `0x0001` and display text `0x0009`) are split out to [[P1-10b]]: they need `H` and the group encodings (P1-11), and the panel the owner decides ([[0006-trustees]]).

## Tested

- Every vector in `docs/spec/vectors/primitives.json`, decoded through codecs built from the file's own type descriptors and re-encoded byte for byte, with every rejection checked against its error code.
- fast-check properties over randomly nested lists and structs of every primitive: `decode(encode(x)) = x`; random and single-byte-mutated inputs are rejected or re-encode to themselves; every proper prefix is `truncated`; any extra byte is `trailing-bytes`; over-maximum lengths are rejected from the 4-byte prefix alone (T-52); every value at or above `r` is `non-canonical`.
- Record framing: unknown, unexpected and unknown-version cases, type and version 0, the test range admitted only on request, and `profile-mismatch` reported straight after the header.
- The UTF-8 validator, written out from RFC 3629's table, agrees with the platform's fatal decoder on random input, on every 1- and 2-byte sequence and on the 3-byte boundaries.
- `TAG_REGISTRY` and `RECORD_TYPES` match the tables in [[domain-separation]] and [[versioning]], parsed from the markdown, and `ds()` refuses tags that aren't specified.
- Encoders reject out-of-range, wrong-type and extra-key values instead of emitting them. Hostile JavaScript inputs are tested too: `Buffer` and non-byte typed arrays, overridden list iterators, struct keys like `a,b`, hand-built record types and a polluted `Object.prototype`.

## Known-weak

- The vectors are still checked only by TypeScript. Noir (P1-17) and Solidity (P1-18) consumers don't exist yet, so a misreading shared by the spec and this code would go unnoticed until they do ([[0001-canonical-encoding]], Consequences).
- `RecordSchema.decode` requires the pinned version, but a caller can still pass `UNPINNED`. Only vector files and tests should; the verifier (P1-19) must pin every record (check 2.3 in [[verifier]]).
- `ds()` builds only the hash input. `H` itself arrives with P1-11.
