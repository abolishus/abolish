# P1-10b: Election-definition and display-text record layouts

- State: in review
- PR: #35
- Branch: `claude/p1-10b`
- Phase: Phase 1: Threat model, spec, crypto core, circuits, verifier, reference election (CLI only)

## Scope

Split from [[P1-10]], which built the primitive codecs, record framing and `DS` framing. This item specifies and implements version 1 of the election definition (`0x0001`) and the display-text record (`0x0009`) in `docs/spec/` and `packages/crypto`, with vectors (`docs/spec/vectors/election-definition.json`, `display-text.json`) and the `profile-mismatch` vectors. It also specifies the `abolish/v1/election-definition` tag's input layout.

Waits on: the group and hash layer (P1-11) for `H` and for group elements in the definition; the trustee panel encoding ([[0006-trustees]], which the owner decides) for the panel field, which until then can be a test panel.

## Carried over from P1-10's reviews

Non-blocking findings from the #21 reviews. #35 closes all four (see Built).

- **The definition's own version pin.** The election definition carries the profile, so it can't be decoded against a pin known in advance. Add a dedicated definition decoder: decode `UNPINNED`, then reject with `profile-mismatch` unless the decoded version equals the profile's pin for `0x0001`. Add a vector for it. Otherwise, once a second definition version exists, a creator could encode a new election under a retired layout (T-34, T-31; [[verifier]] check 2.3). Also correct the `packages/crypto` README, which says only vector files and tests pass `UNPINNED`.
- **Error code precedence.** When a record's version is both unknown to the decoder and not the pinned one, `RecordSchema.decode` reports `unknown-version`, while [[verifier]] 2.3 says `profile-mismatch`. Settle which code wins in [[notation]] and the vectors, then make the code match.
- **Unregistered record numbers.** A production `RecordSchema` (without `allowTestRange`) accepts any number from 1 to `0xfeff`, including numbers the registry never assigned. Reject numbers outside `RECORD_TYPES` unless the test range is allowed, so [[versioning]] stays the only place numbers are assigned.
- **`struct()` keeps the caller's fields array.** Copy and freeze the fields when the codec is made, so the layout can't change after a record type registers it.

## Built (#35)

- [[election-definition]] (new): version 1 of `0x0001` as a **draft** layout. It covers the profile, `election_id`, chain IDs and contract addresses, election type, tally scheme and selection range, the electorate (tier, group, root, block, size), the membership key hash, the panel (`panel_id`, `k`, `n`), the ceremony transcript hash, timing and the display-text commitment. It also specifies the definition hash (`abolish/v1/election-definition` is now specified), the two-step decode against the definition's own profile, and ten well-formedness rules with codes.
- [[display-text]]: version 1 of `0x0009` as a draft, with translations (lowercase BCP 47 tag, question, description, options) and five shape rules after the commitment check.
- [[versioning]]: draft layouts. A draft is covered by vectors but not frozen by them, and is never used on a public chain or in a real election. A verifier reports an election pinning a draft as unverifiable ([[verifier]] 8.3). The registry assigns record types `0x0001` and `0x0009` version 1, both draft.
- [[notation]]: `profile-mismatch` wins over `unknown-version`.
- [[vectors/README|vectors]]: `draft`, `types`, the `struct` and `ref` descriptors, and the record-vector members (`hash`, `commitment`, `pinned`, `definition`, `illFormed`).
- `packages/crypto`:
  - `encodeElectionDefinition` and `decodeElectionDefinition` (with the self-pin check), `electionDefinitionHash`, `electionDefinitionRule`.
  - `encodeDisplayText`, `decodeDisplayText`, `displayTextCommitment`, `displayTextRule`.
  - `newElectionId` and `newDisplayTextSalt`, from the CSPRNG.
  - `PROTOCOL_SCHEMA`, `PARAMETERS`, `DRAFT_VERSIONS` and `pinsDraftVersion`.
  - The carried-over fixes: the pin is checked first; production schemas reject unassigned record numbers; `struct` copies and freezes its layout.
- Tests:
  - `election-definition.json` (56 vectors) and `display-text.json` (21), printed by `scripts/definition-vectors.py`. That script is an independent Python encoder plus a rule checker that confirms every `illFormed` label. All vectors run through the production code.
  - fast-check: round-trips, a flipped byte or random bytes are rejected or re-encode, self-pin, and hash binding.
  - One mutation test per well-formedness rule, plus tests for parameters and randomness.
- T-17's residual gains the creator-chosen bytes of a definition.
- Threats: T-34, T-31, T-30, T-32, T-17, T-14, T-16, T-01, T-41, T-52.

## Known-weak

- **Both layouts are drafts.** P1-14 (panel, ceremony), P1-17 (electorate, verification-key hash), P1-18 (contracts, timing and close rule) and the owner's trustee decision ([[0006-trustees]], including whether civic elections need a marker) may change fields in place before they are frozen.
- **No well-formedness bound on `l1_inclusion_bound`, `sequencing_window` or `max_sequencer_drift`** (zero is accepted). P1-18 owns the close rule and adds the bounds.
- **A creator can archive somewhat over 100 chosen bytes per definition:** `election_id`, `display_text_commitment` (only the report-only check 2.7 compares it with text), and the free bits of the bounded integers (times, `l1_inclusion_bound`, `sequencing_window`, `max_sequencer_drift`, `root_l2_block`). T-17's residual now says so.
- **Labels can differ only invisibly** (`Yes` and `Yes` plus U+200B): exact repeats are rejected, look-alikes aren't (T-41).
- **Both drafts must be frozen before any public-chain run,** including the reference election against staging (a testnet) that the phase gate requires. The freeze PR records the freeze cutoff ([[versioning]]).
- **Translations aren't checked against each other.** Two translations can give an option different meanings. The commitment makes that public evidence but doesn't prevent it (T-41).
- **`threshold ≥ 2` is the only floor on `k`.** [[0006-trustees]] may raise it.
- **Decode-error labels in the vectors are written by hand** from the strict-decoding rules; only the encodings and the rule labels are checked by the independent script. `unexpected-record-type` for a definition is tested in TypeScript only, because a vector file's known types are only those in that file.
- **One identity in two tier groups can choose which tier's cell its ballot falls in**, and today one secret gives one nullifier across tiers. P1-17 and P3-2 must handle this (see [[verifier]] 6.1). Distinct roots stop only identical groups.
