# T-54: Trustee unavailability

- Area: Availability and censorship resistance (G-10)
- Adversary: A-1, A-7
- Status: **Needs decision** (P1-7). A ranked-choice mixnet (P1-4) would add sequential mixer availability. Under P1-3 (option B), trustees must also be online during voting (otherwise their share is posted publicly for every ballot, with classical privacy only) and must process postings within the complaint window; a trustee that misses the window can't contribute to the tally, so the tally needs k trustees that did.

## Threat

Fewer than k trustees are available after close, so the tally can never be decrypted.

## Mitigation

k-of-n with k < n, chosen by the owner (P1-7; [[0006-trustees]]: 4-of-7, decided on 2026-10-12, tolerating three unavailable trustees at the tally; rule 7 needs `n − 1` at the ceremony); the reference election and simulations run with trustees offline (P1-20, P1-21).

- 2026-10-13 (P2-13 part 1): the trustee node approves a transcript only with at least `max(k, n − 1)` qualified seats, its own among them ([[0006-trustees]] rule 7), so a coordinator that withholds a second seat's message stalls the ceremony rather than shrinking its margin. A retry after a lost response gets the message the node already sent, so a transport hiccup doesn't end a run; a crash between the run's first records still abandons it, and the creator starts another.
- 2026-10-13 (P2-13 part 2): the node reaches the coordinator only by polling it, and a lost poll, post or response costs one poll: it is asked again and the seat answers with the message it recorded (tested as a property over whole ceremonies). A coordinator that withholds a seat stalls or shrinks the run exactly as [[ceremony]] says, and the node logs why it refused, but doesn't yet tell the coordinator.
- 2026-10-15 (P1-12c part 2a, [[delivery]], What a node owes, Capacity): a node's complaints, which keep its summed shares valid, are owed for its complaint scope only and fit the forced path before it serves an election, so a flood of postings can't exhaust what it pays to complain. With board data withheld, a counted ballot's failing posting can fall outside the scope, and its summed shares then fail; P4-3's data availability closes that.

Index: [[THREAT_MODEL]].

## History

- 2026-10-12 (P1-14 part 2, [[ceremony]]): a ceremony qualifies a seat only if it took part in all four rounds and passed every check; the protocol's floor is `k` qualified seats. [[0006-trustees]]'s proposed rule 7 (`n − 1`) is the owner's; until then a definition can bind a ceremony with as few as `k` seats, leaving its tally no failure margin.
- 2026-10-11 (P1-15, part 1): a cell with no published opening fails the election (`tally-missing`, [[tally]]); any trustee holding `k` passing summed shares can combine and publish it, and any `k` give the same opening, so which trustees are online doesn't change the result.
- 2026-10-12 (P1-15, part 2a, [[tally]], Tally window): tally opening version 1 fixes a 7-day tally window, starting when the checkpoint anchoring the counted set is due (after every earlier window, each a constant of its pinned version or contract), as the tally's term in the seal, so no one can shorten it for one election and a longer earlier window never eats into it. The operator boards only attributed openings, so stripping a signature doesn't block the tally (the attributed original is boarded); the verifier still counts an unattributed opening that passes, as a defence against an operator that breaks that rule. A cell with no opening by the seal still fails the election permanently, and the board operator can cause that by refusing every opening, unattributed, since openings have no direct-submit path yet. [[tally]] requires one, as events under the event accumulator, before any election registry is deployed (P1-18).
- 2026-10-12 (P1-19 part 4a, [[verifier]], Key ceremony): the verifier applies [[0006-trustees]] rule 7, adopted by the owner: 3.2 fails `ceremony-participation` when a valid transcript has fewer than `max(k, n − 1)` qualified seats, so a coordinator that shrinks the qualified set to `k` (leaving the tally no margin) fails the election. `packages/crypto`'s `ceremony-quorum` still means fewer than `k`; the registry quorum `q = n − 1` is P1-18's follow-up.
- 2026-10-12 (P1-12 part 3b, [[delivery]]): the delivery deadline (two days) and the complaint window (five days), counted from `closes_at + l1_inclusion_bound`, are constants of the delivery records' version 1 and terms of `W_S`, so the counted set is fixed before the tally. A trustee that misses the complaint window can't complain about an invalid posting, its summed shares then fail, and the tally needs `k` other trustees. Postings deliver only through the contract path, whose data every trustee's L2 node reads, so an operator can't withhold a posting through the complaint window and publish it afterwards, which would have kept an invalid ballot counted that no trustee could complain about and left fewer than `k` summed shares passing (the owner's decision in [[0002-everlasting-privacy]], 2026-10-12).
- 2026-10-12 (P1-7 follow-up, [[contracts]], Trustee registry): every deployment's registry quorum is `q = max(k, n − 1)` under rule 7, matching the participation rule; [[0018-ceremony-possession]] now states the rule as adopted. The cost is the one rule 7 accepts: an election whose ceremony can't gather `n − 1` seats, or their registration signatures, doesn't open, so two seats unavailable at the ceremony stall it (the tally still needs only `k`).
- 2026-10-12 (P1-15 part 3, [[tally]], Destruction): a missing or early destruction statement is only reported, never an election failure, so no trustee can veto a result by withholding one. The destruction window (1 day after `t_D`, which is the tally window's end or, if later, the anchoring deadline of the segment before it) extends the seal by about a day; trustees keep and resend the openings they already signed, but one that has destroyed its material at `t_D` can no longer combine a cell nobody had combined.
- 2026-10-12 (P3-4 part 2b-2a, [[nullifier-key]]): creating the Tier 2 key needs `max(k, n − 1)` seats' approvals, and a seat approves only holding its share, so one corrupt seat can stall it, unattributably, by withholding its dealt share from one honest seat and not approving itself. A seat that zeroes its own share only loses its own seat (`identity-commitment`), rather than failing the run.
- 2026-10-13 (P3-4 part 2b-2b, [[nullifier-reshare]]): a panel change needs `max(k, n − 1)` of the predecessor's seats to deal (the old panel's consent, so that the release alone can't choose who receives `sk`; review of #166), so, as for opening elections under rule 7, any two old seats that are gone, refuse or are corrupt block every panel change, including one that would replace them, and the key then stays on a shrinking panel until `n − k + 1` losses end it; panels should be refreshed or changed while at most one seat is missing and `max(k', n' − 1)` new seats to approve, so a reshare run can be stalled as the initial key can (one corrupt dealer withholding from one honest new seat, with one new seat that doesn't approve); the predecessor stays in force meanwhile, and a run's approvals expire at its deadline, so a stalled run releases its seats and the adversary delays a panel change only while it keeps withholding. The initial key's approvals have no deadline yet, so a stalled initial run blocks the scope's key for good until part 2b-4 gives them one. Losing `n − k + 1` of the predecessor's shares before a reshare still ends the key.
- 2026-10-13 (P2-16 part 1a, [[election-definition]] Author panel): a version-6 poll with an author panel can be counted only if `author_threshold` author seats take part at the tally; otherwise it never can, by anyone. Accepted by the owner's decision on author-added trustees ([[0027-trustee-panels-and-live-results]], Liveness); the UI must say so plainly (P2-16 part 7).
- 2026-10-13 (P4-3 part 2a, [[0029-board-data-availability]]): decided, not built. Checkpoint version 2 names each segment's CIDs on L1, and before any result each trustee panel's threshold of seats must attest through the L2 contract path that it held the ballot extent by `c_I` and the counted extent before any summed share, or the election fails `unavailable`, listing who attested, complained or did nothing. Both points come before any summed share, so a seat that won't attest aborts before anyone knows the outcome, as its panel's threshold could by withholding the tally; no attestation is asked after the result, which would hand trustees a veto ([[tally]], Destruction checks). The new duty falls on the same seats earlier: by `c_I` and by the counted extent's quorum.
- 2026-10-13 (P1-18 part 4b-3d-1, [[contracts]], Board): the contract path for receipts, postings and complaints exists in code, accepting any number per seat and ballot, so neither an operator refusing board-path records nor a seat signing junk can keep the honest record off L2. Deployment waits on parts 4b-3d-2 and 4c.
- 2026-10-13 (P2-16 part 2a, [[delivery]] Version 2): a version-4 ballot is delivered only when every qualified seat of both panels holds its shares; an author seat can't yet be delivered through the contract path, which needs the author key set on L2, so the election registry MUST refuse a definition with an author panel until P2-16 part 5 gives the board contract that key set.
- 2026-10-13 (P1-18 part 4c-1, [[0030-close-rule]]): decided, not built. Each default-panel seat owes a close statement by `c_I`, the L2 head derivable from L1 by `closes_at + δ`. Fewer than `k` statements leave the close unchecked, reported with the silent seats named, never a failed election; `k` seats stating low can fail an election (`close-contested`), as refusing the tally already can, but can't change which ballots count.
- 2026-10-13 (P1-18 part 4c-2a, [[close]]): specified. The statement is due within `CLOSE_WINDOW` (2 days after `closes_at + δ`), sent as soon as `L_δ` is final; with fewer than `k` counted seats the close is unchecked and reported, never failed, so `n − k + 1` silent seats can't fail an election.
