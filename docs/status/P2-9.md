## Scope

`apps/web`: TanStack Start SSR (discovery, results, poll creation), and PostHog proxied via our domain.

## Plan

1. **Scaffold, poll pages and the moderation log** (this part): TanStack Start rendered on the server; a poll page from the API's definition, board head and moderation state; the public moderation log; a lookup by poll ID; the security headers.
2. **Accounts and PostHog**: mount the account handler from `@abolishus/core` (P2-5 part 1) on this origin, with Turnstile once P2-5 part 2 lands; PostHog proxied through our domain, capturing no poll IDs from pages a signed-in account views beyond what T-67 accepts; a Node server entry for the built handler, for P2-11's image.
3. **Discovery and poll creation**: the API has no listing route yet (P2-3 part 2 or a follow-up adds one, honouring delisting); poll creation needs the election registry write path.
4. **Results**: per-cell tallies once P1-15 publishes them, with the display text checked against the definition's commitment before it is shown (T-34).

## Built (part 1)

- `apps/web`: TanStack Start 1.168 (React 19) on Vite+, SSR, file routes (`src/routes/`; `src/routeTree.gen.ts` is generated by the build, in the repo's style).
  - `/`: what the site is and a lookup form (a plain GET form, so it works without script). `/polls?id=…` forgives `0x`, capitals and spaces and redirects to the poll's one address; anything else returns to the form, marked invalid.
  - `/polls/<id>`: only canonical lowercase hex is a poll page (T-31). The definition is decoded with `@abolishus/crypto`; one that doesn't decode, or names another election, is refused rather than shown (T-34). Shown: counting rule, options, selections, electorate tiers and group sizes, trustee threshold, opening and closing times in UTC, the definition hash to compare with the registry, a broken well-formedness rule if any, the board's size, chain head and root, marked as the server's word until anchored (T-24), and the moderation state with its reason; delisted or hidden polls get `noindex`.
  - `/moderation`: the public log, paged by sequence number (T-68).
- Data comes only through server functions, which call the API from our server with an oRPC client over the contract, checking every answer against it (`ResponseValidationPlugin`), with no redirects followed and a 5-second timeout. No request to the API carries anything of the visitor's (T-10).
- Every response carries a CSP with a fresh 128-bit nonce, which the router stamps on the inline scripts it renders, plus `no-referrer`, `nosniff`, same-origin opener and resource policies and a restrictive `Permissions-Policy` (T-43, T-11, T-67). Server functions refuse cross-site calls (TanStack's CSRF middleware) before any handler runs. A failed API call reaches the page as one fixed error; the log gets the error's kind only.
- Every string is in the i18n catalog (`src/messages.ts`); every component has stories.
- New dependencies: `@tanstack/react-start` and `@tanstack/react-router` (the brief's frontend stack), `@orpc/client` and `@orpc/openapi-client` (the contract's own client; `@orpc/client` was already in the tree).
- Threats: T-10, T-11, T-24, T-31, T-34, T-43, T-67, T-68.

## Tested (part 1)

- `test`: hex, election-ID, `u64` and search-text rules, by property; the definition view against every vector in `docs/spec/vectors/election-definition.json` (hash, broken rule and facts for each decodable one, refusal for each undecodable one, refusal under any other election ID), on arbitrary bytes and on byte-flipped vectors; the CSP and headers.
- `test` (`tests/ssr.test.ts`): builds the app and renders pages with the built server against a stub API. Every page has the headers, every inline script carries that response's nonce and every other script is one of our bundles, with no inline handlers and no other-origin URLs; nonces differ per response. A poll page shows the vector's definition hash and the board head; a page request carrying an account cookie, a bearer token, `x-forwarded-for` and a user agent reaches the API with none of them; a hidden poll shows the reason and `noindex`; a definition for another election is refused; unknown, upper-case and short IDs are 404; lookups redirect to the canonical address or return to the form; the log lists and pages; both server functions answer 403 to a cross-site call without calling the API, and run for a same-origin one; with the API down, the page is a 500 that quotes no address or error.
- `test:storybook`: poll summary (default, dark, empty board, hidden, delisted, ill-formed), moderation log (default, dark, with more, empty), lookup form (default, dark, invalid) and the site frame (not found, error), each with a play function and axe (WCAG 2.2 AA).

## Known-weak (part 1)

- **The page doesn't check the registry or the anchor.** It decodes the definition and shows its hash, but doesn't compare it with the election registry on L2, nor the board head with an L1 checkpoint; it says these are the server's word. The verifier is where they are checked (T-34, T-24).
- **No question or option text yet.** The display text lives off the board; showing it needs fetching it and checking its commitment (P1-10b), which comes with results (part 4).
- **The CSP is weaker than the ballot client's**: `'self'` scripts beside the nonce (route chunks load by dynamic import) and no Trusted Types, since the framework renders inline scripts. Nothing on this site casts a vote or holds a voting secret (T-43).
- **The server sees which polls a visitor views** (T-11, T-67), as any web server does. Its own request log and the proxy in front of it must keep no addresses or query strings (P2-11, as for the API).
- **No production server entry or image yet**: the build is a fetch handler (`dist/server/server.js`); part 2 adds the Node entry and P2-11 the image.
