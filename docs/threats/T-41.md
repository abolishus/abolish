# T-41: Targeted malicious client

- Area: Client integrity and cast as intended (G-6, G-13)
- Adversary: A-2, A-1, A-7
- Status: **Planned.** Residual: a voter who loads the client from abolish.us without checking its hash trusts whoever serves that domain. Hash-checking in a browser has no good UX; the native app (P5-2) closes this for its users, except that a voter with a recovery backup can still be lured into authenticating with the backup passkey on a malicious web client on the ballot RP ID, which exposes the secret however they vote ([[0017-identity-recovery-backup]]). Under P1-3 (option B), a malicious client can also post an invalid share on the voter's last ballot; the proven complaint can arrive after close, too late to re-vote, so that vote is nullified.

## Threat

Whoever serves the JavaScript serves a modified ballot client to one voter.

## Mitigation

The ballot client is a reproducible, signed, hash-addressed static build pinned to IPFS (P2-8, P0-3); the verifier checks a served client against a signed release (P1-19); `abolishus.eth` and a second domain serve the same hash (P4-4).

## History

- 2026-10-11 (P1-13): a ballot's L1 reference and membership message are made after the cast-or-challenge choice, so Benaloh doesn't audit them; the voter's receipt check must show the ballot's admission verdict and whether it is selected ([[revoting]], Owned elsewhere).
- 2026-10-11 (P2-6 part 1): [[0017-identity-recovery-backup]] widens this threat's reach. Whoever serves the ballot client's RP ID can read a voter's secret from the recovery backup on any device the backup passkey syncs to, including one where the voter never ran the ballot client, once the voter authenticates there; and a served `/.well-known/webauthn` that differs from the signed release could let another origin ask for the PRF. The RP ID's well-known and associated-domain files are part of the signed release and P1-19's served-client check covers them.
- 2026-10-11 (P1-12, part 2): a client that posts an invalid share is caught by a trustee's complaint, a Chaum–Pedersen proof of the DH value anyone checks. Only the client that made a ciphertext, or the trustee it is for, knows the `m` that makes its posting pass ([[share-encryption]], Public posting), a failing posting is ignored, and a trustee can't exclude a ballot without a proof ([[share-encryption]], Complaints).
