## Scope

## Plan

## Known-weak

- Nothing is deployed and nothing anchors yet (part 2), so every board is unanchored and the `reference-election` check can't cover anchoring until P1-20 uses this contract on Anvil.
- The anchoring authority can still fail a running election, attributably, by anchoring a checkpoint no board matches first; the contract then keeps it. A Safe makes that a quorum's act, not one key's ([[contracts]], Board anchor, Known-weak).
- The anchor can't refuse a segment past an election's seal (it can't read the definition); verifiers ignore those.
- A call with one checkpoint costs about 84,000 gas, each further one about 34,000, an election's first about 22,000 more; on mainnet that is a recurring cost for the owner to fund.
- The anchoring runners hold the Safe's quorum online, and the Safe's configuration (owners, threshold, modules, guard, singleton) can change after deployment; the verifier doesn't check it yet, and part 2 must use no module or guard that bypasses the threshold.
- A quorum held at some moment could anchor checkpoints for elections not yet created. Verifiers ignore anchors for segments before an election's first segment (its creation's L1 origin), and the creator MUST check that the few slots from that segment on are empty once creation is final, abandoning the identifier otherwise (a per-slot check, so a briefly held quorum can't block future identifiers wholesale); a creator that skips the check can lose its election to an anchor made in the drift window before creation.
- The anchored checkpoint carries no content address of its segment object ([[board]], Residuals); adding one (P4-3) means a new anchor deployment.
