# T-35: Time manipulation

- Area: Integrity and verifiability (G-7, G-8, G-9)
- Adversary: A-2, A-1
- Status: **Planned.** Residual ([[0030-close-rule]]): within δ, a sequencer withholding batches can still admit ballots made after close (beyond it the election fails, unless `k` trustees lie), and the board operator can through the board path within `s_A`, T-50.

## Threat

Ballots are accepted after close, or rejected before, by a server clock, or by the L2 sequencer choosing timestamps, lagging its L1 origin or rebuilding unposted blocks with earlier timestamps.

## Mitigation

Opening and closing are defined by L2 timestamps in the election definition, not server time, together with a bound on when the ballot's batch reached L1; forced ballots carry an L1 timestamp stamped by our relay contract; the verifier applies the same rule ([[0004-l2-choice]], P1-18, P1-19).

## History

- 2026-10-11 (P1-13): `l1-ref-after-close` bounds the block a ballot names, not when it was made; P1-18's close rule must not admit ballots made after close, or a coercer with the sequencer could outrank every honest re-vote ([[revoting]], Residuals).
- 2026-10-13 (P1-18 part 4c-1, [[0030-close-rule]]): decided, not built. An ordinary direct-submitted ballot counts if its L2 block is at or before close; a relayed ballot by its L1 stamp; a board-path ballot by the operator's word within `s_A`. The panel's close statements give a close head at `closes_at + δ`, and a ballot after it that would change a result fails the election (`close-contested`), so a sequencer rebuilding pre-close blocks gets δ silently and beyond δ only with `k` seats lying (checkable only while the L1 blobs live); a compromised operator can admit ballots made after close through the board path for up to about two periods.
- 2026-10-13 (P1-18 part 4c-2a, [[close]]): specified. 5.5 judges each copy by its own path (`window-before-open`, `window-after-close`, `window-boarded-late`), and 6.3 fails `close-contested` when removing the ordinary ballots in blocks after the close head `B` changes a cell's counted set; `B` is the `k`-th largest of the default panel's close statements (`0x0015`), which can only fail an election, never change what counts. [[revoting]]'s MUST now names the five ways a ballot made after close can still count: a sequencer's rebuild within δ, beyond it with `k` seats lying, or beyond it when `n − k + 1` seats stay silent and the close is unchecked (fewer seats than `k` whenever `k > (n + 1) / 2`, and ours alone under the transitional panel, with no false statement); the operator through the board path; and an L1 proposer including a relay call made seconds after close in a block stamped before it.
- 2026-10-13 (P1-18 part 4c-2b-1): built in the election registry. It refuses a definition whose δ is above `MAX_INCLUSION_BOUND`, an hour ([[parameters]]), so a sequencer's silent rebuild of unposted blocks before close is bounded to an hour after close; and it records each election's `opens_at`, `closes_at` and δ for the board's window and statement checks (parts 4c-2b and 4c-3). Until those are built the board still takes ballots at any time.
- 2026-10-13 (P1-18 part 4c-2b-2a): built in the election registry. It refuses a definition assuming a `max_sequencer_drift` above `MAX_SEQUENCER_DRIFT`, 1,800 seconds, or a `sequencing_window` above 3,600 L1 blocks ([[parameters]]), so [[verifier]] 2.6 never accepts a chain whose forced inclusion outruns the post-close windows, and fails closed on any raise of the drift past Base's 30 minutes.
- 2026-10-13 (P1-18 part 4c-2b-2b-1): board-entry version 5 allows the close statement, so a seat can state the close through the board path ([[board]], Allowed payloads; [[close]], Version). The verifier doesn't read version 5 yet (P1-19), the contract path is still to come, and no profile is yet required to pin it.
- 2026-10-13 (P1-19 part 4l): the verifier runs 5.5 on the board path and the ordinary path: a board-path ballot in a segment above `s_A` is rejected `window-boarded-late`, an ordinary one (the board's `BallotSubmitted` under contract-event version 2) by its record's `l2_timestamp` against `opens_at` and `closes_at`, each copy by its own entry; vectors cover every code at and around its bound. Not yet: the relayed path (contract-event version 3), the accumulator's proof of `l2_timestamp` (4.4) and the close check (6.3) ([[verifier]], Ballot admission).
- 2026-10-14 (P1-18 part 4c-2b-2b-2b): specified, not built. The board's relayed-ballot call refuses a stamp outside `[opens_at, closes_at]` (`relay-window`), and the close statements reach the board through a contract path whose events contract-event version 3 archives, so a seat whose board-path statement is held back can still be in the counted extent ([[contracts]], Board, Relayed ballots and Close statements).
- 2026-10-15 (P1-18 part 4c-3): built. The board refuses an ordinary ballot whose block's timestamp is outside `[opens_at, closes_at]` (`ballot-window`) and a relayed one whose stamp is (`relay-window`), and the L1 relay records each call's stamp from its own block, so neither path takes a ballot made after close except through the relay's seconds and a rebuild before `L_δ` ([[close]], Residuals). Seats state the close through the board's statement call, at most two statements each per election. The verifier sets relayed ballots aside until 4.5 matches their calls, leaving 5.5 unverifiable rather than judging an unproven stamp.
- 2026-10-15 (P1-19 part 4o, [[verifier]], Close check): the verifier runs 6.3 once delivery has: `L_δ` from the bundle's run of finalized L1 headers, the default panel's close statements judged by `closeHead`, and the counted sets recomputed without the late ordinary ballots by `closeCheck`. A contract-path statement waits on 4.4, and so does an ordinary ballot's L2 block, so today 6.3 decides boards whose ballots all came by the board path; the dispute-game floor isn't read, which changes no verdict.
