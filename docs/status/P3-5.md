## Scope

`apps/indexer` (Ponder), including direct-submitted ballots.

## Plan

1. **The scaffold and the group registry** (this part): `apps/indexer` on Ponder 0.18, storing `GroupCreated`, `MembersAdded` and `MembersRemoved` verbatim, and `readIndexedGroups` for readers, who replay the records through `@abolishus/crypto`'s `applyGroupRecords`.
2. **Completeness and the board's events**: store each log's raw topics, data and block timestamp and every event the contracts emit (`RegistrarsPinned` included), so a reader can check the index against the event accumulator's storage proofs ([[contracts]], Event accumulator); then the board's events, including direct-submitted ballots (T-25), stored as the contract-event records the verifier reads ([[0025-contract-event-evidence]]), and the election and trustee registries'.
3. **Readers**: the API and worker reading the index where they now read nothing from the chain (P2-3's L1 reference, P3-6's per-tier results), each rechecking what it reads.

## Part 1

- Built: `apps/indexer` (`ponder.config.ts`, `ponder.schema.ts`, `src/index.ts`, `src/env.ts`, `src/records.ts`, an empty `src/api/index.ts`, which Ponder requires); `packages/contracts` exports its generated ABI as `@abolishus/contracts/abi`.
- Dependencies: `ponder` 0.18.0, `viem` 2.57.3 (already in the tree through `@wagmi/cli`) and `hono` 4.13.13 (already in the tree), Ponder's peers. Ponder adds 112 packages, among them `graphql-yoga`, `pg`, `pino`, `drizzle-orm` 0.41.0 (beside the catalog's 0.45.3), `@electric-sql/pglite` and `pg-query-emscripten`, none with an install script. The catalog change routes the PR to the owner (CODEOWNERS).
- Independent review (in-session, `crypto-review` checklist): nothing blocking. Applied: the threat and status text no longer claim a corrupted row always fails a replay (a deleted removal or tail doesn't); `reorgWindow` set to Ponder's maximum and its wall-clock finality documented; both reads in one repeatable-read snapshot; event IDs ordered bytewise (`collate "C"`); a non-hex record fails as corruption; tests for a reordered row and a dropped removal. Left for part 2: storing raw logs and `RegistrarsPinned` for the accumulator check.
- Tested: on Anvil, records sent through both Ponder's backfill and its live indexing replay, under the pinned registrars, to exactly the leaves sent, an empty group included; a wiped index, with Ponder's RPC cache dropped, is rebuilt from the chain to the same result; under another registrar set every group's history fails at its first record; a reordered row fails and a dropped removal still replays; the deployment's parser refuses malformed values (property tests).
- Known-weak: the index trusts its L2 node for which logs exist, and anyone with write access to its database can delete rows: a dropped removal or a dropped tail of additions still replays, to another tree, and no reader checks completeness yet (the verifier's accumulator check does; part 2 stores what readers need for it). Ponder's finality is a wall-clock window (600 s, its maximum), not the L2's safe head, so a reorganisation of the unsafe chain after it leaves orphaned records that still replay; readers must treat rows above the safe head as provisional. Ponder's tree is large for what it does here, and runs in the indexer's process with the database credential; its RPC cache lives in Postgres schemas of its own beside the index, and the test drops every `ponder_` schema in the test database.
