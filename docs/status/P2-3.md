## Scope

`apps/api` (Hono + oRPC): board read, ballot submit, election definitions.

Must include the T-10 no-join test for this app: no request log line, metric label or cache key carries both an account or session identifier and a ballot, nullifier or poll-participation value.

## Plan

1. **Read side and request log** (this part): every procedure of the contract, with `ballots.submit` failing closed; election definitions stored in core; the T-10 request-log test.
   2a. **Strict JSON bodies** (this part): a body whose objects repeat a key is refused before admission exists to read it (T-31).
   2b. **Heads and proofs in O(log n)** (this part): the board tree's perfect subtrees stored as each entry is appended, so a head or proof reads O(log n) rows (T-52), as part 1's known-weak required before part 2 boards ballots.
   2c. **Each board under its pinned version** (this part): entries encoded, hashed and chained under the board-entry version the election's stored definition pins, never version 1 by default, since every plurality or approval profile pins version 4 (verifier 2.3) and a board under version 1 would fail 2.3 and 4.x for every entry the server boards.
2. **Ballot admission**: `ballots.submit` decodes the record strictly and runs the admission checks (verifier 5.1 to 5.5, 5.7, 5.8) before `appendEntry`, with the segment taken from the anchoring clock. Needs P1-17b (membership proof verification) and the ballot record's decoder; until then the server boards nothing, and nothing is lost: a voter can submit directly once P1-18's direct submit exists (T-25).

## Built (part 1)

- `packages/core`:
  - migration `0001_election_definitions.sql`: one write-once row per election (`SELECT`, `INSERT` for `abolish_app`; triggers reject every change for every role);
  - `storeDefinition` (strict decoding and well-formedness through `@abolishus/crypto`, idempotent, `conflict` on different bytes) `readDefinition` and `hasDefinition` (an existence check that doesn't read the bytes);
  - `readHead`, `readEntries` (count and byte bounded, lengths read before payloads), `readInclusionProof` and `readConsistencyProof`, all over `@abolishus/crypto`'s `BOARD_TREE`;
  - `@abolishus/core/test-db`, the per-file test schema helper, for other packages.
- `apps/api` (new, private, AGPL-3.0-only): the contract's router and a `node:http` server with oRPC's OpenAPI handler. JSON bodies only, bounded and cut off at `MAX_REQUEST_BODY`; a GET with a body is refused; board procedures answer only for elections with a stored definition; `ballots.submit` answers `ELECTION_NOT_OPEN`.
- Transport limits: a POST with a query string is refused; at most 32 requests in flight, the rest get 503 before anything is read; idle connections are destroyed after 15 s, a request must arrive within 30 s and none holds a slot past 60 s, so stalled or slow clients can't hold the slots; an oversize body is cut off without destroying the socket, so the 413 reaches the client.
- `erasableSyntaxOnly` in both packages' `tsconfig.json`: Node runs the app with type stripping only, which rejects parameter properties (core's `AppendError` had one) and enums.
- Request log (T-10, T-11): method, matched contract route, status and duration only; errors by kind only. The handler context is the database alone.
- Decision: no Hono yet (see the app's README). Adding it changes the owner-reviewed catalog, and nothing needs it until accounts (P2-5).
- Threats: T-10, T-11 (no addresses logged), T-23, T-24, T-31, T-34, T-52, T-53.

## Built (part 2a)

- `apps/api`: `hasDuplicateKey` (`src/json.ts`) scans a body that `JSON.parse` has already accepted and finds any object with two keys equal once unescaped (`"a"` and `"\u0061"`), with its own stack so deep nesting costs no call stack. The body reader refuses such a body with 400 before oRPC or any procedure sees it.
- Threats: T-31 (a history entry).

## Built (part 2b)

- `packages/crypto` (`src/merkle.ts`): `appendSubtrees` (the perfect subtrees a new leaf completes, from the frontier's hashes), `rootSubtrees`, `inclusionProofSubtrees` and `consistencyProofSubtrees` (which perfect subtrees each hash of a root or proof folds, mirroring RFC 9162's `MTH`, `PATH` and `SUBPROOF` recursions), and `foldSubtrees`. No new hash or tree: the same `BOARD_TREE` and recursion, unrolled. A changeset (minor).
- `packages/core`: migration `0006_board_subtrees.sql`, an append-only `board_subtrees` table (`SELECT`, `INSERT` for `abolish_app`; triggers reject every change for every role; a leaf needs its entry and a parent both children; fixed `search_path`). The migration refuses to run over a populated board, since nothing boards before it and a hand-written board is wiped and rebuilt.
- `appendEntry` stores each entry's subtrees in its transaction; `readHead`, `readInclusionProof`, `readConsistencyProof` and the size checks of every read fold or look up O(log n) rows (the last entry by the primary key, then at most a few hundred subtree rows) rather than every entry hash, and `count(*)` is gone.
- `auditBoard` recomputes every subtree from the entry hashes `checkBoard` derives (`subtree-missing`, `subtree-mismatch`), since the database can't hash.
- Threats: T-52 (a history entry), T-23, T-24.

## Built (part 2c)

- `packages/core` (`src/board.ts`): `appendEntry` reads the board-entry version the election's stored definition pins, in its transaction after the lock, and encodes the entry under it; it refuses `no-definition` (so a board starts only once its definition is stored) and `unsupported-version` (a pin other than 1, 3 or 4, or none; T-36). `readBoard` and `readEntries` encode under the same version; `boardVersion` is the shared lookup. Definitions are write-once, so a board's version never changes.
- `src/audit.ts`: `auditBoard` recomputes and checks the board under that version (`checkBoard` pinned to it, not unpinned), and reports `board-unpinned` for entries with no stored definition pinning a readable version.
- Tests store a definition before appending (`newElection` in `tests/db.ts`, exported as `@abolishus/core/test-db`; `apps/worker` and `apps/api` tests use it).
- Threats: T-23 (a history entry), T-34, T-36.

## Tested (part 2c)

A version-1 board is unchanged (every earlier test passes over the typical vector's version-1 pin).
- `no-definition` for an election without a definition, `unsupported-version` for pins 2 and 9, with nothing written.
- `readEntries` and `readHead` over a version-4 board agree with `checkBoard` under version 4.
- The audit passes a version-4 board, fails a row hashed under version 1 on it (`entry-hash-mismatch`), and reports `board-unpinned` for rows stored without a definition, under pin 2 or under a definition row that doesn't decode (which `appendEntry` refuses as `unsupported-version`); `readBoard` refuses such a board.
- Each version takes only its own payload types: a version-1 board refuses share receipts, complaints and destruction statements, a version-3 board destruction statements (`invalid-entry`); the ones a version allows reach the table, whose CHECK still refuses them (Known-weak).
- Mutation reasoning: encoding under version 1 in `appendEntry`, `readEntries` or the audit fails the new tests.

## Independent review

A fresh in-session subagent reviewed the diff against `.github/review/crypto-review.md`, the crypto-review and migrations skills, and ran the tests and a live server. Nothing blocking. Its findings:

- **Fixed:** `src/main.ts` crashed under plain Node on parameter properties, in the app and in core (now `erasableSyntaxOnly` plus a startup test); the existence check read the whole definition (now `hasDefinition`); a POST's query string was ignored rather than refused; 500s from output validation weren't logged; an oversize streamed body could reset the connection before the 413 arrived; per-request memory was unbounded across concurrent requests (now an in-flight cap); the empty-board head is now stated in the contract; the unused `definition_hash` column is dropped; storing a definition now says it must come from a finalized L2 block.

Its nits: `retry-after` on 503 and the startup test waiting for its child, done; a test that a 500-class `ORPCError` is logged, not added (the router has no seam to make an answer fail its output schema without test-only code).
- **Third pass**, over the timeout fix: nothing blocking. Its slow-reader finding (a client trickling reads, never idle) is fixed with a 60 s deadline per slot, tested; the 500-class log test stays as above.
- Not changed: `@abolishus/core/test-db` stays an export of the source-only, private package, for other packages' database tests. The migrations skill's rebuild-job rule has nothing to update until P3-5 builds the job; the definitions table is rebuilt from `DefinitionRegistered` events there.

## Known-weak

- **No ballots are taken yet** (part 2).
- **An entry inserted around `appendEntry`** (the API's role may insert, as above) has no subtrees: reads covering it and every later append for that election fail until the board is wiped and rebuilt, and wrong subtrees inserted with it would serve wrong roots until a client or `auditBoard` catches them. The read-only API role in part 2 closes this (T-23, T-52).
- **Board pages still read their lengths and rows by index**, bounded by the page limit; the audit is O(n) per board, by design.
- **The API connects as `abolish_app`, which may insert** board entries and definitions, though part 1 never writes. A compromised API could store a wrong definition for an election not yet stored, permanently (clients still catch it against the registry hash). A read-only role for the API's reads comes with part 2, which needs to write only through `appendEntry`.
- **A few connections can still take every in-flight slot** for up to the 60 s deadline at a time, and reconnect; per-address connection limits belong to the proxy (P2-11, T-52).
- **No rate limiting** (`RATE_LIMITED` is never returned) and no CORS, which the ballot client will need from its own origin (P2-8).
- **The proxy's own access log** is outside this test; P2-11 must configure it (T-11).
- Stored entry hashes are served as stored; a client that checks what it is served catches a column that disagrees with the bytes.
