# P3-6: Per-tier results

- State: in progress (part 1, the verifier's per-tier results in its summary, merged in #N; part 2, per-question results in the verifier's report once definition version 5's ballots are counted, next)
- Phase: Phase 3: Tier 2 ZK identity, Semaphore groups, indexer, per-tier results

## Scope

Per-tier results everywhere (API, web, verifier). The brief: every result is reported per tier, with the tier as a first-class layer (a tier switcher, never a footnote) with counts and scope, and tiers are never blended into one headline number. [[verifier]] 8.1 and 8.2 fix what a result carries (T-01, T-16, T-53).

## Parts

1. **The verifier's summary** (this part). `abolish-verify` already wrote each tier's `counted` and `counts` into the JSON report (`tiers`, P1-19 part 4o), but its stderr summary showed only the verdict and the failed checks. It now prints the results: one line per tier in `electorate` order, Tier 0 labelled not Sybil-resistant, each cell under a tier that has more than one, and no line that sums two tiers. The header says the figures aren't verified unless `verdict` is `verified`, so a crafted bundle's counts never read as the election's result. [[verifier]], Command line, states the format.
2. **Per question.** Under definition version 5 the report's `tiers` and `cells` carry each question's slice (`questionResults` in `packages/crypto`) and the summary prints them per question. Waits on the counted set under definition version 5: the delivery check doesn't read its ballots yet, so 7.1 never passes there and `tiers` is never reported.
3. **Scope: anonymity-set size and turnout** per tier and cell (8.1) and the small-count flags (8.2). Wait on 2.4's recomputation from the board's group additions (the archive replay, [[P4-3]]) and on a spec that fixes the small-count threshold.
4. **API and web.** A results route serving each tier's result from the board and the tier switcher on the poll's results page. The results pages are [[P2-9]] part 4's; this part supplies the per-tier data they show.

## Part 1

- `packages/verifier/src/cli.ts`: `summary` (now exported for its tests) appends the result lines.
- [[verifier]], Command line: the result lines' format.
- Tests (`packages/verifier/tests/cli.test.ts`): no results before the report has `tiers`; the exact lines for three tiers (Tier 0's label, a two-cell tier with its cells, a tier without counts); the not-verified header under `failed` and `unverifiable`; a cell without counts shown by its code; and a property that each tier's line carries exactly its own figures, once and in order. No vector's bundle reaches a counted tally, so the tests set `tiers` and `cells` on a real report.
- Threats: T-01 (Tier 0 labelled and never summed with another tier), T-53 (figures labelled unverified unless the verdict is verified).

## Known-weak

- A regional cell is shown by its number, not by the regions its groups were created with (8.1): the report doesn't carry them yet.
- The summary prints a tier's counts as one flat list of options, correct while every counted election has one question (part 2).
- No anonymity-set size, turnout or small-count flag yet (part 3).
