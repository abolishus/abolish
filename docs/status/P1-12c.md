# P1-12c: Membership-checked intake and bounded trustee receipts

- State: in progress (part 1, membership-checked intake and the bounded receipt obligation, merged in #171; part 2, the batched contract-path receipts, their capacity check and a bound on complaints, waits on P1-18 part 4's direct-submit contract)
- Branch: `claude/p1-12c`
- Phase: Phase 1: Threat model, spec, crypto core, circuits, verifier, reference election (CLI only)

## Scope

The fix the owner chose on 2026-10-12 for the residual accepted on P1-12 part 3b (#101; [[0002-everlasting-privacy]], Decision): a trustee node's obligation to send receipts through the contract path ([[delivery]], Direct submit) has no bound, since intake checks no membership, so a flood of ineligible ballots plus an operator that withholds board data until the node's cutoff can force more contract-path receipts than any budget allows and silently drop receipted ballots whose clients have gone away (T-25, T-52, T-54).

- [[share-encryption]] (Intake and receipts) and [[delivery]]: at cast, the client gives each trustee the full ballot record, its membership proof included, with the ciphertext; spoiled ballots never reach intake, so the Benaloh challenge is unchanged.
- A trustee receipts only a ballot whose membership proof verifies against the registered tier root.
- A trustee node owes contract-path receipts only for the ballot [[revoting]] would count for each tier and nullifier, so its obligation is bounded by the electorate; state that bound and the capacity the windows support, and check it as `deliveryWindowFits` checks the windows.
- P1-18: the contract takes share receipts in batches (many signatures, one call, one forced deposit).
- Remove the residual from [[delivery]], T-25 and T-52 once closed.

MUST be done before any election registry is deployed. Board data availability (a content address per anchored segment and a publication deadline) complements it and stays with P4-3.

## Plan

1. **Membership-checked intake and the bounded obligation** (#171). [[share-encryption]] (Intake and receipts): a trustee takes the whole ballot record and runs the admission checks of [[verifier]] 5.1 to 5.4 on it, with `share-hash` before the membership proof, then decrypts. [[delivery]] (What a node owes): a node owes a contract-path receipt only for the ballot [[revoting]]'s selection picks for each tier and nullifier from its view, at most two per member of each tier. `packages/crypto`: `intakeBallot` and `owedReceipts`.
2. **Payable and complaints bounded** (waits on P1-18 part 4's direct-submit contract). The batch call for share receipts (many signatures, one call, one forced deposit); the capacity the windows leave for the bound, checked as `deliveryWindowFits` checks the windows, against each definition's actual member counts (Tier 0 identities cost a Turnstile solve, or gas on the self-paid path, so a node must refuse or flag a definition it can't pay for); a bound on complaints (a posting call that names an admitted ballot, so a node can tell which complaints can matter); then remove the residual from [[delivery]], T-25 and T-52.

## What was built (part 1)

- [[share-encryption]], Intake and receipts: intake takes the ballot record under the pinned version, and checks `delivery-malformed`, then `ballot-stray`, `ballot-tier` (`ballot-cell`), `validity-shape`, `share-hash-unqualified`, `share-hash`, `membership-proof`, `option-proof`, `sum-proof` and decryption. Before any intake the node checks the definition as a verifier does before admitting ballots, 2.4 and 2.8 included, since the recomputed member counts are what bound its obligation. The L1 reference isn't checked at intake. Notes: what a receipt now says (a registered member's ballot), the order, intake open to members rather than to anyone, and the timing residual narrowed to members.
- [[delivery]], Direct submit: **What a node owes**. Once L1 has finalized a block after close, for each (tier, ν) of a ballot it receipted, the node runs [[revoting]]'s selection over its view (its receipted ballots less those shown absent, with every ballot of that tier and nullifier it holds from the anchored board or the contract's records, each admitted and with its L1 reference admitted) and owes the selected ballot's receipt only if it receipted its ballot hash, under any L1 reference (a ballot cast again with the same core after a reorganisation keeps its receipts); nothing on a tie. It decides once, at a decision point before `c_D`, over the view it then holds, and refuses intake after it. It also owes the newest receipted ballot whose L1 reference fails (a reorganised block whose core the client cast again, when the board's copy is withheld). So at most `2 · Σ group_size_t` receipts per seat. The old "MAY skip a superseded ballot" rule is replaced. Residuals: the unbounded obligation becomes "bounded, not yet shown payable" (part 2), and a new, narrower one: a newest ballot that reached the trustees but not the board, with withheld board data, leaves the older selected ballot only its board-path receipts.
- [[ballot-validity]], Casting: step 5, the finished record goes to each qualified seat's intake.
- `packages/crypto`: `intakeBallot(election, keys, record, ciphertext)` (decodes under the election's pinned version, then `admitForIntake`, the admission checks with `share-hash` inserted, then `openShares` and the receipt), returning the ranking fields too; `intake` is renamed `intakeShares` and documented as the share half with no membership check, used only by simulations; `owedReceipts(view, l1, window)`, which throws while any L1 reference is pending. `packages/sdk`'s simulation calls `intakeShares` (its ballots carry no membership proofs, `SIMULATION_STUBS`).
- `docs/spec/vectors/intake.json` from `packages/crypto/scripts/intake-vectors.py`, an independent Python implementation reusing the ballot, ballot-v2, share-encryption and share-receipt generators, with membership proofs and pairing verdicts from snarkjs 0.7.5 over Semaphore 4.14.3's depth-32 artifacts (sha256-checked by `ballot-proofs.mjs`).
- T-25 and T-52 history.

## Tested (part 1)

- `intake.json`, 31 cases through `intakeBallot`: every seat's acceptance with its receipt, ranking fields and `M` re-made byte for byte (ballot versions 1 and 2), and a refusal at every step: `delivery-malformed` (truncated, another version, both ways), `ballot-stray`, `ballot-tier`, `ballot-cell`, `validity-shape`, `share-hash-unqualified`, `share-hash`, `membership-proof` (another L1 block, a non-member's own tree, another ballot's proof, another cell of the tier), `option-proof`, `sum-proof`, `share-proof`, `share-check`; and the order where two checks fail (`validity-shape` and `share-hash-unqualified` before `share-hash`, `share-hash` before the membership proof, the membership proof before the validity proofs and before decryption). Each accepted receipt passes `checkShareReceipt`.
- Properties: any single-byte change to an accepted record is refused; `owedReceipts` owes at most two receipted ballots per tier and nullifier, independent of the view's order, and agrees with a direct reading of the rule over views whose casts often share a ballot hash (`FC_NUM_RUNS`).
- `owedReceipts` units: the newest receipted ballot only; the newest receipted ballot whose block was reorganised away when the board's copy is withheld (from `claude-review` on #171); a receipt for a ballot hash covering its core cast again under another block after the first block failed the L1 check; one per tier and nullifier; nothing on a tie; nothing when a ballot it didn't receipt supersedes; a board copy of a receipted ballot is the same ballot; ballots with an unadmitted L1 reference neither count nor supersede; it throws while L1 hasn't passed close, and when one message names two ballot hashes; an accepted vector intake feeds it.
- The share half: `share-receipt.json` unchanged, through `intakeShares`. Crypto and sdk suites pass; `vp check` and `vp run -r check` clean.

## Known-weak (part 1)

- Not yet payable: what the windows and the L2 let a node send by `c_D` with batched receipts is part 2's, with P1-18's batch call, and so is a bound on complaints. The residual in [[delivery]], T-25 and T-52 stays until then, and MUST be closed before any election registry is deployed.
- The node's view keeps a receipted ballot it can't show absent, so with withheld board data a newest ballot that never reached the board leaves the older selected ballot only its board-path receipts (and the client's copies); It MUST be closed (P4-3's data availability) or accepted by the owner before any election registry is deployed, and is in STATUS (Known-weak). The view ignores the close rule (5.5) until P1-18 specifies it.
- A member can still make a node verify, decapsulate and store any number of their own ballots; only the node's rate limits bound that, now per nullifier if it chooses.
- `intakeShares` keeps the old membership-free intake for simulations; the sdk simulation still has no membership proofs (P1-21 part 2).

## Independent review (part 1)

In-session subagent with `.github/review/crypto-review.md`, on the complete diff:

- **Blocking, fixed:** `owedReceipts` keyed "receipted" by `M`, but a receipt is for a ballot hash. A ballot cast again with the same core after its block was reorganised away (revoting Client rule 4) keeps its first cast's receipts, so with its re-delivery blocked the node owed nothing for the selected copy, and an operator refusing its board-path receipts could drop it. The node now owes the selected ballot's receipt if it receipted its ballot hash under any L1 reference, counted before the L1 filter; spec, a unit test and a model property cover it.
- **Non-blocking, applied:** the new residual (a newest ballot that never reached the board) is a trade against main's unbounded obligation; it now MUST be closed (P4-3) or accepted by the owner before any registry is deployed, and is in STATUS Known-weak.
- **Non-blocking, superseded:** the subagent suggested the node decide again whenever its view changes; `claude-review` on #171 showed that the union of decisions is unbounded (below), so the node decides once instead.
- **Non-blocking, carried to part 2:** the bound is the electorate, which Tier 0 identities can inflate; part 2's capacity check runs against each definition's actual counts.
- **Nit, left:** `intakeShares` is exported; its name and documentation say it checks no membership and that a node never receipts with it, and the sdk simulation needs it until P1-21 part 2 brings membership proofs.
- **From `claude-review` on #171, blocking, fixed:** with board data withheld the node may hold only its own copy of a ballot whose block was reorganised away, which fails the L1 check, so it owed nothing for the copy cast again that the delivery check selects. A node now also owes, per tier and nullifier, the receipt of its newest receipted ballot whose L1 reference isn't admitted, so the bound is two per member of each tier.
- **From `claude-review` on #171, blocking, fixed:** owing the union of every decision as the view changed broke the bound (an operator releasing data, or a member getting their own ballots recorded one at a time, flips the selection). The node now decides once, at a decision point before `c_D`, over the view it then holds, and refuses intake after it.
- **Nits, applied:** vectors pinning `validity-shape` and `share-hash-unqualified` before `share-hash`; the statement check now takes the election's definition hash, not the expected statement's; a model-based property for `owedReceipts`.
