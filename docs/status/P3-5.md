## Notes

- 2026-10-12: Ponder 0.17.12, the newest release older than 7 days, doesn't run here. It loads `ponder.config.ts` through `vite-node` 1.0.2, which assumes Vite 5. The workspace overrides every `vite` to vite-plus-core (Vite 8), and the config fails to load (`__vite_ssr_exportName__ is not defined`). Pinning Vite 5 for Ponder alone would add a second Vite and esbuild to the tree. Ponder 0.18.0 (published 2026-10-06) drops `vite-node` and depends on Vite 8, so it should run under the override. Check that once it clears the release age, before writing code against it.
- Adding `ponder`, `viem` and `hono` to the catalog edits `pnpm-workspace.yaml`, which CODEOWNERS routes to the owner, so part 1's PR waits for owner review. Ponder 0.17.12 also brings in `graphql-yoga`, `@electric-sql/pglite`, `pg-query-emscripten` and `drizzle-orm` 0.41.0 next to the catalog's 0.45.3. Its tree adds about 180 packages; the PR body has to justify each.
- Part 1's plan: index the group registry's `GroupCreated`, `MembersAdded` and `MembersRemoved` events into Ponder's own schema, storing each record's bytes with its block, transaction and log index. The tier tree is rebuilt from the indexed records through `@abolishus/crypto`'s `applyGroupRecords` and `tierTreeRoot`, never in the indexer. Test it against Anvil: deploy the registry, add and remove signed batches, then check that the indexed records replay to the same tiers as the records sent. `packages/contracts` gains an `exports` entry for its generated ABI.
