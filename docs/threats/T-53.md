# T-53: Discreditation

- Area: Availability and censorship resistance (G-10)
- Adversary: A-1
- Status: **Partial by design.** Verifiability answers the claim only for people who check, or trust someone who did.

## Threat

Fake results, look-alike sites, or claims that results are forged.

## Mitigation

Anyone can verify every result; the three entry points are listed everywhere (P4-4); releases are signed.

## History

- 2026-10-11 (P1-16): anchors for the board count only within their period's window ([[board]], Timing), so a compelled or seized anchoring key can't fail a closed election by anchoring a conflicting checkpoint later. While an election runs, that key can fail it, publicly and attributably.
- 2026-10-11 (P1-16 follow-up, #37): a checkpoint that no board can match fails the election attributably (`checkpoint-inconsistent`), so an anchoring key's holder can't make an election permanently unverifiable while blaming mirrors, except through a checkpoint that extends every receipt with entries never published, or forks only after the last receipt: that is not mitigated yet, and nothing attributes it ([[board]], Residuals; P4-1, P4-3).
- 2026-10-11 (P1-17): a single bad registration can't discredit a tier's results: forbidden commitments get leaf 0 in the tier tree instead of failing the election definition ([[membership]], Commitments and removals).
- 2026-10-11 (P1-13): a ballot naming an L1 block that never comes, or an ancient one, can't keep an election unverifiable: references above the head are rejected once L1 finalizes a block after close, and ones before `l1_ref_min` by number alone ([[revoting]], Admission).
- 2026-10-11 (P1-19 part 2): the verifier's command line exits on `verdict` alone and never prints `verdictAgainstInputs` without `verdict` and the unauthenticated inputs, so a crafted bundle can't make a script or a reader take its findings as the election's verdict; 0 means verified only, and no code is one Node exits with on its own ([[verifier]], Command line).
- 2026-10-12 (P4-1 part 1): the anchoring deadline is 12 hours, an immutable value of the L1 board anchor, which refuses anchors outside the window; deployment refuses an authority without code or with only an EIP-7702 delegation, though a Safe's owners and threshold can change later and its quorum is held online by the anchoring runners. The authority (a Safe) can still fail a running election, attributably, by anchoring a checkpoint no board matches first ([[contracts]], Board anchor).
- 2026-10-12 (P1-19 part 3a): anchors read from L1 state never fail an election on their own: a missing or malformed node, an absent account, or a word that neither the copy nor a given checkpoint matches is unverifiable, and the run stays unverifiable while the header, the anchor's address and `f` are local inputs ([[verifier]], Anchors from L1).
- 2026-10-12 (P1-19 part 3c): a format-3 bundle takes the election identifier, the pinned board-entry version and the anchor's address from the election definition, so they can't disagree with the election being verified; the definition is listed as its own input, `local-file` until 2.1 checks its hash against the L2 registry, so the run stays unverifiable ([[verifier]], Definition).
- 2026-10-12 (P1-19 part 4a): the key-ceremony checks never fail an election on unauthenticated inputs: the panel a format-4 bundle gives is a local input, so the verdict stays unverifiable, and a copy without the transcript leaves 3.1 unverifiable, never failed ([[verifier]], Key ceremony).
- 2026-10-13 (P4-3 part 2a, [[0029-board-data-availability]]): decided, not built. Checkpoint version 2 names each segment's CIDs on L1, and before any result each trustee panel's threshold of seats must attest through the L2 contract path that it held the ballot extent by `c_I` and the counted extent before any summed share, or the election fails `unavailable`, listing who attested, complained or did nothing. Withholding becomes a verdict anyone reproduces from L1 and the L2's events, never one that depends on a verifier's network, which a reachability rule would have made a discreditation route.
- 2026-10-13 (P1-18 part 4b-3d-2, [[contracts]], Contract-event record, What the board frames): the version-2 event check runs only the board's own checks that need no election, framing a ballot's elements as the board does and never decoding them, so a member's ballot the board accepts and the verifier rejects passes the event check and can't fail every election through the board's shared sequence. Until the registry refuses a profile pinning version 1, an election pinning it fails 4.4 at its first board event (Known-weak there).
- 2026-10-13 (P1-18 part 4c-2a, [[close]]): `k` seats stating a low close head, or `k` seats with one liar and the rest silent, can fail an election (`close-contested`), as `k` seats refusing the tally can; fewer can't, and no statement changes which ballots count. A false `L_δ` and equivocation are attributed to their seat for good; a claim below a permissionless game's floor is reported and still counts, so no false game can change the head. A compelled sequencer that withholds the batches of the last minutes before close past `L_δ` can fail an election whose result a ballot in them would change, unattributed (adversary 1); relaying near close is the client's answer.
- 2026-10-13 (P1-19 part 4k, [[verifier]], Contract events): 4.4's event check fails the election only at a record inside the extent 4.1 and 4.2 authenticated; past it no record is read, and on a copy the board checks don't authenticate a failing record leaves 4.4 unverifiable with its code, so no mirror can fail an election by appending or serving a contract-event record. Only the operator boards these records, and every log the release contracts emit passes the check.
- 2026-10-13 (P1-18 part 4c-2b-2a): the election registry caps a definition's `sequencing_window` and `max_sequencer_drift` at Base's current values ([[parameters]]), with no headroom, so an L2 governance raise of either during a poll fails every open poll at [[verifier]] 2.6, unattributed, until a registry with new ceilings is deployed.
