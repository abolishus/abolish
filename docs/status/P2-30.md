# P2-30: Account-gated Tier 0 registration

- State: todo
- Phase: Phase 2: Open polls end to end at Tier 0

## Scope

The owner's decision of 2026-10-21 ([[0024-tier0-registration]], Owner decision): voting needs an account, and an account registers at most one Tier 0 voting identity per group, through blind-issued tokens, so the server never learns which identity belongs to which account.

## Rules

- Inside the `crypto-review` gate where it touches the token protocol, `packages/crypto`, `packages/core`'s checks or the ballot client.
- The ballot client blinds and unblinds; `apps/web` only relays with the account's session. Nothing stores or logs an account next to a token's unblinded value, a commitment or its timing; redemptions are delayed and batched so timing can't join them (T-10, T-11).
- The issuer key is rotated by period and its compromise is a new threat entry (it mints Tier 0 identities).

## Plan

1. Spec and vectors: VOPRF issuance and redemption (RFC 9497, as Privacy Pass, RFC 9578) bound to the group and period, with independent vectors.
2. `packages/crypto`: blind, evaluate, unblind, verify.
3. The issuer in `packages/core` and `apps/api`: one token per account per group, only to an account verified by email and phone ([[P2-31]]); key, rotation, rate limits.
4. `apps/web`'s relay and the ballot client's blinding, the cross-origin handoff, and redemption on the registration request in place of the Turnstile solve.
5. The signing service checks a redeemed token, with delay and batching; the T-10 and T-11 tests.
6. Migration of the registration screens ([[P2-8]]) from Turnstile-only to account-gated.
