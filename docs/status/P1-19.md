## Scope

`packages/verifier` CLI: download the board (from local files first), recompute and check everything, and check a served ballot client against a signed release. Spec in `docs/spec/verifier.md`. Per [[0005-permanent-archive]]: check the archived event sequence against each contract's event accumulator using archived storage proofs at output roots (reporting whether each root settled by TEE-only or ZK proof), walk the manifest chain and every anchor's `archiveLocator`, and pass with Arweave or IPFS unreachable.

## Built on #40

The verifier imports `@abolishus/crypto`, the first import between workspace packages. Crypto's `exports` point only at `dist/` (gated.ts), so CI builds crypto first; #40 (`ci:`) added that build to the setup action and before the gated check, and has merged.

## Known-weak

- **The L1 header is a local input** (part 3a). Anchors read from L1 are only as good as the header, the anchor's address and `f`, all local files until part 3b, so no run is verified or failed through them yet. The report gives the block's hash so a user can compare it with a node they trust.
- **A crafted `f` or clock still costs some time** (part 3a): until they are pinned, a bundle chooses how many slots are read, up to `2^20` (about a second here) before `l1-range-too-long`. Under a short testnet period an honest election reaches that bound sooner (about 12 days at 1 second), and is then unverifiable, never failed. It changes no verdict.
- **A wrong address holding some other contract reads as no anchors** (part 3a), so `unanchored` against the inputs; harmless while the address is a local input, and closed when part 3b pins it and 1.2 checks its code.
- **Extension and embedded trie nodes are tested only on hand-built tries** (part 3a): the Anvil tries in the vectors are too small to contain them.

- **No verdict yet.** Every input is a local file and most checks aren't implemented, so every run reports `unverifiable`. That is by design, not a gap in what's built.
- **The summary for authenticated inputs is untested.** It can't be reached while `local-file` is the only input source; part 3, which adds the first authenticated source, must test the one-line `verdict:` summary.
- **No installed binary yet.** The command line runs from a checkout (`src/bin.ts`); packing it and declaring `bin` need a `ci:` change to `gated.ts`, then a follow-up.
- **Anchored encodings `board.bin` can't carry.** If an operator anchors an entry that doesn't split back into itself (bytes past its payload), every copy is short or mismatched, and the election stays unverifiable for good, never failed. This is a residual in [[verifier]], Bundle, with the same candidate fix as [[board]]'s withheld tails: anchor a content address of each segment object (P4-1, P4-3).
- **An anchored oversize entry is hashed in full** (up to 4 GiB) before 4.1 rejects it. Only the anchoring authority or a mirror within the anchored extent can cause this, and it costs time, not the verdict (T-52).
- **`board.bin` is split by the version-1 layout.** An anchored entry in another layout (no other version exists) would leave the copy unsplittable or mis-split: unverifiable from that copy, never a failure. If a version 2 changes the layout, splitting must follow the pinned version.
