# T-31: Encoding ambiguity and parser differentials

- Area: Integrity and verifiability (G-7, G-8, G-9)
- Adversary: A-2, A-9
- Status: **Partial** (P1-2 accepted by the agent, owner may veto: explicit byte layouts). P1-10 built the primitive codecs and framing; record layouts and the Solidity and Noir consumers are still missing.

## Threat

Two byte strings decode to the same value, or two implementations decode the same bytes differently, so a hash, signature or anchor commits to something other than what a verifier checks.

## Mitigation

Canonical encodings defined in `docs/spec/`, hand-written strict decoders that reject non-canonical forms, round-trip property tests, and cross-language vectors consumed by TS, Solidity and Noir (P1-2 ADR, P1-8, P1-10). No schema library defines protocol bytes.

Built so far (P1-10): the strict primitive codecs, record framing and `DS` framing in `packages/crypto`, tested against `docs/spec/vectors/primitives.json` and with fast-check round-trip and rejection properties. Not yet: record layouts (P1-10b onwards), and the Solidity and Noir consumers of the vectors (P1-18, P1-17). Until those exist, a misreading shared by the spec and the TypeScript code goes undetected.
