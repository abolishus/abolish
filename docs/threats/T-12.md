# T-12: Cross-poll linkability

- Area: Ballot secrecy, unlinkability and privacy (G-3, G-4, G-5, G-12)
- Adversary: A-10
- Status: **Planned.** Residual: a published Benaloh opening (opt-in, sent after close, canonically ordered) can still be linked to its voter through network metadata (T-11), and usually shows the voter's real choice ([[verifier]] check 6.2).

## Threat

Nullifiers, identity commitments or proof data link one voter's ballots across polls.

## Mitigation

Semaphore nullifiers are scoped per poll and tier group, from the election-definition hash (which binds the chain, contracts and election), the tier and the tier's root under the `abolish/v1/nullifier-scope` tag, and unlinkable without the secret ([[membership]], Scope); ballots carry no stable identifier. A test asserts no on-chain data links a member to any poll (P3-2).

## History

- 2026-10-11 (P1-17): scope specified and built (`nullifierScope` in `packages/crypto`, vectors in `membership.json`).
- 2026-10-12 (P3-2 part 1): the group registry takes no election identifier, definition or nullifier; an addition names a group, a position and commitments only, so nothing on chain joins a member to a poll ([[contracts]], Group registry, Verification).
- 2026-10-12 (P1-17b part 2): the pinned membership proving key's reference string is checked well formed ([[membership]], Reference-string check), so a membership proof reveals nothing about the voter's leaf or secret beyond the public signals, whoever ran Semaphore's ceremony.
- 2026-10-17 (P3-2 part 5a, [[registration]], The direct path): the address that pays a self-paid Tier 0 addition sits on L2 next to the commitment, so the client MUST use it for that addition alone, never for a ballot, posting, receipt, complaint or later registration, nor any address funded from or to it.
