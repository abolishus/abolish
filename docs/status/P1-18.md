# P1-18: `packages/contracts` scaffold

- State: in progress (part 2: election registry, #52; part 1 merged in #38)
- Branch: `claude/p1-18`

## Scope

`packages/contracts` scaffold (Foundry 1.8.3): an immutable bulletin-board contract, election-definition registry, trustee key registry and direct-submit path; fuzz + invariant tests; PII-ban tests; wagmi bindings. Per [[0005-permanent-archive]]: each contract keeps an on-chain running hash and counter of its own events, and the anchor carries a generic, versioned `archiveLocator`.

## Plan

The item is built in parts, each its own PR on this branch's name:

1. **Scaffold and event accumulator** (this part). The Foundry package, reproducible build settings, and the event accumulator every contract inherits: [[contracts]], `abolish/v1/event-accumulator`.
2. **Election registry.** Write-once definition hashes, with `election_id` assigned from the chain ID, the registry's address and its counter ([[board]]). This waits for P1-10b (#35), which fixes the definition, its stub hash and the registry rules.
3. **Trustee key registry.** Waits for P1-14, which waits for the owner's ML-KEM question ([[0002-everlasting-privacy]]).
4. **Direct submit** and the contract-event record `0x0008` with its inclusion evidence. These wait for P1-12's ballot format (owner questions) and P1-17's membership proof.
5. **wagmi bindings**, once there is a deployable contract. This adds `@wagmi/cli` as a dev dependency, justified in that PR.

## What was built (part 1)

- [[contracts]], Event accumulator:
  - genesis is `H(DS(tag, u8(0) ‖ u64(chain_id) ‖ address))`;
  - each step is `H(DS(tag, u8(1) ‖ acc ‖ u64(n) ‖ u8(k) ‖ topics ‖ u32(len(d)) ‖ d))`;
  - the values sit at the ERC-7201 slot `abolish.event-accumulator`;
  - every log goes through it, no anonymous events.

  The tag `abolish/v1/event-accumulator` is now specified.

- `packages/contracts`:
  - `foundry.toml`: solc 0.8.30, EVM `cancun`, optimizer at 200 runs, no metadata hash or CBOR, no cache. The `ci` profile runs 10,000 fuzz runs and 512 × 64 invariant runs;
  - `EventAccumulatorLib` and the abstract `EventAccumulator`, with `_log1` … `_log4`;
  - a TypeScript source-rules test.
- `packages/crypto`: `eventAccumulatorGenesis`, `eventAccumulatorStep` and `replayEventAccumulator`, for the verifier's 4.4 replay (P1-19).

## Tested

- `docs/spec/vectors/event-accumulator.json`, from an independent Python implementation (`packages/crypto/scripts/event-accumulator-vectors.py`, hashlib only). It has 4 genesis vectors, 5 sequences (1 to 5 events, every topic count, odd data lengths, a repeated log, another address) and 4 rejected inputs. TypeScript and Solidity both check every vector.
- TypeScript:
  - a hand-written genesis input;
  - fast-check properties (passing at `FC_NUM_RUNS=1000`): dropping, altering or swapping any log changes the accumulator; another chain or address changes it; moving bytes between topics and data changes it;
  - malformed arguments are rejected, and inputs aren't aliased.
- Solidity:
  - the vectors through the library;
  - deployment stores genesis under several chain IDs, and a chain ID above `u64` reverts;
  - a fuzz test replays the logs the EVM actually recorded and compares the getter and the raw storage slots;
  - a typed event decodes with the standard ABI;
  - a reverted call leaves no trace, and 0 or 5 topics revert;
  - an invariant suite: the stored values equal the shadow replay of exactly the successful logs, the count never decreases, and the values sit at the slot.
- Mutation checks, run by hand: changing the step's prefix byte fails the vector tests, and skipping the accumulator in `_log1` fails the replay fuzz test and the invariant. Adding an `emit` to a contract in `src/` fails the source-rules test.
- Two builds in different directories produce byte-identical `out/`.

## Tested (part 2)

- `docs/spec/vectors/election-registry.json`, from an independent Python implementation (`packages/crypto/scripts/election-registry-vectors.py`, hashlib only): 6 identifiers and 2 inputs with no `u64` encoding. TypeScript and Solidity both check them.
- Solidity runs all 59 vectors of `election-definition.json` through the contract's decoder: each rejected one with its decode error code, each accepted one with its hash, stub hash and well-formedness label, and a test encoder re-encodes every accepted one byte for byte.
- One unit test per admission rule, each with a definition that breaks only that rule (all eight deployment fields, the epoch and opening boundaries, a root at the registering block, a ceremony recorded for another stub with the same transcript hash), plus a repeated transcript hash across two elections being allowed, and four non-canonical calldata forms (trailing word, dirty padding, offset `0x40`, offset 0 with a junk word).
- Fuzz: any one-bit change to an approved definition is refused; arbitrary bytes are refused.
- Invariant suite (several creators, registrations from any account, second definitions): the count equals creations, identifiers are the derived ones, creators and definition hashes match a shadow and never change once set, a registration succeeds exactly when its caller is the creator and none exists, and the accumulator counts every event. Passes under `FOUNDRY_PROFILE=ci`.
- Mutation checks by hand: dropping the write-once, creator, epoch or opening check, letting a root sit at the registering block, widening the tier enum, accepting a root equal to `r`, loosening the profile pin rule, dropping the distinct-roots rule, mis-slicing the stub, or dropping the calldata offset, padding or length checks each fail a test.

## Known-weak

- **solc is fetched by forge at build time**, from binaries.soliditylang.org. It is checked against the checksum list built into the hash-pinned forge binary, but `install-toolchain.sh` doesn't pin it itself. A `ci:` follow-up should install solc 0.8.30 with its sha256 next to forge.
- **No contract that emits result-affecting events exists yet.** The accumulator protects nothing until the registries and direct submit use it (parts 2 to 4).
- **The source-rules test is a text scan.** It strips comments and strings, but Yul in an unusual form, or an `emit` built by other means, could slip past it. The replay fuzz test and the invariant check the real logs of the harness only.
- **No gas snapshot yet.** The contracts skill asks for `forge snapshot --check` on hot paths. The election registry runs once per election (about 98,000 gas to create, 115,000 to register), so it isn't one; the snapshot comes with direct submission (part 4), the first hot path.
- **The election registry's ceremony check is tested against a stand-in** until the trustee registry (part 3) exists, and its timing fields have no close-rule bounds until part 4. Nothing may be deployed before both ([[contracts]], Election registry).
- **solc pin (follow-up `ci:` PR).** It should also set `offline = true` in `foundry.toml` once `install-toolchain.sh` installs solc, before any deploy script lands.
- **forge-std isn't vendored.** The tests declare the few cheatcodes they use by hand (`test/utils/Vm.sol`).
