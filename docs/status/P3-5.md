## Scope

`apps/indexer` (Ponder), including direct-submitted ballots.

## Plan

1. **The scaffold and the group registry** (this part): `apps/indexer` on Ponder 0.18, storing `GroupCreated`, `MembersAdded` and `MembersRemoved` verbatim, and `readIndexedGroups` for readers, who replay the records through `@abolishus/crypto`'s `applyGroupRecords`.
2. **Completeness and the board's events** (2a, the group registry's logs as emitted, and 2b, the other contracts): store each log's raw topics, data and block timestamp and every event the contracts emit (`RegistrarsPinned` included), so a reader can check the index against the event accumulator's storage proofs ([[contracts]], Event accumulator); then the board's events, including direct-submitted ballots (T-25), stored as the contract-event records the verifier reads ([[0025-contract-event-evidence]]), and the election and trustee registries'.
3. **Readers**: the API and worker reading the index where they now read nothing from the chain (P2-3's L1 reference, P3-6's per-tier results), each rechecking what it reads.

## Part 1

- Built: `apps/indexer` (`ponder.config.ts`, `ponder.schema.ts`, `src/index.ts`, `src/env.ts`, `src/records.ts`, an empty `src/api/index.ts`, which Ponder requires); `packages/contracts` exports its generated ABI as `@abolishus/contracts/abi`.
- Dependencies: `ponder` 0.18.0, `viem` 2.57.3 (already in the tree through `@wagmi/cli`) and `hono` 4.13.13 (already in the tree), Ponder's peers. Ponder adds 112 packages, among them `graphql-yoga`, `pg`, `pino`, `drizzle-orm` 0.41.0 (beside the catalog's 0.45.3), `@electric-sql/pglite` and `pg-query-emscripten`, none with an install script. The catalog change routes the PR to the owner (CODEOWNERS).
- Independent review (in-session, `crypto-review` checklist): nothing blocking. Applied: the threat and status text no longer claim a corrupted row always fails a replay (a deleted removal or tail doesn't); `reorgWindow` set to Ponder's maximum and its wall-clock finality documented; both reads in one repeatable-read snapshot; event IDs ordered bytewise (`collate "C"`); a non-hex record fails as corruption; tests for a reordered row and a dropped removal. Left for part 2: storing raw logs and `RegistrarsPinned` for the accumulator check.
- Tested: on Anvil, records sent through both Ponder's backfill and its live indexing replay, under the pinned registrars, to exactly the leaves sent, an empty group included; a wiped index, with Ponder's RPC cache dropped, is rebuilt from the chain to the same result; under another registrar set every group's history fails at its first record; a reordered row fails and a dropped removal still replays; the deployment's parser refuses malformed values (property tests).
- Known-weak: the index trusts its L2 node for which logs exist, and anyone with write access to its database can delete rows: a dropped removal or a dropped tail of additions still replays, to another tree, and no reader checks completeness yet (the verifier's accumulator check does; part 2 stores what readers need for it). Ponder's finality is a wall-clock window (600 s, its maximum), not the L2's safe head, so a reorganisation of the unsafe chain after it leaves orphaned records that still replay; readers must treat rows above the safe head as provisional. Ponder's tree is large for what it does here, and runs in the indexer's process with the database credential; its RPC cache lives in Postgres schemas of its own beside the index, and the test drops every `ponder_` schema in the test database.

## Part 2a (#269)

- Built: `contract_log` in `ponder.schema.ts`, every log the group registry emits as emitted (contract, block number and timestamp, topics, data), the constructor's `RegistrarsPinned` included through a handler of its own; `readContractEvents` in `src/records.ts` returns a contract's rows as contract-event records (`0x0008`), `n` being each row's position in chain order rather than a stored number, so a deleted row shifts every later `n` instead of leaving a gap. Ponder's backfill returns a cached log's topics padded to four with nulls; the handler cuts them at the first null.
- Tested: on Anvil, every indexed log (from the backfill, live, and after the index and RPC cache are wiped and rebuilt) round-trips through the record's codec, passes `checkContractEvent` under version 2 with the registry's role, starts with `RegistrarsPinned`, and passes `checkEventAccumulatorProof` against the registry's accumulator and count read from storage at the head, the slots derived in the test from the spec's ERC-7201 namespace. A dropped log (the removal replay misses), a dropped middle log, an altered log and a log moved to the next block fail; a row deleted from the index itself fails as `accumulator`; an index longer than an older block's proof still checks.
- Known-weak: the check runs only in tests, against storage read from the node; no production reader runs it yet, and a reader must prove the two slots under an output root itself (part 3; the verifier's 4.4 is its own). Only the group registry is indexed: the board's and the election and trustee registries' events, direct-submitted ballots among them, are part 2b. `group` and `group_record` are still written beside `contract_log` rather than derived from it, so the two can disagree in a tampered index; readers that check completeness should read `contract_log`.

## Part 2b (#310)

- Built: the indexer reads all four L2 contracts (`ELECTION_REGISTRY_*`, `TRUSTEE_REGISTRY_*`, `GROUP_REGISTRY_*`, `BOARD_*`, each address and start block, the addresses distinct). `src/events.ts` subscribes to every event of each contract's generated ABI, since Ponder fetches only the logs of handled events: every log of every contract lands in `contract_log`, and an event a later contract version adds is indexed without a new handler. `group` and `group_record` are still written for the group registry.
- Tested: on Anvil, the four contracts deployed (the board reading its registries through `BoardFixture`'s stubs set from `ballot.json`, the election registry with `MockL1Block` at the predeploy); elections created and `ballot.json` ballots submitted directly to the board, before the backfill and live. Each contract's indexed logs frame, pass the event check under version 5 with their role, name the events sent in order and replay to the contract's stored accumulator and count, from the backfill, live and after a rebuild; the board's logs are exactly the ballots submitted. Mutation: without the board's `BallotSubmitted` handler the test fails. `tests/events.test.ts`: every ABI event subscribed once, covering the newest contract-event table for each role.
- Known-weak: only `PanelPinned`, `ElectionCreated` and `BallotSubmitted` among the new contracts' events are produced on Anvil; the others (ceremony and definition registrations, the board's receipts, postings, complaints, batches, roots, relayed ballots and close statements) go through the same handler and are proven subscribed, not emitted. The board reads stub registries in the test. No production reader proves the accumulator slots yet (part 3). No deployment sets the indexer's variables yet.
