# T-01: Sybil accounts at Tier 0

- Area: Eligibility and Sybil resistance (G-1, G-2)
- Adversary: A-1, A-9
- Status: **Not mitigated** (by design: Tier 0 is open polling). Tier 0 results must be labelled as not Sybil-resistant everywhere they appear.

## Threat

Passkeys are free; anyone can register many Tier 0 identities.

## Mitigation

Results are always reported per tier, so Tier 0 is never presented as one-person-one-vote. The verifier enforces the labels: each ballot is tallied in the cell of the tier it proved, and each tier's root comes from that tier's own group additions, attributed by an authorisation that binds the tier, so a signed batch can't be replayed into another tier (verifier 2.4, 2.8). Operator stuffing of Tier 0 and Tier 1 groups is T-06. Turnstile and rate limits raise the cost (P2-5).

Index: [[THREAT_MODEL]].

## History

- 2026-10-10 (P0-ops-8): per-tier labels enforced by verifier 2.4 and 2.8, so a definition can't relabel one tier's aggregate as another's.
- 2026-10-12 (P2-5 part 2): Turnstile now gates every passkey ceremony start, so each Tier 0 account costs a solved challenge. This raises the cost of a sock-puppet account; paid solving services keep it low, so Tier 0 stays labelled not Sybil-resistant. Tier 0 group registration doesn't exist yet; when it does (P3-2) it must check a token with the same `createTurnstile`.
- 2026-10-12 (P3-2 part 4a, [[0024-tier0-registration]]): Tier 0 registration needs no account. Each registration is paid for by its own Turnstile solve on the ballot path, the same cost as an account (or, through the self-paid path of P3-2 part 5, by its own gas, which costs less), so tying registration to accounts would add linkage without adding cost. Still Not mitigated; Tier 0 stays labelled not Sybil-resistant.
- 2026-10-13 (P2-17 part 1, [[membership]], Rolling tier tree and Scope; [[election-definition]], Layout (version 7)): rolling everyday polls take one scope per tier with no root in it, so one secret has one nullifier across every step, group and leaf, and a tier counts at most one ballot per registered secret over the poll's span. Tier 0 identities can now be registered during a poll, after its question and totals are public: still **Not mitigated**, and civic polls can't be rolling (`rolling-class`).
- 2026-10-14 (P2-17 part 2b-1, [[membership]], Reported counts; [[verifier]] 8.1): a rolling tier's growth is reported per anchoring period (leaves added and removed, members at the period's end), and a rolling Tier 0 result is labelled as open to new identities during the poll. A Sybil flood shows as a shape anyone can see, but nothing tells it from a genuine surge: still Not mitigated at Tier 0.
- 2026-10-22 (P2-30 part 1, [[0039-tier0-token-issuance]]): voting at Tier 0 will need an account's blind-issued token, one per account for the group of its region, so a Tier 0 identity costs a verified account ([[P2-31]]); accounts and tokens can still be bought, so Tier 0 stays labelled not Sybil-resistant.
