# @abolishus/admin-cli

The operator's command line. Internal and source-only; AGPL-3.0-only. Commands parse their arguments, call `@abolishus/core` and print one JSON object per line on stdout (refusals on stderr), so a person or an agent can drive it. No domain logic lives here.

## Moderation

`docs/moderation-policy.md` (T-68, T-52). Until the owner names moderators, the operator of the deployment is the only one, so the tooling is this command line on the operator's own database connection, not a page anyone can reach.

| Command                                                                                                                                                         | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `moderation queue [--limit 1..1000] [--after <next>]`                                                                                                           | Polls and grounds with unreviewed reports, longest waiting first (`readReportQueue`). A full page ends with `{ "next": … }`; pass it as `--after` for the next page.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `moderation review <election-id> <reason> <seen-total>`                                                                                                         | Marks reviewed the first `seen-total` reports, the `total` the queue showed (`reviewReports`), so a report counted since stays pending. Records no decision.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `moderation decide <election-id> <delist\|hide\|restore> <reason> --moderator <handle>`                                                                         | Records a decision (`moderate`). Core refuses, with nothing written: `invalid`, `unknown-election`, `unknown-moderator` (a handle never added, or retired), `own-poll` (the handle's account created the poll), `appeal-only` (a restore citing `appeal-upheld`, which only `appeal-decide` records), `open-poll` (hiding an open poll on a ground other than `illegal`, `personal-data` or `threat`), `no-change`.                                                                                                                                                                                                                                                          |
| `moderation refile <election-id> <reason> (--topic <topic> \| --no-topic \| --keep-topic) (--place <place> \| --no-place \| --keep-place) --moderator <handle>` | Refiles a poll's listing tags (`refilePoll`; docs/moderation-policy.md, Refiling). Each tag needs one of the three: set, cleared or kept as the poll is filed under it now, read under the lock, so a hidden poll's withheld place can be kept unseen and leaving a tag out never clears it; keeping both is refused (`invalid`). The reason is `misfiled` or a removal ground the place breaks. A place is filed as typed: NFC, single-spaced, at most 80 characters, no control, bidi or invisible characters (else a usage error). Prints the log sequence number, never the place. Refused: `invalid`, `unknown-election`, `unknown-moderator`, `own-poll`, `no-change`. |
| `moderation status <election-id>`                                                                                                                               | The poll's state and its newest decision, without the moderator.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `moderation log [--after <seq>] [--limit 1..1000]`                                                                                                              | The public log, as `GET /moderation/log` serves it: no moderator.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `moderation moderator-add <handle> <account-id>`                                                                                                                | Gives an account its moderator handle (`addModerator`), so `decide` can refuse a decision on the moderator's own poll and an appeal goes to someone else. Refused: `invalid`, `unknown-account`, `handle-taken` (handles are never rebound), `already-moderator`.                                                                                                                                                                                                                                                                                                                                                                                                            |
| `moderation moderator-retire <handle>`                                                                                                                          | Retires a handle for good (`retireModerator`); deleting its account does the same. Refused: `unknown-moderator`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `moderation appeals [--limit 1..1000] [--after <seq>]`                                                                                                          | Open appeals, by the appealed decision's sequence number (`readAppealQueue`): the poll and the decision, never who appealed. A full page ends with `{ "next": … }`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `moderation appeal-decide <decision-seq> <upheld\|rejected> --moderator <handle>`                                                                               | Reviews an appeal (`decideAppeal`). Upheld records a `restore` citing `appeal-upheld`; rejected writes nothing to the log; either is `superseded` if a later decision changed the poll's state since. Refused: `not-found`, `reviewed`, `unknown-moderator`, `same-moderator` (the handle made the decision, or re-cited the removal since), `own-poll`.                                                                                                                                                                                                                                                                                                                     |

Election IDs are 64 lowercase hex digits, their one spelling (T-31). An option given twice is a usage error, never its last value. Exit codes: 0 done, 1 refused by core (`{ "error": code }`), 2 malformed arguments (with the usage), 3 any other failure, such as an unreachable database (`{ "error": "internal", "kind": … }`, the error's name only, since its message can name the database's address).

## Simulations

`docs/status/P1-21.md`. A scenario is JSON (see `@abolishus/sdk`'s README), given inline or as a file; these commands need no database.

| Command                                                                                                                    | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `simulation plan (--scenario <json> \| --file <path>)`                                                                     | The plan the seed fixes: ballots cast (re-votes' earlier ballots included), how many went direct during the outage, how many the re-vote rule supersedes, how many voters challenge an attempt first and how many of those publish its opening, and each tier's expected counts, with each question's slice of them for a `questions` scenario. No cryptography; instant.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `simulation run (--scenario <json> \| --file <path>) [--progress] [--workers <n>] [--bundle <dir>] [--placeholder-proofs]` | Runs the election through the protocol code and prints the report (`ok`, the definition's and ceremony transcript's hashes, the ballots cast, direct, superseded, challenged and published, each cell's outcome and counts against the plan (for a `questions` scenario, each question's expected and opened counts too, and no figure across questions), the board and its anchors, packages/verifier's report over the closed election, and the stubs). With `--progress`, about a hundred `{ "progress": … }` lines before it. `--workers <n>` runs the trustee seats' intake, most of a run's cost, in `n` worker threads (0 to 64; 0, the default, in this thread); the report is the same. `--bundle <dir>` writes the closed election's verifier bundle (format 4: `bundle.json` and `board.bin`, docs/spec/verifier.md, Bundle) into `dir`, which must not hold either file yet, before the verifier judges it. Every ballot's membership proof is made by the ballot client's own prover (`@abolishus/membership-prover`, over the vendored key and calculator in `packages/membership-prover/artifacts/`), a few seconds per ballot, so the verifier admits every ballot; `--placeholder-proofs` skips proving for a quick run whose ballots the verifier rejects for their placeholder proofs. |

A malformed scenario is a usage error naming the field (exit 2). A run whose cells differ from the plan prints the report, then `{ "error": "simulation-mismatch" }` (exit 1).

## Tier 0 token keys

`docs/runbooks/tier0-token-keys.md` (T-74). The issuer's keys are made on the operator's own machine; these commands need no database.

| Command                                                                     | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tier0-keys period [--at <ISO time>]`                                       | The key period now, or at that time (ISO 8601 with `Z` or an offset): its number, when it starts and ends, and when its key stops redeeming (`redeemsUntil`).                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `tier0-keys generate --from <period> --count <1..16> --dir <dir> [--first]` | A fresh key for each of `count` periods from `period` (`generateTier0IssuerKey`), each written as its `TIER0_ISSUER_KEYS` entry to a new owner-only file `tier0-key-<period>.txt` in `dir`; each synced before it prints that period's times, `publicKey` and `keyId`, never the key; a failed write is `key-unwritable` after the lines of the periods already written. Refused, with nothing written: `period-started` (a period that has begun; `--first` allows the current one, for the first release only), `key-exists` (a file for one of the periods), `no-directory`. |

## Deployment record

[[deployment]] (record `0x0020`; P2-32 part 2a; T-34, T-37, T-71, T-64). Offline: it reads three files and no chain.

`deployment record --l1 <file> --l2 <file> --inputs <file>` builds the deployment record (`buildDeploymentRecord` in `@abolishus/core`) from the deploy script's two chain files (`packages/contracts/deployments/<chain-id>.json`) and the owner's inputs, and prints `version`, `record` (its encoding in hex) and `deploymentHash` (hex). The chain files give every address, the anchor's clock and authority, the portal, the commit, the registrars and the launch panel (its kind, threshold and keys, checked against the identifier the trustee registry computed). They must be one deployment: the same target, commit and deployer, each naming the other's chain, board, anchor, relay and epoch, and each contract at its deployer's CREATE address for its place in the script's order. The inputs file is a JSON object with exactly these keys:

| Key                                            | What it is                                                                                             |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `l2FromBlock`                                  | A block at or before the four L2 contracts' creation, as a decimal string                              |
| `l2MaxSequencerDrift`                          | The L2's `max_sequencer_drift` in seconds (1,800 on Base)                                              |
| `disputeGameTypes`                             | The dispute-game types counted as permissionless, the verifier release's pin                           |
| `ours`                                         | One boolean per launch-panel seat, in seat order: whether we hold it                                   |
| `groups`                                       | The published groups: `{ groupId` (decimal string), `tier` (0 or 1), `selfPaid`, `region }`            |
| `api`, `l2Rpc`, `l1Rpc`                        | Each a list of origins                                                                                 |
| `backupRpId`, `backups`, `accountRpId`         | The backup passkey's RP ID, whether the client offers a backup, and `apps/web`'s RP ID                 |
| `membershipZkeySha256`, `membershipWasmSha256` | The membership prover's hashes, `0x` and 64 hex digits                                                 |
| `tier0TokenKeys`                               | `{ period, key, retired }` from `tier0-keys generate`'s `publicKey`; empty for a version-1 record      |
| `seatRelays`                                   | `{ key, relays: [{ origin, path }] }` per seat with a relay; empty for a version-1 or version-2 record |

The version is the lowest that carries the inputs. Lists the spec orders are put in order; anything repeated still breaks its rule. Refused (exit 1): `unreadable` or `malformed` with the file (`source`: `l1`, `l2` or `inputs`) and the JSON `path` of the first bad value; `mismatch` with `what` the two chain files disagree on; `address` with the `contract` not at its CREATE address; `panel-id` (the launch panel's keys and threshold aren't its identifier's); `seats` (`ours` isn't one per seat); `ill-formed` with crypto's first broken rule as `failure`.

## Running

From `apps/admin-cli`: `vp node src/main.ts moderation queue` with `DATABASE_URL` (a user granted `abolish_app`, never the owner). Only the moderation commands read it; a missing or malformed one is refused as `{ "error": "database-url" }` (exit 1).

## Tests

`vp run --filter @abolishus/admin-cli test` needs `TEST_DATABASE_URL`, and runs uncached. Each run gets its own schema.

## Known-weak

- The policy's rule that a moderator doesn't decide on a poll they created or have a stake in isn't checked: nothing records who created a poll yet (P2-9), and handles aren't tied to accounts (T-10).
- `--moderator` is whatever the operator types; mapping handles to people is the operator's.
