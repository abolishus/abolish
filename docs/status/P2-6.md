# P2-6: Voting identity

- State: in progress (part 1: [[0017-identity-recovery-backup]], in review)
- Branch: `claude/p2-6`
- Phase: Phase 2: Open polls end to end at Tier 0

## Scope

Voting identity: a device-held Semaphore secret, encrypted with a WebAuthn PRF-derived key for recovery.

## Plan

The item is built in parts, each its own PR on this branch's name:

1. **ADR** (this part): [[0017-identity-recovery-backup]]. Where the encrypted copy lives, which credential the PRF comes from, and how a new device finds the copy (T-20, T-10, T-18).
2. **Spec and `packages/crypto`:** `docs/spec/identity-backup.md` with the PRF salt, the HKDF tags, the fixed-length plaintext record, the envelope and its strict decoder, the locator id and the recovery code; the `packages/crypto` API the ballot client calls; cross-language vectors from an independent implementation. Uses RFC 8439's ChaCha20-Poly1305 from `@noble/ciphers`, which P1-12 part 2 (#58) adds, so it starts once #58 merges.
3. **Storage:** the operational table in `packages/core` (no account column, classed in the T-10 no-join test), the ballot-path procedures in `packages/api-contract` and `apps/api` (put, get and delete by locator, fixed body size, no session), a test that a request carrying an account cookie or token is refused, and the expiry rule.
4. The ballot client's flows (create the backup passkey, back up, recover, offer the recovery code) come with [[P2-8]], which also tests that the ballot host's `/.well-known/webauthn` lists no `apps/web` origin.

## Open

- Revoking a stolen identity and re-registering (T-18) has no design yet. At Tier 2 the uniqueness nullifier lets one document register once, so a voter who loses the device and every backup loses Tier 2 until it exists. It needs its own ADR, after P3-2.

## Part 1

- [[0017-identity-recovery-backup]]: option A (a separate backup passkey on the ballot client's RP ID, an envelope stored by us under a PRF-derived locator through the ballot path), with option B (a recovery code, nothing stored) where the PRF is unavailable. Option C (keyed by account, with the account passkey's PRF) is rejected for T-20. `Accepted (agent) — owner may veto`.
- T-20 moves from Needs design to Planned (file and index row); history entries in T-10, T-18 and T-20.
- Tested: `vp check`; in-session subagent review with the `crypto-review` checklist (the ADR fixes the privacy model of a protocol secret).
- Known-weak: nothing is built yet. Anyone can write backup rows (flooding bounded only at the proxy, T-52), a database wipe loses every backup (T-66; the recovery code survives it), and recovery works only on origins the ballot host's `/.well-known/webauthn` lists.
